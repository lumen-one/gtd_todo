# 决策卡片

正文只写"现在是什么样"，不写"为什么是这样"。理由住在这里。

## 什么时候写一张

**半年后有人可能重新提同一个问题的取舍。** 具体是这四类：

- 算法或排序的取舍（为什么分这几档、为什么这个系数）；
- 数据形态的取舍（为什么两个文件而不是一个、为什么这个字段不落盘）；
- 交互上"反直觉但有意为之"的选择（为什么点按不是入口、为什么两个方向不对称）；
- 明确否掉过一条看起来更简单的路。

**不写**：机械改动、局部 UI 调整、纯 bug 修复、重命名、性能微调。这些 commit message 就够了。

## 卡片骨架

```markdown
# 决定：<一句话，现在时>

记录：YYYY-MM-DD
状态：生效中

## 问题

<当时卡在哪。不写方案也要能读懂——写给人看，不是写给自己回忆。>

## 决定

<现在是什么样。现在时。能被代码验证。>

## 备选与为什么输

<至少一条认真想过的路，以及它输在哪。这一面是整张卡片最值钱的部分：
  只记结论的卡片，等于邀请别人半年后再来争论一遍。>

## 代价

<这条决定花了什么、放弃了什么、哪一类场景变差了。写不出代价的，通常是还没想清。>
```

## 卡片怎么"死"

卡片不跟时间死，跟**它描述的那个机制**一起死：

- **机制被删了** → 删卡片。删之前确认没有别的卡片引用它。
- **机制被取代了** → 新卡片写清"取代了哪张"和"旧理由哪几条还成立"；旧卡片标
  `状态：已被 <新卡片> 取代`，内容留着不删（它是这段历史的唯一载体）。
- **机制还在跑** → 卡片必须还在，而且必须准确。机制改了而卡片没改，比没有卡片更糟。
