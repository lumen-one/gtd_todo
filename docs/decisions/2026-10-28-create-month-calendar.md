# 决定：新建第 1 页是月历，点某天即落定

记录：2026-10-28
状态：生效中

## 问题

新建第 1 页原来是四档：今天 18:00 / 明天 18:00 / 自选日期时间… / 不排期
（[2026-10-24](2026-10-24-create-date-first.md)）。前两档只覆盖两天，第三天以后全走
『自选』——而它要先串两级系统弹层（日期对话框 + 时间对话框）才看得见日历。最常做的那个
动作（挑个日子）反而藏在最深的一层后面。

另一处：两档的时刻都是 18:00，但开始型和截止型的时刻不是同一件事。截止型问的是"什么时候
前做完"，18:00 是工作窗末尾、安全上界；开始型问的是"什么时候动手"，落在 18:00 等于说这
件事从傍晚才开始。

## 决定

第 1 页换成月历（[UI 文档](../ui-interaction.md) §5.1）：

- 与[日历弹窗](../panels/calendar.md)共用 `MonthCalendar`，但**不打点**：新建时只关心选
  哪天，那天已经排了什么与这件事无关；
- 点某天即落定并翻到第 2 页，没有『确定』——日期在表单页仍然看得见，『改日期』可以回；
- 时刻按类型取默认：截止型该日 18:00，开始型该日 12:00；第 2 页切类型时，没手动改过的
  时刻跟着换整点；
- 日期行中间那颗时刻可点改，改过即钉住，之后切类型不再覆盖；
- 『不排期』从"第四档"挪到标题行右侧的一颗按钮，仍然是显式入口。

## 备选与为什么输

- **保持四档，只把『自选…』换成内联月历**：两条路都要维护，而且『自选』还得先点一次才
  见到日历——最常做的事仍然多一次点击。
- **点某天之后在日历下方滑出「时刻 + 确定」，确认再翻页**：多一次点击，而"确定"要确认的
  那件事（选了哪天）在第 2 页仍然可见；直达表单更省。
- **点某天之后不进表单，直接在日历下方敲标题回车建**（等于把日历长按那条路搬进加号）：
  步数最少，但丢掉类型、工时、重要度、提醒——把
  [2026-10-24](2026-10-24-create-date-first.md) 那张卡片解决的问题又还回去了。
- **月历上也打三个点**：新建时是噪音，而且要把 controller 一起拖进这个组件。

## 代价

- 月历占掉第 1 页大半高度，悬浮面板最窄 240dp 时一格只有 34dp，比四档列表费眼。
- "时刻跟着类型换"是隐式规则：用户手动改过时刻之后它就失效，得靠"时刻可点"和日期行的
  可见文案让人知道自己改的是什么。
- 开始型落 12:00 意味着"中午开始"，上午就要动手的活得手动往前拨。
- 少了『今天 / 明天』那种一眼看全两天落点的列表，得在月历上认得今天那一格。
