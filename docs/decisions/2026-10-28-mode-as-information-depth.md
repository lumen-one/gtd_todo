# 决定：调度模式 = 信息深度的停靠点

记录：2026-10-28
状态：生效中

## 问题

三档原本按"算法替人做主的程度"分：完整、标准、无排序。可这条轴上只有无排序一档真的
动了算法（把排序交还给人），另外两档的差别全在"响不响"——而响不响跟调度无关。名字也
不在一个尺度上：「无排序」说的是输出，「完整 / 标准」说的是程度。

更麻烦的是表单：无排序档仍然完整跑一遍公式（算裕度、算风险、判不可行、算锚点），于是
新建时照样问工时和重要度——用户选了"不要你安排"，还是被要求填一堆只有算法才用得上
的指标。

## 决定

~~三档~~两档按**软件向你问多少、拿这些算什么**重排，从少到多（[UI 文档](../ui-interaction.md) §7.0）：

- **无排序**：只问标题和日期。不跑调度算法，今日截止型组的成员按"今天到期（含逾期）"
  判定，组内顺序靠 `manual_order`。提醒 = 截止前 `manual_lead_minutes`（默认 30）那一刻
  响一次，逾期不响。~~『提醒我』这一档不出现（开始型同此，到点照响）。~~
- **标准**：多问工时（长期 / 按时长）。跑公式，按裕度风险排先后，今日页按锚点准入，
  提醒按裕度节奏多次~~、只对开了『提醒我』的生效~~。
- ~~**完整**：多问重要度（1–5）。`priority = risk × importance`。~~（见文末 10-29 修订二）

配套三条：

- **界面按档裁剪，数据不留空白**：无排序档不问的字段写入合理缺省——`estimatedWork` = 30、
  `importance` = 3、`remind` = true。切到标准档立刻能参与排序，不必补数据。
- **编辑表单不按档裁**：新建求快、编辑求全；在无排序档点『编辑』看到工时那一行，正好是
  把一件升成有估值的唯一入口，不必先切档。
- **无排序档的提醒是时点提醒**：时刻 = `deadline − manual_lead_minutes`，按墙钟算、不受
  通知时间段约束（越界时退到截止时刻本身），沿用 `point_fired` 幂等，只响一次。

## 备选与为什么输

- **无排序档存 `estimatedWork = null`**：`isLongTerm` 的判据就是它为 null，语义是"长期"。
  借它表达"用户没填"会把两个概念压在一个符号上，还要连带改完成判定、sidecar 落盘与
  '转正'逻辑。选缺省 30 的理由是：不问是界面问题，不该污染领域模型的符号。
- **无排序档保留按裕度的提醒节奏**：那就仍然需要工时与公式，与"不安排"直接冲突；
  "多久响一次"本身就是替人安排。
- **截止前分两段提醒（提前一天 + 提前半小时）**：提前一天已经在替人决定"什么时候该想
  这件事"，还要管"第一段响过没被看到"的状态。一次就够，错过靠手动『推迟』。
- ~~**标准档保留重要度**：乘数最多 5 倍，裕度差出一个 τ（480 分钟）就盖不动；标准档的
  定位是"只按时间压力排"，重要度属于完整档那层"人的偏好"。~~（修订二：改成默认关的开关——
  定位没变，愿意开的人不必为此多选一个档）
- ~~**把"全响"拆成独立开关**：完整档本来就该是"让软件全权做主"，拆开会让三档从一条阶梯
  退化成两个正交旋钮。~~（门槛取消后，"全响"已经不是任何一档的属性）

## 代价

- 无排序档没有裕度、风险、不可行预警，也不做工时对账（完成靠勾选）。一件三天后截止、
  要四小时的活，标准档会在裕度变薄那天把它捞进今天，无排序档要等到当天才出现。
- `estimatedWork = 30` 是隐藏值：切到标准档后，实际要四小时的活会按 30 分钟算裕度。
  切档时值得提示一次。
- 新装默认无排序 = 默认把"有截止的怎么安排"这个特色关掉。这一条暂时接受，等算法成熟
  再讨论默认档换不换。
- ~~三档不再共用一张"提醒门槛"表：无排序的提醒是时点型（一次），另两档是调度型
  （按裕度多次）。~~

**2026-10-29 修订**：提醒门槛整个取消——有时间的任务一律提醒（通知栏 + 横幅），
`remind` 从"要不要提醒"改成每件任务自己的『响铃』（有声 / 静音两档渠道）；无排序档的
提醒从一次变成两站（`T − 提前量` 与 `T`，截止型与开始型同一套）。原因："这一档出不出声"
对用户太难解释，而"要不要响铃"本来就是任务自己的事。

**2026-10-29 修订二**：完整档取消，重要度改成标准档里的一个开关（`ask_importance`，
默认关）。三档里只有无排序真的换了算法，完整档与标准档的区别从头到尾只有"问不问
重要度"一处——拿一个表单开关冒充一个档位，代价是三颗按钮挤在一行、用户要读完三条
说明才知道该选哪颗。开关打开 = 原来的完整档语义（多问、当乘数），关掉 = 乘数取 1、
新建与编辑表单里都不出现（关掉的是整个维度，不是一个控件的可见性）。老设置文件里的
`full` 落到标准并把开关打开，表单行为与升级前一致。

模式按钮回到两格，它们下面那一行留给 **AI 编排的入口位**（不可点）。它**不是第三档**：
AI 做的是记习惯、估工时、改截止、调参数，排在调度之上，不是另一种排序算法——占一颗
模式按钮会承诺一个将来一定要拆掉的形状。

缺省值那三条不变（`estimatedWork` = 30、`importance` = 3、`remind` = true）：不问就按
缺省落盘，切档立刻能参与排序。区别只在"重要度关掉时排序乘数为 1"——从"没数据所以恒
3"变成"这个维度不参与"。
