# 决定：日历的点分三色，按任务类型配、按明度分三层

记录：2026-10-28
状态：生效中

## 问题

日历格子里只有一颗强调色的点，说的是"这天还欠着活"。它不区分这天是"有事开始"还是"有事
到期"——两件事在日历上的后果完全不同：开始型那天没动手只是晚一点，截止型那天没干完就是
逾期。要在 4dp 的点上多带一层信息，能用的通道只有形状、颜色、大小。

## 决定

**三颗点，三种情形**：开始型 = 开始色，截止型 = 截止色，已经干完的 = 完成色（暖灰，不分
类型）。一天最多三点，从左到右 开始 → 截止 → 完成。

**颜色不动色相，按明度分三层**：截止最重、开始居中、完成最淡。浅色底是 6.2 / 4.5 / 3.6 对
白卡的对比，深色底反过来（变亮才是变重）。每套预设只配两个有色——开始沿用该主题的色相，
截止取相隔约 150° 的那一侧并避开逾期橙红（`#D84315`）那一段；完成是全主题共用的一颗暖灰。

**色值写死在预设上，不从种子算**：种子受"按钮托白字"的对比约束，四套之间本来就不齐
（橙 `#EF6C00` 白底 3.1:1，墨蓝 `#1E5AA8` 6.9:1）。直接拿来当点用，四套的点就没有统一的
明度层次，三层阶梯也立不起来。

## 备选与为什么输

**形状区分（圆点 vs 短横杠）。** 并排时一圆一方，看着不是同一族的东西；而且横杠要宽一倍才
看得出来，而格子下沿只有 4dp 高。

**开始用中性灰、截止用强调色。** 灰当"开始"会读成"这事不重要"，但开始型只是没有后果，
不是不重要。

**截止用固定色（比如紫），不随主题。** 紫是梅紫主题的强调色本身，那套主题下两点会撞在一起。
固定色要同时避开橙、墨蓝、苔绿、梅紫四个色相，色轮上只剩黄与靛紫两段，而黄在白底上的
对比度天生不够。

**拿 M3 的 tertiary 当第二色。** 四套分别是 `#636032`、`#705575`、`#3B6470`、`#815340`
——都与主色同明度（对比 1.00）、色度偏低发灰。4dp 的点只剩色相可辨，色弱视角下直接糊。

**已完成仍用蓝。** 蓝与墨蓝主题的强调色同区（色相差 11°），那套主题下"开始"与"截止"两个
点看起来是同一种颜色。这个隐患从两色时代就在，三色时绕不过去。

**已完成沿用浅灰。** 上一版否过灰，理由是"跟这天没事太接近"——那时日历只有"有 / 无"两态，
灰点确实会被读成没点。三色之后灰是三层里最淡的一档，不再是"有与没有"的对立，这条理由不再
成立。

## 代价

- **多一张色表要维护**：四套预设 × 两档明暗共十六个值，写在 `AppThemePreset` 上。加第五套
  主题时得给出对的四个值，不能只给种子。
- **第一次看不知道谁是截止**：没有图例。点开那天，列表面板里的徽标会说类型；这里不为它加
  一行图例，那会把弹窗撑高一行。
- **完成色偏淡**（3.6:1）：浅色卡片上是颗很轻的暖灰。这是"退场"的形式，不是看不见——它已经
  踩到图形元素可辨的下限，再淡就不该画了。
