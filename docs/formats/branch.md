# B.8 `支线.md`（任务分组）

"哪些任务属于同一条线"的持久记录。一个文件装全部支线，应用维护整份。

## 文件长什么样

```markdown
## 校招准备

- 投一份简历 #[k3f9a2]
- 刷完 DP 二十题 #[m8c1d4]

## 副业

- 写落地页 #[p2q7r1]
```

- `## 名字` 一段一条支线，段的先后就是卡片在界面上的先后。
- 段内一行一条任务引用：`- ` 开头，标题，行尾 `#[任务id]`。
- **空段合法**：刚建的支线还没装任务，`## 名字` 单独一行留着。

## 行语法

| 元素 | 规则 |
|---|---|
| 段标题 | `## 名字`（`#` 与名字之间可有空格）。名字就是卡片上那个名字，允许重名，靠段序区分 |
| 条目行 | `- ` 或 `* ` 开头 |
| `#[id]` | **判据**。行尾的 `#[...]`，里面是任务 id（`.gtd/<id>.md` 的文件名） |
| 标题 | 只给人读。读进来之后**以 `tasks.md` 里的实时标题为准**，保存时按它重写 |

## 四条约定

- **标题不是身份**：改标题不会掉引用，`#[id]` 才决定这行指着谁。
- **找不到任务的 id 不吞**：`tasks.md` 里暂时没有那一件（被删了、另一个引擎还没写完、
  两台设备还没同步过来）时，这一行**原样留在文件里**，界面上标灰显示成失效引用、长按可删。
  自动清掉等于替用户丢数据。
- **正文不保真**：不属于段标题或条目行的自由文字，保存时消失——这个文件由应用整份维护，
  与 [编排](plan.md) 是同一处理。
- **不做增量写**：每条命令都是"读整份 → 改一段 → 整份写回"（与编排、主线同一套理由，
  两个引擎可能同时写同一个文件）。定位用段序下标，界面的下标与这一次读盘是同一份数据。

## 与任务的关系

- 存的是**引用**不是副本：任务改名、改期、完成，支线这一行都跟着（删除见上条）。
- 一件任务可以在多个段里出现，没有独占约束。
- 支线**不参与调度**：不写 sidecar、不进 `.gtd/`、不响提醒、不占工时。
