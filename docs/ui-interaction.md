# UI 与交互需求文档（安卓侧边栏版）

> 定位：这是**客户端层的需求**。architecture.md 的分层契约不变：侧边栏、悬浮把手、系统通知
> 全部是"平台呈现"，用户能做的一切动作仍然只能通过 TaskService 的命令进入核心。
> UI 里只出现接口名，不出现平台名——本文件描述"要什么"，"从哪个文件调"永远归适配器。

---

## 0. 一句话定位与设计原则

**日常一切操作发生在悬浮侧边栏里，App 主体几乎不开。**

0. **数据归属（地基）**：人写的归人、内核算的归内核，**物理分成两个文档**
   （人类文档 `tasks.md` + 内核属性文档 `.gtd/<id>.md`，见 §4.3）。
   下面的原则都建立在这条之上——侧边栏怎么摆、手势怎么滑，都不改变"谁写谁负责"。
1. **唯一入口哲学**：侧边栏承载添加、查看、完成、推迟、改期、日历、任务池、查看已完成的全部日常操作；
   打开 App 只剩设置页（暂定）。
2. **忙时零摩擦**：忙的时候点「+」、默认三无直接确认入池，属性整理全部推迟到闲时（三无的工作强度默认'长期'——不估工时、不设优先级，§4.2）。
3. **隐私防瞟**：人多的场合**不打开面板**——把手拖出头再拐个弯，就地记一条（[快记](panels/quick-note.md)），
   清单一次都不露；面板一旦打开，内容就在明处（v1.24 撤掉了『隐私』按钮，[已撤销的隐私过头](panels/README.md#privacy-off)）。
4. **提醒自律，且默认不打扰**（见 §7.0）：默认
   **标准模式**只排列不提醒——看得到先后，听不到声音；需要被推着走的事
   **逐个手动开提醒**。切到**完整模式**才是"算法判定该响的都响"；
   **无排序**再弱化一层——连先后也交给人拖。三档都保留：夜间静默（通知时间段）、
   散件永不出声。

## 1. 名词表（本文件的专用词）

| 词                   | 定义                                                                                                                                                                             |
| -------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **侧边栏**           | App 自建的悬浮侧边条：贴屏小把手，任意界面（含其他 App 上方）拖出展开成面板                                                                                                      |
| **可推**             | 软任务：靠投入时间完成的事（写论文、收拾房间）；可有可无截止日                                                                                                                   |
| **不可推**           | 固定时点任务：到点必须发生的事（会议、约定、车票）；有确切日期时间，不需估工时                                                                                                   |
| **三无**             | 无结束日期、不需要提醒、可被推迟的任务——即完全无约束的散件；**工作强度默认'长期'**（见下面两行）                                                                          |
| **散件**             | 三无任务（默认'长期'）：标准/完整档在任务池横线后面，等闲时整理或被定期挑走；**无排序档常驻今日页最底**（[今日清单页](panels/today.md) ⑥）                                                                |
| **长期（工作强度）** | 工作强度的一个**特殊值**：不是分钟数，是"这事长期存在、眼下估不出来"的标记；三无任务的缺省值                                                                            |
| **长期任务**         | 工作强度 = 长期的任务：**没有**工作强度数值、优先级、时间裕度（剩余工作量同理），内核属性文档里**只有一个任务 id**（§4.3）                                              |
| **任务池**           | 侧边栏『任务池』页：所有未完成任务的总览，横线分"未来计划段"与"散件段"（无排序档只剩计划段，[任务池页](panels/pool.md)）                                                                                   |
| **已完成**           | 侧边栏『已完成』页：已完成任务的总览，按完成日期分今天/昨天/更早三组；动作只有『恢复未完成』与删除（[已完成页](panels/completed.md)）                                                                            |
| **今日清单**         | 侧边栏『今日清单』页：挂起组（最顶）+ 逾期置顶 + 固定时点组 + 可推组 + 例行组（周期实例）+ 被挑散件 + 散件段（仅无排序档），分组连续编号；"当前"即"今日"                                              |
| **灵感**             | 侧边栏『灵感』页：从指定 Markdown 文件提取显示的段落，**可就地编辑**（只写正文段，frontmatter 不动，[灵感页](panels/notes.md)）                                                                            |
| **周期任务**         | 循环任务（每天/每周X），在设置页创建维护，到点自动出现，响不响单独设                                                                                                             |
| **定期挑**           | 定时（默认每天）从散件段随机挑一件附到今日清单尾部，不响提醒，仅可见；无排序档照旧（被挑中的那件从页底散件段移出，不重复显示）                                     |
| **今日会响**         | **会真的响**的今日条目：提醒锚点落在今天且**过了提醒门槛**的可推任务 + 今天到点且开了提醒的不可推任务（提醒口径；分组构成见 [今日清单页](panels/today.md)，门槛见 §7.0）                                  |
| **裕度（slack）**    | 距截止的真实可用工时 − 剩余工时，唯一压力表（见 architecture.md）                                                                                                                |
| **人类文档**         | `tasks.md`：**所有任务**都记在这一个文档里，`# 标题` 分类，一条任务一行（见 §4.3）。这里的**「分类」= `# 标题` 小节**，与任务类型（fixed/flex，记在内核属性的 `type`）不是一回事 |
| **内核属性文档**     | `.gtd/<任务id>.md`：内核算出来的属性（任务id/工作强度/优先级/时间裕度/剩余工作量）；人也能看能改（见 §4.3）                                                                      |
| **行指纹（digest）** | 人类文档里那一行的指纹，存在内核属性文档里；两条文档靠它对号（人不写、也不该改）                                                                                                 |
| **调度模式**         | **标准**（默认）/ **完整** / **无排序** 三档选一个，见 §7.0。三档是**一条逐级弱化的谱系**：算法替人做主的程度依次递减                                                  |
| **标准模式**         | 默认档。算法照常算先后（谁先做），但**不出声**；只有手动开了提醒的任务会响                                                                                                       |
| **完整模式**         | 算法判定该响的都响（顺序与标准完全一致）                                                                                                                                         |
| **无排序模式**       | **标准的再弱化版**：不再按算法排先后，今日清单**可推组**的顺序全靠手动拖（其余组的排法不变，见 [今日清单页](panels/today.md)）；**今天该看哪几件仍由算法挑**（锚点落在今天 / 今天到期），只额外把全部三无散件附在页底（⑥）——有截止的任务一件不多；被挑中的那件仍单列 ⑤ |
| **调度优先级**       | 算法排顺序用的分 = `risk × 优先级`（人看不到具体数字，只看顺序）                                                                                                                 |
| **手动序**           | 无排序档下人拖出来的顺序（`manual_order`，记在任务上、重启保留）；切到标准/完整后**保留但不生效**                                                                                |
| **风险（risk）**     | 由时间裕度算出的"误期风险"，∈(0,1]，裕度越小越接近 1；**非线性**（§7.1）                                                                                                         |
| **详情卡**           | 点条目展开的那张**只读**卡（[今日清单页](panels/today.md)）：备注全文 + 全部属性 + 调度派生量；改数据仍要走显式动作（底部按钮与长按菜单同源）                                                    |
| **挂起进行**         | 长期任务的"正在做"标记（`in_progress`）：点了『挂起进行』这件事就进今日页最顶的挂起组；多件可挂、组内可拖；保持到完成或主动取消，**不按天过期**                |
| **挂起组**           | 今日页最顶的那一组（⓿，逾期组之上，[今日清单页](panels/today.md)）：全部挂起进行中的任务，**无编号**；三档调度模式下都在最顶、都能拖                                                                  |
| **主线** | 侧边栏顶栏第二行那一条：当前正在推进的一件大事（写论文、装修……）。**同时只有一条**在跑，完成后归档；主线住在 `tasks/主线.md`，与任务池是两层——行为链上的步骤**不是任务**，不进调度、不占工时（[主线覆盖页](panels/mainline.md)） |
| **行为链** | 主线里的一串步骤，排成一条链：勾了就完成（记完成时刻，文字加横线），链上第一个没勾的是"下一步"。链上步骤与 `tasks.md` 无关（[主线覆盖页](panels/mainline.md)） |
| **圈（记录）** | 主线『记录』页（日历）上**手动拖选连续日期**圈出来的一段，圈里写文字——这就是主线 log 的本体；某天几点勾了哪一步是另一层（自动流水），点开那天看（[主线覆盖页](panels/mainline.md)） |

## 2. 平台与权限前置（安卓）

- 平台：安卓 App，Flutter（现有工程已有 domain/application/repository/scheduler，本阶段补安卓 shell）。
- 需要的系统能力（全部走插座，契约见 [sockets/delivery.md](sockets/delivery.md)）：
  - **悬浮窗权限**（SYSTEM_ALERT_WINDOW）：侧边栏把手与面板；

## 4. 任务模型（UI 视角）

### 4.1 类型二分

每条任务二选一：

|        | 不可推（固定时点）                                       | 可推（软任务）                                                                             |
| ------ | -------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| 例子   | 会议、约定、车票                                         | 写论文、回邮件                                                                             |
| 必填   | 日期时间（创建时选『定点』，经『自选…』弹日期+时间弹窗） | 截止日可选                                                                                 |
| 估工时 | 不需要                                                   | 需要（进调度）；**无截止的三无除外**——默认'长期'，不估工时                        |
| 提醒   | **只到点响一次**（**完整模式**，或该任务手动开了提醒时） | 有截止日→按裕度排序并按裕度调频（§7）；**标准模式下手动开了提醒才响**；无截止日→**不提醒** |
| 归属   | 今日清单（到点当天）、任务池计划段                       | 有截止：今日清单+任务池计划段；无截止：任务池散件段                                        |

### 4.2 字段（对现有 domain 的扩展需求）

沿用现有 Task（id/title/description/deadline/estimatedWork/remainingWork/importance/status/
snoozedUntil/metadata/created），需要扩展（详见 §10）：

- **类型**：fixed / flex（可推）。三无 = flex 且无截止。
- **截止日可空**：现在 deadline 是必填，散件没有截止——这是最大的领域变更。
- **工作强度的特殊值'长期'**：三无任务（可推 + 无截止 + 不提醒）创建时**默认长期**——'长期'不是分钟数，标了它就是**不估工时、不设优先级、不算裕度**，内核属性文档里只有一个任务 id（§4.3）。**长期不是新类型**（类型仍是 fixed/flex，§4.1）；有截止的可推任务仍必须给数字工时（缺省 30 分钟，进 slack 数学，§7.1）；'转正'= 补截止 + 把'长期'换成具体工时（[任务池页](panels/pool.md)）。
- **标签 `tags`**（正式字段）：人类文档行尾的 `##标签`，见 §4.3。
- **完成时刻 `completedAt`**（正式字段）：人类文档的 `完成 <日期,时间>`，
  与打勾同步落一次；`status=completed` 与它任一成立即视为完成。
- **提醒开关 `remind`**（走 metadata 缓冲带）：标准模式下给**单个任务**
  开提醒——开了它，这一件就按完整模式的规则出声。它**不改变顺序**，只改"出不出声"
  （§7.0）；完整模式下这个开关没有意义（本来就全响）。
- 散件与"被定期挑中"的状态、周期任务规则，见 [任务池页](panels/pool.md) 与 §10。

### 4.3 存储形态：双文档（正典见 [formats/](formats/README.md)）

**人写的归一个文档，内核算的归另一个文档**：`tasks.md` 一行一条任务（人看人改，
应用只代笔自己那一行）；`.gtd/<任务id>.md` 装内核算出来的属性；两条靠行指纹配对。
长期任务的内核文档只剩 `id` 一行——'长期'不单独落一行，**没有 `work_intensity` 就是长期**。

字段、行语法、配对与归属规则的正典在 [formats/](formats/README.md)，本节不复述。

**分工与承诺**（写死）：

|                      | 人类文档 `tasks.md`                                | 内核属性文档 `.gtd/<id>.md`                            |
| -------------------- | -------------------------------------------------- | ------------------------------------------------------ |
| 谁写                 | 人（也由应用代笔**自己那一行**）                   | 应用                                                   |
| 应用改什么           | 只改它自己写的那一行：插入新任务、打勾、补完成时刻 | 全部字段随任务对象改写                                 |
| 应用绝不做什么       | **不重排行、不动别人的行、不动标题/空行/正文**     | 不动人的东西（这文件本来就只有内核字段）               |
| 人在 Obsidian 里能做 | 改名/改日期/改备注/加删行/换分类/加标签            | 也能改（字段级保真：注释、未知字段、内核备注原样保留） |
| 冲突时谁赢           | 人类那边赢（任务名/创建/结束/完成/备注/标签）      | 内核那边赢（工作强度/优先级/时间裕度/剩余工作量）      |

- **人只改人类文档也能用**：应用发现指纹变了就按上面的归属合并；
  新增的行会被内核接管并分配任务 id（**首次同步会提示一次**）；
  删掉的行不会连带删掉内核属性（文件即备份，删不删由人决定，只提示）；
- **人类文档里不出现任何内核字段**：id、工作强度、优先级、时间裕度、剩余工作量
  一个都不写进去——这是"共享/查看的文档要干净"这条要求的落地；
- **形态选择**：所有任务记在一个 `tasks.md` 里用标题分类
  （不是一任务一文件）；`log` 数据（领域事件流）**单独一个文档**，
  见 [架构文档](architecture.md) §3.3。

> 与 Obsidian 相连的形式不变（[灵感页](panels/notes.md)）：**形式上只是单纯在 Obsidian 外
> 增加一个手机侧边栏的快捷入口**——不做 Obsidian 插件、不接管 vault、不代改笔记，
> 差异只在"多一个入口读同一批文件"。

## 5. 创建流程

### 5.1 完整对话框（侧边栏内弹出）

```text
┌──────────────────────────────┐
│  新建待办                     │
│  回车 = 跳到备注 · 直接点确认 = 三无   │  ← 对话框常驻提示文案
│  标题…            ← 首焦点    │
│  备注…（选填）                │
│                              │
│  类型 [三无 ✓] [有截止] [定点] │  ← 常驻按钮，默认『三无』
│                              │
│      [ ✱ 确认 ]              │  ← 纯点按，没有任何手势
└──────────────────────────────┘
```

1. 标题输入框首焦点；**回车 = 跳到备注**（对话框上有提示文案说明这一操作）。
2. 备注选填，可留空。
3. **类型档位常驻在对话框里**（不再藏在手势里），三个互斥按钮，**默认『三无』**：
   - **三无** = 可推 + 无截止 + 不提醒 → 入池散件段；**工作强度默认'长期'**（不估工时、不设优先级）；
   - **有截止** = 可推 + 有截止日 → 下方升起日期档位；
   - **定点** = 不可推（固定时点）→ 下方升起日期档位。
4. **日期档位**（选了类型才升起，没选就是三无）：
   - 『有截止』→ **【今天】【明天】【自选…】**：今天/明天取该日 **18:00**
     （当日工作窗末尾的常用截止点），要精确到分走『自选…』；
   - 『定点』→ 只给 **【自选…】** 一个：定点必须有确切时刻，"今天/明天"这种含糊档位没有意义；
   - 『自选…』= 弹日期 + 时间弹窗，选完**回到对话框**，所选日期显示在按钮上；
   - 点回『三无』→ **清掉已选日期、档位收起**（可逆，不留残留）。
5. **确认键是纯点按**（长按与滑动全部移除）：
   - 停在『三无』（默认态）→ 点确认**直接创建三无任务入池散件段**，中间不弹任何东西；
   - 选了『有截止』/『定点』但还没点日期档位 → 点确认**自动弹日期+时间弹窗**，选完即创建；
   - 已选日期 → 点确认按所选类型与日期创建（可推有截止 / 定点）。
6. **提醒开关不进新建对话框**（明确不做）：默认三无本来就不响；要响在创建后走『编辑』
   开『提醒我』（§7.0）。新建只问"是什么、什么时候"，不额外问"要不要吵你"。
7. **语音输入**：任何输入框都可以用输入法的语音键说话出字，App 不额外做语音功能。

> **为什么砍掉手势**：长按不松再滑档位这套动作**没有视觉 affordance**——不长按就永远
> 看不到档位在哪、也无从知道它能二分；而且它和系统返回手势、面板翻页手势抢同一块触摸区

## 7. 提醒系统

### 7.0 调度模式三档（**默认标准**）

**三档是一组三选一**（设置页『提醒与排序』节），按"算法替人做主的程度"从强到弱排：

|                                             | **完整**                | **标准（默认）**                                         | **无排序**                                 |
| ------------------------------------------- | ----------------------- | -------------------------------------------------------- | ------------------------------------------ |
| 算法排先后（谁先做）                        | 是                      | 是                                                       | **否**——今日可推组由人拖（`manual_order`） |
| 自动提醒                                    | 凡算法判定该响的都响    | **不出声**（默认安静）                                   | 与标准一致：不出声                         |
| 单个任务                                    | 不用开（本来就全响）    | 可手动开提醒（编辑表单『提醒我』，落 metadata `remind`） | 同标准                                     |
| 到点类提醒（不可推到点 / 设了响的周期实例） | 照原方案响              | 默认不响，开了才响                                       | 同标准                                     |
| 今日清单有哪几件                            | 锚点落在今天 / 今天到期 | 同左                                                     | **有截止的同左**；另加页底 ⑥ 散件段（全部三无，仅这一档） |
| 任务池的顺序                                | 整理序（`pool_order`）  | 同左                                                     | 同左；**散件段不显示**（那些件在今日页 ⑥）                 |

一句话记：**完整 = 排 + 响；标准 = 排 + 不响；无排序 = 不排 + 不响**。
三档互不重叠，也不存在"组合"——切一档就够了，不会出现"排但不响且不按锚点"这种第四态。

- **无排序是标准的再弱化版**：它把标准档里"算法排先后"这一层也去掉，其余全部照抄标准
  ——含默认不出声、含"有截止的任务仍按锚点准入"。唯一的加法是页底 ⑥ 散件段：
  标准/完整档看散件要切到任务池，无排序档把那段直接铺在今日页最底下（[今日清单页](panels/today.md)）。
  想让它出声，仍然去编辑表单给单件开『提醒我』。

- **为什么默认标准**：提醒是打扰。默认"只排队、不出声"，需要被推着走的事再单独开——
  一次设置或一次点击的代价，换默认安静（代价记在 [架构文档](architecture.md) §11）。

- **门槛与送达策略是两件事，串联生效**：门槛决定"**要不要**出声"（这一件
  `reminds = false`、结果里的下一站 `nextReminderAt = null` 就是不出声），通知时间段决定
  "**什么时候**允许出声"（段外顺延，§7.1）。所以标准模式下连"顺延"都不会发生——
  根本没有那一站。（**锚点照算**：提醒锚点是调度计算，今日清单准入用它，不受门槛影响。）

- **切换立即生效**：顺序与下一站闹钟都重算（提醒是计算结果，无迁移、无历史改写）。

### 7.1 算法与默认策略（时间裕度优先 + AI 调参）

有截止日的可推任务一律换算成"工作分钟"（跳过夜间/午休/周末）再比。`available` / `slack` /
`risk` / `priority` / 提醒间隔的公式与默认参数**只有一份**，在
[架构文档](architecture.md) §3.1；本节只说这些量在界面上怎么用、由谁调，以及哪些任务
根本不在那套公式里。

- **排序四档**：不可行 → 普通（调度优先级降序）→ 逾期 → 已推迟。不可行是
  "已经注定误期"，单独一档等用户裁决（改截止 / 砍范围 / 加班）；
- **裕度优先**：裕度越薄风险越高、越排在前面；**优先级（1–5，缺省 3）是乘数**，
  让重要的事整体前移。乘数最多 5 倍，裕度差出一个 τ（480 分钟）以上它就盖不动了。
- **为什么非线性**：线性要让裕度"到哪算 0"凭空定一个量纲，还会算出负风险；
  指数族只要一个尺度 τ，且恒在 (0,1]——**裕度还宽时催得少，裕度一薄就陡然变急**；
  γ>1 = 裕度充足时压得更低（更平）、薄了迅速冲到 1（更陡）。τ 与 γ 的取值见
  [架构文档](architecture.md) §3.1。
- **`priority` 这个名字只属于算法内部**：人定的是**优先级**（内核属性文档的
  `priority` 键 = `Task.importance`，缺省 3），算出来的是**调度优先级**（不落盘、不进人类文档）；
  界面照旧展示裕度这类派生量，但不显示这个排序分——**顺序本身就是表达**。
- **全局通知时间段（多段式）**：可推任务的提醒只落在时间段内，时间段外静默
  （这是**门槛之后**的一道，§7.0）。设置里支持**多段编辑**
  （如 9:00–12:00、14:00–18:00、19:00–21:00，方便抠掉午睡/饭点）；默认一段 **9:00–21:00**；
- **AI 动态调整 = L2 软控制**：AI 只允许在 Scheduler `params` 声明范围内微调
  （α、最小间隔、间隔拐点、风险尺度 τ 与陡度 γ），一切变更走 origin=ai 的领域事件，**可审计、可拒绝**——
  回滚不承诺（[架构文档](architecture.md) §6：逆命令机制未设计，落地前 UI 只提供"拒绝"）；
  没配 key / AI 挂掉 → 默认策略照常。
- **不可推**：只到点响一次，不提前、不进调度；**标准模式下要先给这一件开提醒**
  才会响（§7.0）。（实现：`TaskService.nextPointReminder()` + ReminderDispatcher
  双源单闹钟；`point_fired` 保证只响一次，改期重新生效；错过超过 30 分钟不再补响。）
- **散件 / 可推无截止**：永不提醒（三档都一样）。
- **三无的默认工作强度 = '长期'**：'长期'不是分钟数，是"长期存在、估不出来"的标记——标长期的任务不估工时、不设优先级，也不进 [架构文档](architecture.md) §3.1 那套公式（它们本来就没有截止；内核属性文档里只有一个任务 id）。
- **周期任务**：响不响单独设置（**标准模式下"规则设了响"就等价于给这个实例手动开了提醒**）；
  **不占工时**（不进裕度容量计算）；
  当天实例**跨日生成**（不存在"应用没开还会有零点任务"这回事）；
  完成即消，次日再生。（实现：实例在启动/跨日/回前台时**幂等**生成
  ——没有"每天零点"的后台闹钟，应用下一次活着的时候补齐，落成任务文件。）

### 7.2 提醒呈现与推迟

> **前提**：本节讲的是"响了之后长什么样"。**标准模式下大多数任务走不到这里**
> ——要响，先给那一件开提醒，或把模式切成完整（§7.0）。

- 到点弹**系统通知**，通知上直接给快捷按钮：**『完成』『推迟 1 小时』**；
- 点通知**正文** → 展开**侧边栏**并定位到该任务。**定位边界**：目标在今日清单 → 定位高亮；
  已滚进任务池 → 跳池子定位高亮；已完成 → 跳『已完成』页定位高亮（[已完成页](panels/completed.md)）；已删除 → toast"已删除，可在回收找回"。
- **推迟档位**：通知快捷固定 1 小时；长按菜单『推迟』给档位：**30 分钟 / 1 小时 / 3 小时 /
  明早 9 点 / 自选时间**。推算结果落在静默/休息段 → **顺延到下一时段开头**（不强制响，
  夜间静默是硬规则；**不可推的到点闹钟不受静默限制**）；跨休息段的推迟按 architecture.md **D8**
  给显式选项"到下个工作窗"（≤120 分钟按自然时间）。**绝对档位（明早 9 点 / 自选）原样响**
  ——静默段顺延只作用于相对档位推算出的时刻。
- **可选闹钟模式**（**只对时点性提醒生效**：不可推的到点提醒 + 设了响的周期任务；
  可推任务的 Slack 例行软提醒永远普通通知）：开启后升级为**全屏提醒界面 + 持续响铃**，
  必须手动点『完成 / 推迟 / 知道了』才停；走系统闹钟渠道，媒体静音压不住
  （实现上对应 full-screen intent，需锁屏显示/上层显示权限，走 PermissionPort）。
  （实现：原生渠道 `gtd_alarm`（IMPORTANCE_HIGH + 闹钟音 + 震动）+
  `setFullScreenIntent`；权限缺失时退化为普通通知。
  应用被杀时由系统闹钟的接收器照"交付草案"弹出通知，按钮点击回传应用；
  应用当时没开则在下次启动补做。）

- **明暗三选一**：**跟随系统（默认）/ 浅色 / 深黑**，落 `settings.json` 的
  `theme_mode`；两个引擎（应用内壳 + 系统级悬浮面板）读同一份设置，切换
  立即生效、不迁移任何任务数据。深色底 = **暖深褐黑**（`#1E1B18` 底 /
  `#2A2622` 卡）而不是纯黑——配橙种子保住"纸"的暖底基因。

  暗底已达标不动。"不随预设变"与"随明暗提亮"是两件事：前者防装饰性漂移，

    落 `settings.json` 的 `handle_hot_width`，两处把手（系统级悬浮 + 应用内）
    共用同一个值、改完立即生效；原生侧另在 prefs 里存一份镜像（服务可能比 Dart
    先起来）。选的就是"好抓"与"不挡路"的折中点——热区盖住的触摸归把手（[把手与面板](panels/handle.md)），
    越宽越好抓、底下那一竖条越挡路，系统返回手势被抢走的边也越宽。**竖向高度不开
    这个口子**：200dp 是系统手势排除的配额上限，调小只是自损竖拖起手的容错。
    `settings.json` 本就**不参与同步**（范围见 [sockets/sync.md](sockets/sync.md)），所以它是
    纯本机手感项，换设备不跟着走。
11. 〔悬浮壳〕**固定侧边栏大小**：打开时**冻结此刻生效**的宽高——开关本身落
    `settings.json` 的 `panel_size_locked`，数值仍写 `panel_width` /
    `panel_height`；两条改尺寸的把手撤掉，内侧竖条就地换成跟手收起把手
    （朝停靠侧拖过面板宽的一半即缩回，见 [把手与面板](panels/handle.md)）。关掉只解锁、数值保留。
    与第 8 条的『固定把手位置』是两件事：一个锁把手的**竖向位置**，一个锁
    **面板的宽高**。固定后误触改尺寸这件事就没有了——把手那两条边原本是面板上
    唯一会改布局的地方。
12. **展开后默认页面**：一组四选一——**今日清单（默认）/ 灵感 / 任务池 / 已完成**，
    落 `settings.json` 的 `default_page`（存页的稳定 id，与页序无关）。拖动把手展开即落
    这一页（默认页是今日清单且今天排过编排时，每次展开先亮编排覆盖页，见 [今日编排](panels/plan.md)）；点通知定位时按定位目标走，不被它盖掉（[把手与面板](panels/handle.md)）。桌面上没有"展开"这一步，
    它是**重新打开窗口时**左栏的起始页（副标题随之改口，见本节开头）。标签最长四个字，窄面板
    下用可换行的 chip 而不是四等分按钮——240dp 上四等分会把"已完成"挤成省略号。
13. **工作时间**：**哪几天算工作日**（一~日多选）+ **那几天的工作窗**（多段式，
    如 09:00–12:00、13:30–18:00），落 `settings.json` 的 `work_days` / `work_windows`。
    它是 §7.1 那个 `available` 的分母——**改完立即重算，已定下的提醒锚点全部作废**
    （产能变了，旧锚点没有意义）。默认周一至周五、两段（09:00–12:00、13:30–18:00）。
    入口只有设置页这一项（v1.32 撤掉桌面标题栏那颗『工作时间规则』按钮：桌面的设置页
    就摆在侧边栏右边，标题栏不必再放一份），打开编辑面板；
    应用内今日清单不再有只读版。**节假日/调休未做**（`WorkTimeRule.holidays` 留位未接线）。

## 11. 边界与异常

- **权限被拒**：悬浮窗被拒 → App 内抽屉形态兜底（**四页全功能复用**：同一套 panels，
  App 内左侧滑呼出，无悬浮把手）；悬浮面板的引擎/窗口起不来 → 回退为"把手打开应用面板"
  （功能不减，只是会跳进应用）；通知被拒 → 提醒只在侧边栏内高亮；
  精确闹钟被拒 → 提醒可能迟到（如实提示用户）。
- **后台被杀 / Doze**：提醒依赖 AlarmPort 系统闹钟唤醒（见 [sockets/delivery.md](sockets/delivery.md)），不靠 Timer。
- **闹钟模式权限**：全屏提醒需要锁屏显示/上层显示权限；被拒则退化为普通通知 + 响铃。
- **无 AI 配置**：默认策略照常，设置页显示"未接入"。
- **误触防护**：完成走长按菜单（天然防误触）；**翻页不靠"重手势"**——
  横滑与列表的纵向滚动方向正交，浏览清单不会翻页，翻页也不会误滚列表；
  纵向唯一的越界是**今日页到顶之后再下拉**（[今日编排](panels/plan.md)）：列表没到顶时
  它不存在，而且要拉过一截（72dp 或快甩）才算数，浏览中不会误触；
  通知上的"完成"按钮点击后提示完成，误触可去『已完成』页『恢复未完成』（[已完成页](panels/completed.md)）。
  **批量动作不走这条防线**：它靠自己两步（长按 → 菜单『多选』→ 勾选 → 按动作）；删除仍是软删除 + 撤销 toast，一次删多件时恢复整批；批量完成不进回收站，反悔去『已完成』页逐条恢复。
  **新建确认是纯点按，不承担
  防误触职责**：误建的代价很低（直接进散件段，长按就能改能删）。
- **详情卡是打开那一刻的快照**：它不订阅控制器的后续刷新（后台重锚、别的
  引擎改了任务，卡上的派生量不会自己变）。动作一律"先收卡再执行"（执行完这条任务
  往往已经从清单消失），所以不会留下一张指向旧数据的卡；要看最新的，关掉再点一次。
- **默认模式下"什么都不响"**：这是**标准模式的正常表现，不是故障**。要响有两条路——
  ①给那一件开『提醒我』（编辑表单里），②把设置里的调度模式切成**完整**。
  设置页的三选一旁写明这一点，避免被当成通知权限没给。
- **无排序模式下页底会多一段散件**：有截止的条目与标准/完整完全一致
  （仍按"锚点落在今天 / 今天到期"准入），变的只有组内顺序；页底那段 ⑥ 是这一档的
  设计（全部三无散件，池子那边不再显示，[今日清单页](panels/today.md) / [任务池页](panels/pool.md)）。**有截止的任务无故变多是 bug
  不是特性**；不想看到的拖到下面，要回到"算法排先后"就切回**标准**或**完整**。
- **存储层的异常**：
  - 人类文档里缺 `创建` 的复选框行 → **不改动**、进 `warnings`（它在 Obsidian 里仍是
    普通待办，但内核不接管、不进任何清单——与 architecture.md [人类文档](formats/tasks-md.md)"只进 warnings"是同一件事）；
  - 两行内容完全相同 → 无法区分内核属主，只告警不猜（改掉任务名或创建时间即可分开）；
  - 人在 Obsidian 里删掉了某一行 → 内核属性文件**保留并提示**，不静默删数据；
  - 人在 Obsidian 里改了任务名 → 优先按指纹、其次按名字、最后按位置配对（[配对规则](formats/matching.md)）；
    位置配对只在"两边剩余数量恰好相等"时启用，数量不等宁可新接管也不猜。

## 12. 范围声明（有意不做 / 边界澄清，防将来被当遗漏）

- **性能/尺寸规格**（把手大小、动画时长等）：实现期以手感调参定，不写死数字；**侧边栏宽高是例外**——范围与默认值见 [把手与面板](panels/handle.md)（用户能拖，数字本身就是给用户看的调参入口）；
- **多设备同步**：只做**同一局域网内**（[局域网同步](sockets/sync.md)）——不经云端、
  不跨网络、无账号；换网络或异地靠任务目录本身（Obsidian 共享是事实上的同步）；
- **备份恢复**：交给任务目录本身（文件即备份），App 不另做；`legacy-tasks/`
  （迁移存档）与 `.gtd/.trash/`（回收站）都**只增不自动清理**；
- **Obsidian 插件 / vault 接管**：不做。与 Obsidian 的连接形式就只有"多一个手机侧边栏
  入口读写同一批文件"（灵感篇的正文段可就地改，[灵感页](panels/notes.md)）；
- **人类文档的任务行里写内核字段**：不做。id/工作强度/优先级/时间裕度/剩余工作量
  只进 `.gtd/`，人类文档保持干净；
- **提醒的"自动升级"**：不做。标准模式下**不会**因为"快到期了"就自动开始提醒
  ——要响只能给那一件开提醒，或把模式切成完整。这是"默认安静"的代价，记在 [架构文档](architecture.md) §11；
- **用户自选调度算法**：不做（`slack.v1` 留在算法注册表里做对照，但设置页没有切换入口；
  要换得动组装点）。**调度模式三档不是算法选择**：换算法是换"怎么算 risk/priority"，
  而这三者改的是"算完之后用不用它"，两者别混为一谈；也没有往注册表里加
  第三个不带数学的假算法，`Scheduler.schedule` 也不收任何排序口径；
- **无排序档下的"智能整理"**：不做。按截止/优先级/习惯自动重排、或提示"要不要按算法
  排一遍"，都与该档"顺序就是人的决定"直接冲突；要做也只能做成**一次性**的显式动作
  （点一下才排，且排完即转为手动序）；
- **给固定时点组与例行组排手动序**：不做。前者时刻就是序、后者实例每天新生没有可持久的
  序号（"四处不跟着变"）；
- **详情卡的"整卡可编辑"**：不做。详情卡只读，改数据走显式动作（底部按钮
  或长按菜单）；同理**详情里不做改期**（改期的主场景在日历 [日历弹窗](panels/calendar.md)）、**不显示排序分**
  （`risk` / `priority` 是排序键，顺序本身就是表达）。要改字段去『编辑』；
- **已完成页不做统计、不设条数上限**：只按天列条目，不做"本周完成 N 件"一类的汇总
  （要流水有 `log.md`）；也不做分页与"仅看最近 30 天"的开关——按天分组 +
  `ListView.builder` 足够，真到几千条再说。
- **数据埋点/使用统计**：无（`log.md` 是本地操作流水，不上报）；
- **新平台 shell**（iOS 等）：架构支持，需求不在本阶段；
- **桌面/Windows 端不做移动端的"进出"机制**：把手、遮罩、抽屉、跟手收起都不在桌面做
  （[桌面布局](panels/desktop.md)）——桌面窗口常驻，那套东西没有对应物。但**页面与能力**（四页 / 主线 / 设置 /
  提醒弹窗 / 同步）与安卓是同一份，不另做简化版。托盘图标、全局快捷键、开机自启属
  Windows 原生能力，当前不在范围。
- **面板头的『关闭』与『隐私』按钮**：不做（v1.24 撤掉）。关面板有点遮罩、返回键、尺寸固定
  后的收起把手三条路；防瞟走快记（[快记](panels/quick-note.md)）。面板头只留右上角『设置』——窄面板上多一颗图标，
  页名就少一截。
- **主线不做提醒、不与任务双向联动、不自动归档**：行为链步骤不参与调度（要参与就另建任务，
  两边不互相同步）；完成主线必须是显式动作（全部勾完 → 点『完成主线』），勾完不会自己归档；
  归档只有"看"没有"恢复为当前"——要重做就新建一条（同时只有一条在跑）。主线也不做统计
  图表与"连续 N 天"成就一类的汇总，日历上能看到的就是全部。
