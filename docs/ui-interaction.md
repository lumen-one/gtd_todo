## 0. 一句话定位与设计原则

**日常一切操作发生在悬浮侧边栏里，App 主体几乎不开。**

0. **数据归属（v0.7 起的地基）**：人写的归人、内核算的归内核，**物理分成两个文档**
   （人类文档 `tasks.md` + 内核属性文档 `.gtd/<id>.md`，见 §4.3 与决议 36）。
   下面的原则都建立在这条之上——侧边栏怎么摆、手势怎么滑，都不改变"谁写谁负责"。
1. **唯一入口哲学**：侧边栏承载添加、查看、完成、推迟、改期、日历、任务池的全部日常操作；
   打开 App 只剩设置页（暂定）。
2. **忙时零摩擦**：忙的时候"堆三无"一键入池，属性整理全部推迟到闲时。
3. **隐私防瞟**：人多的场合拖过头，面板隐藏全部清单内容，只留一条极简输入框。
4. **提醒自律**：夜间静默、可推任务按裕度自动调频、散件永远不出声。

## 1. 名词表（本文件的专用词）

| 词 | 定义 |
|---|---|
| **侧边栏** | App 自建的悬浮侧边条：贴屏小把手，任意界面（含其他 App 上方）拖出展开成面板 |
| **可推** | 软任务：靠投入时间完成的事（写论文、收拾房间）；可有可无截止日 |
| **不可推** | 固定时点任务：到点必须发生的事（会议、约定、车票）；有确切日期时间，不需估工时 |
| **三无** | 无结束日期、不需要提醒、可被推迟的任务——即完全无约束的散件 |
| **散件** | 任务池横线后面的三无任务，等闲时整理或被定期挑走 |
| **任务池** | 侧边栏第 3 页：所有未完成任务的总览，横线分"未来计划段"与"散件段" |
| **今日清单** | 侧边栏第 1 页：逾期置顶 + 固定时点组 + 可推组 + 例行组（周期实例）+ 被挑散件，分组连续编号；"当前"即"今日" |
| **疑问笔记** | 侧边栏第 2 页：从指定 Markdown 文件只读提取显示的段落，编辑去 Obsidian |
| **周期任务** | 循环任务（每天/每周X），在设置页创建维护，到点自动出现，响不响单独设 |
| **定期挑** | 定时（默认每天）从散件段随机挑一件附到今日清单尾部，不响提醒，仅可见 |
| **今日会响** | nextReminderAt 落在今天的可推任务 + 今天到点的不可推任务（提醒口径；今日清单的分组构成见 §6.1） |
| **裕度（slack）** | 距截止的真实可用工时 − 剩余工时，唯一压力表（见 architecture.md） |
| **人类文档** | `tasks.md`：**所有任务**都记在这一个文档里，`# 标题` 分类，一条任务一行（见 §4.3）。这里的**「分类」= `# 标题` 小节**，与任务类型（fixed/flex，记在内核属性的 `type`）不是一回事 |
| **内核属性文档** | `.gtd/<任务id>.md`：内核算出来的属性（任务id/工作强度/优先级/时间裕度/剩余工作量）；人也能看能改（见 §4.3） |
| **行指纹（digest）** | 人类文档里那一行的指纹，存在内核属性文档里；两条文档靠它对号（人不写、也不该改） |

## 4. 任务模型（UI 视角）

### 4.1 类型二分

每条任务二选一：

| | 不可推（固定时点） | 可推（软任务） |
|---|---|---|
| 例子 | 会议、约定、车票 | 写论文、回邮件 |
| 必填 | 日期时间（创建时自动弹日期弹窗） | 截止日可选 |
| 估工时 | 不需要 | 需要（进调度） |
| 提醒 | **只到点响一次** | 有截止日→Slack 调度（§7）；无截止日→**不提醒** |
| 归属 | 今日清单（到点当天）、任务池计划段 | 有截止：今日清单+任务池计划段；无截止：任务池散件段 |

### 4.2 字段（对现有 domain 的扩展需求）

沿用现有 Task（id/title/description/deadline/estimatedWork/remainingWork/importance/status/
snoozedUntil/metadata/created），需要扩展（详见 §10）：

- **类型**：fixed / flex（可推）。三无 = flex 且无截止。
- **截止日可空**：现在 deadline 是必填，散件没有截止——这是最大的领域变更。
- **标签 `tags`**（v0.7 新增，正式字段）：人类文档行尾的 `##标签`，见 §4.3。
- **完成时刻 `completedAt`**（v0.7 新增，正式字段）：人类文档的 `完成 <日期,时间>`，
  与打勾同步落一次；`status=completed` 与它任一成立即视为完成。
- 散件与"被定期挑中"的状态、周期任务规则，见 §6.3 与 §10。

### 4.3 存储形态：双文档（决议 36/37，正典见 architecture.md 附录 B）

**人写人看的归一个文档，内核算的归另一个文档。** 任务数据不是一个文件，是两个：

```text
tasks/
├── tasks.md           ← 人类文档：Obsidian 里看/改/共享的就是它
└── .gtd/<任务id>.md    ← 内核属性文档：应用自己写
```

**人类文档**（一个文档、`# 标题` 分类、一条任务一行）：

```markdown
# 工作

- [ ] 任务名 创建 2026-10-11,07:00 结束 2026-10-12,18:00 这是备注。 ##这是标签1 ##这是标签2
- [x] 交房租 创建 2026-10-01,09:00 完成 2026-10-01,09:30 ##生活
```

人写的六个属性：**任务名、创建日期、结束日期、完成日期、备注、标签**。
**更多的标签 = 更多的属性**：多打一个 `##标签` 就多一个维度，内核不解释它的语义
（唯一用法：新任务按第一个标签落到同名 `# 小节`）。

**内核属性文档**（应用根据已有属性算出来或补上的那部分）：

```markdown
---
id: task-001
digest: 7683b0bb       # 行指纹：把这一条和人类文档里那一行对上号
work_intensity: 120    # 工作强度（完成它需要的工时，工作分钟）
remaining_load: 0.75   # 剩余工作量（**分数**，乘以工作强度才是分钟）
priority: 3            # 优先级 1–5
time_slack: 210        # 时间裕度（工作分钟）
status: active
---
```

**分工与承诺**（写死，这是本次改造的全部要点）：

| | 人类文档 `tasks.md` | 内核属性文档 `.gtd/<id>.md` |
|---|---|---|
| 谁写 | 人（也由应用代笔**自己那一行**） | 应用 |
| 应用改什么 | 只改它自己写的那一行：插入新任务、打勾、补完成时刻 | 全部字段随任务对象改写 |
| 应用绝不做什么 | **不重排行、不动别人的行、不动标题/空行/正文** | 不动人的东西（这文件本来就只有内核字段） |
| 人在 Obsidian 里能做 | 改名/改日期/改备注/加删行/换分类/加标签 | 也能改（字段级保真：注释、未知字段、内核备注原样保留） |
| 冲突时谁赢 | 人类那边赢（任务名/创建/结束/完成/备注/标签） | 内核那边赢（工作强度/优先级/时间裕度/剩余工作量） |

- **人只改人类文档也能用**：应用发现指纹变了就按上面的归属合并；
  新增的行会被内核接管并分配任务 id（**首次同步会提示一次**）；
  删掉的行不会连带删掉内核属性（文件即备份，删不删由人决定，只提示）；
- **人类文档里不出现任何内核字段**：id、工作强度、优先级、时间裕度、剩余工作量
  一个都不写进去——这是"共享/查看的文档要干净"这条要求的落地；
- **落实决议 36 的形态选择**：所有任务记在一个 `tasks.md` 里用标题分类
  （不是一任务一文件）；`log` 数据（领域事件流）**单独一个文档**，
  见 architecture.md §3.3 与决议 37。

> 与 Obsidian 相连的形式不变（§6.2 与决议 37 重申）：**形式上只是单纯在 Obsidian 外
> 增加一个手机侧边栏的快捷入口**——不做 Obsidian 插件、不接管 vault、不代改笔记，
> 差异只在"多一个入口读同一批文件"。

## 5. 创建流程

### 5.1 完整对话框（侧边栏内弹出）

```text
┌──────────────────────────────┐
│  标题…            ← 首焦点    │
│  （提示：回车进入备注）        │  ← 对话框常驻提示文案
│  备注…（选填）               │
│                              │
│      [ ✱ 确认 ]              │  ← 悬浮文字提示："长按确认，松手完成"
└──────────────────────────────┘
```

1. 标题输入框首焦点；**回车 = 跳到备注**（对话框上有提示文案说明这一操作）。
2. 备注选填，可留空。
3. 确认键的手势（拍板：**按住不松一滑到底**）：
   - **长按**住确认键 → 原地升起分类档位，悬浮文字全程提示；
   - 手指**不松**，顺势滑到档位：
     - **不可推** → 松手 → **自动弹日期弹窗**（选日期+时间）→ 完成；
     - **可推** → 档位再二分一次，滑向：**有截止日**（松手→弹日期弹窗）/ **无截止日**（松手→入池散件段）→ 完成。
   - **降级路径**：直接**点击**（非长按）= 按默认分类创建：可推、无截止日、无提醒（等价三无），之后可再编辑补属性。
4. **语音输入**：任何输入框都可以用输入法的语音键说话出字，App 不额外做语音功能。

### 5.2 快捷堆三无（忙时专用）

- 独立按钮（与"添加待办"并排），**跳过整个对话框**：
  输入一句话（或一个词）→ 即刻成为三无任务入池散件段。
- 目标场景：正在忙，只想把脑子里的东西甩出去，两秒内完成。

## 6. 悬浮侧边栏

### 6.0 把手与面板

- 贴屏小把手（可拖动停靠左右边缘），拖出展开成面板；
- **面板本体是系统级悬浮面板**（v0.6 / 决议 35）：拖出后在**当前 App 上方就地展开**，
  不是把用户带进应用；面板与应用内壳**共用同一份 panels**（`ui/panels/side_panel.dart`）；
- **三页结构，垂直翻页**；翻页手势要**重一点**（更大行程/速度阈值），避免浏览清单时误翻；
- 页序：**今日清单 → 疑问笔记 → 任务池**；
- 把手与面板互斥显示：展开时把手让位、收起后把手回来；应用自身在前台时两者都收起
  （此时走应用内把手 + 应用内面板）；
- 进应用的唯一入口：面板头『设置』与实例菜单『编辑规则』。

### 6.1 第 1 页：今日清单

**分组连续编号**（裁决见 §12 决议 11/12）：

```text
① 逾期组      过截止未完成：无编号、橙红徽标置顶，完成/改期前不消失
② 固定时点组  今天到点的不可推任务：按时间点升序，橙色时间徽标；组内不可拖（时间就是序）
③ 可推组      今天有提醒或今天到期的可推任务：Slack 调度排序（infeasible 优先）；可拖插队
④ 例行组      周期任务当天实例：排在可推组之后；不占工时、默认不响（设了响的到点走提醒）
⑤ 被挑散件    定期挑/手动挑的那一件：附在本页最后，无提醒、仅可见
```

- **编号跨 ②③④ 组连续**（1、2、3…）；逾期组与被挑散件（⑤）不编号（⑤ 弱化呈现，决议 25）。
- **上下拖拽 = 手动插队，只对可推组生效**：手动顺序是**持久意图**（记在任务上）——
  被拖到前面的任务压在可推组最上面，**保持到它完成**；其余可推任务仍按调度排序。
  多件插队件之间**后插的在上**（栈式），插队件之间可再拖调整相对顺序。
- **长按条目弹菜单**：完成 / 推迟（档位见 §7.2）/ 编辑 / 删除（软删除，见 §12 决议 15）；
  『编辑』复用创建对话框，**编辑态 = 属性展开表单**（显式控件直改类型/日期/工时/备注，
  改完调度自动重锚）——长按滑档位手势只属于『新建』（见 §12 决议 17）。
- **菜单按组上下文相关**（决议 23/25）：
  ② 固定时点组的『推迟』= snooze 本次提醒（事件时刻不变，走 D8 档位）；
  ④ 例行实例 = **完成**（今日完成，次日再生）/ **跳过今天**（不完成，今日不再显示）/
  **编辑规则**（跳设置页定位到该规则，不提供"编辑实例"——实例是临时的）/
  **删除规则**（需确认，从 routines.md 移除），**无『推迟』**（实例默认不响，改节奏去编辑规则）；
  ⑤ 被挑散件 = 完成 / **放回池子** / 编辑（展开表单，可顺手转正）/ 删除，
  **无『推迟』**（无日期可推，"放回池子"承担"今天不想做"的语义）。
- **完成后**：人类文档里那一行**原地**把 `- [ ]` 改成 `- [x]` 并补 `完成 <日期,时间>`
  （内核属性文档同步落 `status: completed` 与 `completed_at`），**这一行与其余内容
  原样保留**（Obsidian 里可翻历史），各清单立即消失；疑问笔记文件与此无关，**零写入**。
  **删除** = 内核属性文件移入 `.gtd/.trash/` + 那一行用 `%%…%%` 注释掉（可捞回，见 §4.3）。
- 每页都可**添加待办**（进 §5.1 对话框）与**堆三无**。

### 6.2 第 2 页：疑问笔记

- 数据源：用户在 Obsidian 维护的一篇 Markdown（暂名"疑问笔记.md"，路径设置里可配）；
  **App 只读，编辑去 Obsidian**（与 Obsidian 的连接形式见决议 37：就只是多一个入口，
  不做插件、不接管 vault）。
- **提取显示规则**（已确认）：
  - 显示 **frontmatter 闭合 `---` 之后、到下一个 `---` 之间**的那段正文（不是 YAML 本身）；
  - 行内出现 `[[` 的**整行屏蔽不显示**（过滤 wiki 链接行）；
  - **App 对该文件零写入**——frontmatter 一个字符都不动；它不是任务，只是只读查看；
  - 正文里没有第二个 `---` → 取到**文件末尾**；
  - 空状态：文件未配置/找不到 → "未找到疑问笔记，去设置选择文件"；整段被 `[[` 过滤光 → "这一段没有可显示的内容"。

### 6.3 第 3 页：任务池

- **条目操作（长按菜单，散件段与计划段同款）**：**挑到今日**（不转正，附今日尾部，
  当日手动挑标记生效，自动挑让位）/ **转正**（走 §5.1 对话框补属性，进调度）/
  完成 / 编辑 / 删除（软删除，见 §12 决议 15）。
- **上下拖拽**：仅为整理位置方便看（无调度含义）；**顺序持久化**——显示序记在任务
  metadata，重启保留；新建任务进对应组末尾。
- **空状态**："池干水清"。
- **一条横线分两段**：
  - **横线前（计划段）**：明天、后天……未来要做的任务（有截止的可推 + 未来的不可推）；
    **周期任务按下一次发生日期升序插入对应位置**（设置里提供"是否显示"开关；决议 27）；
  - **横线后（散件段）**：全部三无散件。
- **散件转正**两条路：
  1. **闲时手动**：长按散件选『转正』→ 走 §5.1 对话框补属性（分类/截止/工时）→ 进调度；
  2. **定期挑**（自动）：间隔可设置，**默认一天**；**随机**挑一件附到今日清单尾部，不响提醒只可见。
     细则：每天**独立随机**；昨天没做完的件**回池子重新参与随机**（不优先续挑）；
     你**手动挑过**的日子，当日自动挑就让位——今日尾部**最多一件散件**。

### 6.4 日历弹窗

- 从侧边栏点击（日历入口）弹出**月历**；有任务的日子打点。
- 点某天 → **当天列表从弹窗底部下滑展开**（同一弹窗内联动，**不再叠一层弹窗**）。
- 当天列表里可直接**改某任务日期**，改完调度自动重锚（事件驱动，符合防 Zeno 规则）。
- **改期的适用范围**（决议 24）：可推/不可推任务可改；**例行实例只读**（在其发生日打点，
  点开提供『编辑规则』跳转）；散件与被挑散件无日期，不进日历。

### 6.5 隐私过头（拍板）

- 人多的场合：把面板**拖拽过头**（越过阈值）→ 面板**隐藏所有已有任务内容**，
  只变成**一条极简单任务输入框**——写完即走，旁边人瞟不到任何清单。
- 松手后停留在"只留输入"状态；再次正常拖出才恢复完整面板。
- **输入框创建的任务 = 等价堆三无**：入池散件段，顶部小字提示"已静默入池"（§12 决议 22）。

### 6.6 空状态与首次引导

- **首次拖出侧边栏**：一次性三步气泡引导——拖出展开 / 重手势翻页 / 右下角『+』添加；设置里可重看；
- 今日清单空："今天没有会响的事"，附快捷按钮『从池子随机挑一件』（等价手动挑，§12 决议 21）；
- 任务池空："池干水清"；疑问笔记空态见 §6.2。

## 7. 提醒系统

### 7.1 默认策略（拍板：Slack 默认 + AI 调参）

- 有截止日的可推任务沿用现有 slack.v1：

```text
available = workMinutesBetween(now, deadline)      # 跳过夜间/午休/周末
slack     = available − remainingWork
interval  = clamp(0.5 × slack, 30min, 480min)
nextReminderAt = addWorkMinutes(now, interval)     # 自动落在工作窗内
```

- **全局通知时间段（多段式）**：可推任务的提醒只落在时间段内，时间段外静默。
  设置里支持**多段编辑**（如 9:00–12:00、14:00–18:00、19:00–21:00，方便抠掉午睡/饭点）；
  默认一段 **9:00–21:00**；
- **AI 动态调整 = L2 软控制**：AI 只允许在 Scheduler `params` 声明范围内微调
  （α、min/max 等），一切变更走 origin=ai 的领域事件，**可审计、可拒绝**——
  回滚不承诺（架构合同 §6：逆命令机制未设计，落地前 UI 只提供"拒绝"，决议 28）；
  没配 key / AI 挂掉 → 默认策略照常。
- **不可推**：只到点响一次（拍板），不提前、不进调度。【已落地 v1.5：
  `TaskService.nextPointReminder()` + ReminderDispatcher 双源单闹钟；
  `point_fired` 保证只响一次，改期重新生效；错过超过 30 分钟不再补响（决议 32）】
- **散件 / 可推无截止**：永不提醒。
- **周期任务**：响不响单独设置；**不占工时**（不进 Slack 容量计算）；
  当天实例**跨日生成**（不存在"应用没开还会有零点任务"这回事）；
  完成即消，次日再生。【已落地 v1.5：实例在启动/跨日/回前台时**幂等**生成
  （没有"每天零点"的后台闹钟——应用下一次活着的时候补齐），落成任务文件】

### 7.2 提醒呈现与推迟（拍板）

- 到点弹**系统通知**，通知上直接给快捷按钮：**『完成』『推迟 1 小时』**；
- 点通知**正文** → 展开**侧边栏**并定位到该任务。**定位边界**：目标在今日清单 → 定位高亮；
  已滚进任务池 → 跳池子定位高亮；已完成 → toast"该任务已完成"；已删除 → toast"已删除，可在回收找回"。
- **推迟档位**：通知快捷固定 1 小时；长按菜单『推迟』给档位：**30 分钟 / 1 小时 / 3 小时 /
  明早 9 点 / 自选时间**。推算结果落在静默/休息段 → **顺延到下一时段开头**（不强制响，
  夜间静默是硬规则；**不可推的到点闹钟不受静默限制**）；跨休息段的推迟按 architecture.md **D8**
  给显式选项"到下个工作窗"（≤120 分钟按自然时间）。**绝对档位（明早 9 点 / 自选）原样响**
  ——静默段顺延只作用于相对档位推算出的时刻（决议 26）。
- **可选闹钟模式**（**只对时点性提醒生效**：不可推的到点提醒 + 设了响的周期任务；
  可推任务的 Slack 例行软提醒永远普通通知）：开启后升级为**全屏提醒界面 + 持续响铃**，
  必须手动点『完成 / 推迟 / 知道了』才停；走系统闹钟渠道，媒体静音压不住
  （实现上对应 full-screen intent，需锁屏显示/上层显示权限，走 PermissionPort）。
  【已落地 v1.5：原生渠道 `gtd_alarm`（IMPORTANCE_HIGH + 闹钟音 + 震动）+
  `setFullScreenIntent`；权限缺失时退化为普通通知（决议 31）。
  应用被杀时由系统闹钟的接收器照"交付草案"弹出通知，按钮点击回传应用；
  应用当时没开则在下次启动补做（决议 33）】

## 11. 边界与异常

- **权限被拒**：悬浮窗被拒 → App 内抽屉形态兜底（**三页全功能复用**：同一套 panels，
  App 内左侧滑呼出，无悬浮把手）；悬浮面板的引擎/窗口起不来 → 回退为"把手打开应用面板"
  （功能不减，只是会跳进应用）；通知被拒 → 提醒只在侧边栏内高亮；
  精确闹钟被拒 → 提醒可能迟到（如实提示用户）。
- **后台被杀 / Doze**：提醒依赖 AlarmPort 系统闹钟唤醒（architecture.md 附录 A），不靠 Timer。
- **闹钟模式权限**：全屏提醒需要锁屏显示/上层显示权限；被拒则退化为普通通知 + 响铃。
- **无 AI 配置**：默认策略照常，设置页显示"未接入"。
- **误触防护**：翻页重手势、确认长按、完成走长按菜单——三处天然防误触；
  通知上的"完成"按钮点击后给撤销 toast。
- **隐私过头状态**下不渲染任何任务数据（不只是视觉隐藏，不进 widget 树）。
- **存储层的异常**（v0.7）：
  - 人类文档里缺 `创建` 的复选框行 → **不改动**、进 `warnings`（当普通待办看待）；
  - 两行内容完全相同 → 无法区分内核属主，只告警不猜（改掉任务名或创建时间即可分开）；
  - 人在 Obsidian 里删掉了某一行 → 内核属性文件**保留并提示**，不静默删数据；
  - 人在 Obsidian 里改了任务名 → 优先按指纹、其次按名字、最后按位置配对（附录 B.3）；
    位置配对只在"两边剩余数量恰好相等"时启用，数量不等宁可新接管也不猜。

## 14. 范围声明（有意不做 / 边界澄清，防将来被当遗漏）

- **性能/尺寸规格**（面板宽度、把手大小、动画时长等）：实现期以手感调参定，不写死数字；
- **多设备同步**：v1 单机——任务目录即数据（Obsidian 共享已是事实上的"同步"）；
- **备份恢复**：交给任务目录本身（文件即备份），App 不另做；`legacy-tasks/`
  （迁移存档）与 `.gtd/.trash/`（回收站）都**只增不自动清理**；
- **Obsidian 插件 / vault 接管**：不做。与 Obsidian 的连接形式就只有"多一个手机侧边栏
  入口读同一批文件"（决议 37）；
- **人类文档的任务行里写内核字段**：不做。id/工作强度/优先级/时间裕度/剩余工作量
  只进 `.gtd/`，人类文档保持干净（决议 36）；
- **数据埋点/使用统计**：无（`log.md` 是本地操作流水，不上报）；
- **新平台 shell**（iOS 等）：架构支持，需求不在本阶段；
- **桌面/Windows 端**：沿用现有 shell，不在本文档范围。
