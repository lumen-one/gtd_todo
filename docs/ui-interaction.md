## 0. 一句话定位与设计原则

**日常一切操作发生在悬浮侧边栏里，App 主体几乎不开。**

0. **数据归属（v0.7 起的地基）**：人写的归人、内核算的归内核，**物理分成两个文档**
   （人类文档 `tasks.md` + 内核属性文档 `.gtd/<id>.md`，见 §4.3 与决议 36）。
   下面的原则都建立在这条之上——侧边栏怎么摆、手势怎么滑，都不改变"谁写谁负责"。
1. **唯一入口哲学**：侧边栏承载添加、查看、完成、推迟、改期、日历、任务池的全部日常操作；
   打开 App 只剩设置页（暂定）。
2. **忙时零摩擦**：忙的时候"堆三无"一键入池，属性整理全部推迟到闲时。
3. **隐私防瞟**：人多的场合点面板头的『隐私』，面板隐藏全部清单内容，只留一条极简输入框
   （**v0.15 改入口**：原先是"面板拖过头"，那道手势已删，见 §6.5）。
4. **提醒自律，且默认不打扰**（v0.9；v0.12 起前两档并入三档，见 §7.0）：默认
   **标准模式**只排列不提醒——看得到先后，听不到声音；需要被推着走的事
   **逐个手动开提醒**。切到**完整模式**才是"算法判定该响的都响"（原方案）；
   **无排序**再弱化一层——连先后也交给人拖。三档都保留：夜间静默（通知时间段）、
   散件永不出声。

## 1. 名词表（本文件的专用词）

| 词 | 定义 |
|---|---|
| **侧边栏** | App 自建的悬浮侧边条：贴屏小把手，任意界面（含其他 App 上方）拖出展开成面板 |
| **可推** | 软任务：靠投入时间完成的事（写论文、收拾房间）；可有可无截止日 |
| **不可推** | 固定时点任务：到点必须发生的事（会议、约定、车票）；有确切日期时间，不需估工时 |
| **三无** | 无结束日期、不需要提醒、可被推迟的任务——即完全无约束的散件 |
| **散件** | 任务池横线后面的三无任务，等闲时整理或被定期挑走 |
| **任务池** | 侧边栏第 3 页：所有未完成任务的总览，横线分"未来计划段"与"散件段" |
| **今日清单** | 侧边栏第 1 页：逾期置顶 + 固定时点组 + 可推组 + 例行组（周期实例）+ 被挑散件，分组连续编号；"当前"即"今日" |
| **疑问笔记** | 侧边栏第 2 页：从指定 Markdown 文件只读提取显示的段落，编辑去 Obsidian |
| **周期任务** | 循环任务（每天/每周X），在设置页创建维护，到点自动出现，响不响单独设 |
| **定期挑** | 定时（默认每天）从散件段随机挑一件附到今日清单尾部，不响提醒，仅可见 |
| **今日会响** | **会真的响**的今日条目：提醒锚点落在今天且**过了提醒门槛**的可推任务 + 今天到点且开了提醒的不可推任务（提醒口径；分组构成见 §6.1，门槛见 §7.0） |
| **裕度（slack）** | 距截止的真实可用工时 − 剩余工时，唯一压力表（见 architecture.md） |
| **人类文档** | `tasks.md`：**所有任务**都记在这一个文档里，`# 标题` 分类，一条任务一行（见 §4.3）。这里的**「分类」= `# 标题` 小节**，与任务类型（fixed/flex，记在内核属性的 `type`）不是一回事 |
| **内核属性文档** | `.gtd/<任务id>.md`：内核算出来的属性（任务id/工作强度/优先级/时间裕度/剩余工作量）；人也能看能改（见 §4.3） |
| **行指纹（digest）** | 人类文档里那一行的指纹，存在内核属性文档里；两条文档靠它对号（人不写、也不该改） |
| **调度模式** | **标准**（默认）/ **完整** / **无排序** 三档选一个，见 §7.0 与决议 43。三档是**一条逐级弱化的谱系**：算法替人做主的程度依次递减 |
| **标准模式** | 默认档。算法照常算先后（谁先做），但**不出声**；只有手动开了提醒的任务会响 |
| **完整模式** | 算法判定该响的都响（顺序与标准完全一致） |
| **无排序模式** | **标准的再弱化版**：不再按算法排先后，今日清单**可推组**的顺序全靠手动拖（其余组的排法不变，见 §6.1）；**今天该看哪几件仍由算法挑**（锚点落在今天 / 今天到期），清单不会因此变长 |
| **调度优先级** | 算法排顺序用的分 = `risk × 优先级`（人看不到具体数字，只看顺序） |
| **手动序** | 无排序档下人拖出来的顺序（`manual_order`，记在任务上、重启保留）；切到标准/完整后**保留但不生效** |
| **风险（risk）** | 由时间裕度算出的"误期风险"，∈(0,1]，裕度越小越接近 1；**非线性**（§7.1） |
| **详情卡** | 点条目展开的那张**只读**卡（§6.1，决议 44）：备注全文 + 全部属性 + 调度派生量；改数据仍要走显式动作（底部按钮与长按菜单同源） |

## 4. 任务模型（UI 视角）

### 4.1 类型二分

每条任务二选一：

| | 不可推（固定时点） | 可推（软任务） |
|---|---|---|
| 例子 | 会议、约定、车票 | 写论文、回邮件 |
| 必填 | 日期时间（创建时选『定点』，经『自选…』弹日期+时间弹窗） | 截止日可选 |
| 估工时 | 不需要 | 需要（进调度） |
| 提醒 | **只到点响一次**（**完整模式**，或该任务手动开了提醒时） | 有截止日→按裕度排序并按裕度调频（§7）；**标准模式下手动开了提醒才响**；无截止日→**不提醒** |
| 归属 | 今日清单（到点当天）、任务池计划段 | 有截止：今日清单+任务池计划段；无截止：任务池散件段 |

### 4.2 字段（对现有 domain 的扩展需求）

沿用现有 Task（id/title/description/deadline/estimatedWork/remainingWork/importance/status/
snoozedUntil/metadata/created），需要扩展（详见 §10）：

- **类型**：fixed / flex（可推）。三无 = flex 且无截止。
- **截止日可空**：现在 deadline 是必填，散件没有截止——这是最大的领域变更。
- **标签 `tags`**（v0.7 新增，正式字段）：人类文档行尾的 `##标签`，见 §4.3。
- **完成时刻 `completedAt`**（v0.7 新增，正式字段）：人类文档的 `完成 <日期,时间>`，
  与打勾同步落一次；`status=completed` 与它任一成立即视为完成。
- **提醒开关 `remind`**（v0.9 新增，走 metadata 缓冲带）：标准模式下给**单个任务**
  开提醒——开了它，这一件就按完整模式的规则出声。它**不改变顺序**，只改"出不出声"
  （§7.0）；完整模式下这个开关没有意义（本来就全响）。
- 散件与"被定期挑中"的状态、周期任务规则，见 §6.3 与 §10。

### 4.3 存储形态：双文档（决议 36/37，正典见 architecture.md 附录 B）

**人写人看的归一个文档，内核算的归另一个文档。** 任务数据不是一个文件，是两个：

```text
tasks/
├── tasks.md           ← 人类文档：Obsidian 里看/改/共享的就是它
└── .gtd/<任务id>.md    ← 内核属性文档：应用自己写
```

**人类文档**（一个文档、`# 标题` 分类、一条任务一行）：

```markdown
# 工作

- [ ] 任务名 创建 2026-10-11,07:00 结束 2026-10-12,18:00 这是备注。 ##这是标签1 ##这是标签2
- [x] 交房租 创建 2026-10-01,09:00 完成 2026-10-01,09:30 ##生活
```

人写的六个属性：**任务名、创建日期、结束日期、完成日期、备注、标签**。
**更多的标签 = 更多的属性**：多打一个 `##标签` 就多一个维度，内核不解释它的语义
（唯一用法：新任务按第一个标签落到同名 `# 小节`）。

**内核属性文档**（应用根据已有属性算出来或补上的那部分）：

```markdown
---
id: task-001
digest: 7683b0bb       # 行指纹：把这一条和人类文档里那一行对上号
work_intensity: 120    # 工作强度（完成它需要的工时，工作分钟）
remaining_load: 0.75   # 剩余工作量（**分数**，乘以工作强度才是分钟）
priority: 3            # 优先级 1–5
time_slack: 210        # 时间裕度（工作分钟）
status: active
---
```

**分工与承诺**（写死，这是本次改造的全部要点）：

| | 人类文档 `tasks.md` | 内核属性文档 `.gtd/<id>.md` |
|---|---|---|
| 谁写 | 人（也由应用代笔**自己那一行**） | 应用 |
| 应用改什么 | 只改它自己写的那一行：插入新任务、打勾、补完成时刻 | 全部字段随任务对象改写 |
| 应用绝不做什么 | **不重排行、不动别人的行、不动标题/空行/正文** | 不动人的东西（这文件本来就只有内核字段） |
| 人在 Obsidian 里能做 | 改名/改日期/改备注/加删行/换分类/加标签 | 也能改（字段级保真：注释、未知字段、内核备注原样保留） |
| 冲突时谁赢 | 人类那边赢（任务名/创建/结束/完成/备注/标签） | 内核那边赢（工作强度/优先级/时间裕度/剩余工作量） |

- **人只改人类文档也能用**：应用发现指纹变了就按上面的归属合并；
  新增的行会被内核接管并分配任务 id（**首次同步会提示一次**）；
  删掉的行不会连带删掉内核属性（文件即备份，删不删由人决定，只提示）；
- **人类文档里不出现任何内核字段**：id、工作强度、优先级、时间裕度、剩余工作量
  一个都不写进去——这是"共享/查看的文档要干净"这条要求的落地；
- **落实决议 36 的形态选择**：所有任务记在一个 `tasks.md` 里用标题分类
  （不是一任务一文件）；`log` 数据（领域事件流）**单独一个文档**，
  见 architecture.md §3.3 与决议 37。

> 与 Obsidian 相连的形式不变（§6.2 与决议 37 重申）：**形式上只是单纯在 Obsidian 外
> 增加一个手机侧边栏的快捷入口**——不做 Obsidian 插件、不接管 vault、不代改笔记，
> 差异只在"多一个入口读同一批文件"。

## 5. 创建流程

### 5.1 完整对话框（侧边栏内弹出）【v0.11：去手势化，档位常驻】

```text
┌──────────────────────────────┐
│  新建待办                     │
│  回车 = 跳到备注 · 直接点确认 = 三无   │  ← 对话框常驻提示文案
│  标题…            ← 首焦点    │
│  备注…（选填）                │
│                              │
│  类型 [三无 ✓] [有截止] [定点] │  ← 常驻按钮，默认『三无』
│                              │
│      [ ✱ 确认 ]              │  ← 纯点按，没有任何手势
└──────────────────────────────┘
```

1. 标题输入框首焦点；**回车 = 跳到备注**（对话框上有提示文案说明这一操作）。
2. 备注选填，可留空。
3. **类型档位常驻在对话框里**（拍板：不再藏在手势里），三个互斥按钮，**默认『三无』**：
   - **三无** = 可推 + 无截止 + 不提醒 → 入池散件段；
   - **有截止** = 可推 + 有截止日 → 下方升起日期档位；
   - **定点** = 不可推（固定时点）→ 下方升起日期档位。
4. **日期档位**（选了类型才升起，没选就是三无）：
   - 『有截止』→ **【今天】【明天】【自选…】**：今天/明天取该日 **18:00**
     （当日工作窗末尾的常用截止点），要精确到分走『自选…』；
   - 『定点』→ 只给 **【自选…】** 一个：定点必须有确切时刻，"今天/明天"这种含糊档位没有意义；
   - 『自选…』= 弹日期 + 时间弹窗，选完**回到对话框**，所选日期显示在按钮上；
   - 点回『三无』→ **清掉已选日期、档位收起**（可逆，不留残留）。
5. **确认键是纯点按**（长按与滑动全部移除）：
   - 停在『三无』（默认态）→ 点确认**直接创建三无任务入池散件段**，中间不弹任何东西；
   - 选了『有截止』/『定点』但还没点日期档位 → 点确认**自动弹日期+时间弹窗**，选完即创建；
   - 已选日期 → 点确认按所选类型与日期创建（可推有截止 / 定点）。
6. **提醒开关不进新建对话框**（明确不做）：默认三无本来就不响；要响在创建后走『编辑』
   开『提醒我』（§7.0）。新建只问"是什么、什么时候"，不额外问"要不要吵你"。
7. **语音输入**：任何输入框都可以用输入法的语音键说话出字，App 不额外做语音功能。

> **为什么砍掉手势**：长按不松再滑档位这套动作**没有视觉 affordance**——不长按就永远
> 看不到档位在哪、也无从知道它能二分；而且它和系统返回手势、面板翻页手势抢同一块触摸区
> （决议 41 已经为此吃过一次亏）。档位摆成常驻按钮之后，"默认三无、点确认就走"这条最
> 短路反而比原来更快，与『堆三无』只差一个对话框的距离。

### 5.2 快捷堆三无（忙时专用）

- 独立按钮（与"添加待办"并排），**跳过整个对话框**：
  输入一句话（或一个词）→ 即刻成为三无任务入池散件段。
- 目标场景：正在忙，只想把脑子里的东西甩出去，两秒内完成。
- **与 §5.1 的分工**（v0.11）：对话框的默认态本身已等价三无，两者只差"要不要经过对话框
  （能不能顺手写备注）"。忙到极点用堆三无，还能停半秒就用创建对话框——**两个入口都保留**。

## 6. 悬浮侧边栏

### 6.0 把手与面板

- 贴屏把手 = **一段贴在边缘的半透明白条**（10dp 宽、88dp 高、白色 55% 不透明，决议 40）：
  默认就是"看不见的存在"；可拖动停靠左右边缘，横拖或点按展开成面板；
- **面板本体是系统级悬浮面板**（v0.6 / 决议 35）：拖出后在**当前 App 上方就地展开**，
  不是把用户带进应用；面板与应用内壳**共用同一份 panels**（`ui/panels/side_panel.dart`）；
- **三页结构，左右横滑翻页**（v0.15）：页面区横向拖动即翻页，与列表的纵向滚动是
  两个方向、互不抢手；圆点同时也是**跳转靶**——点哪个跳哪页（页序指示即可点的按钮）。
- **翻页从面板内部起手**：贴着屏幕最边缘那一小条是系统返回手势的地盘（决议 41 的取舍），
  从那儿横拖可能先被判成返回 / 收起面板；往面板里挪一点起手就是翻页。

### 6.1 第 1 页：今日清单

**分组连续编号**（裁决见 §12 决议 11/12）：

```text
① 逾期组      过截止未完成：无编号、橙红徽标置顶，完成/改期前不消失
② 固定时点组  今天到点的不可推任务：按时间点升序，橙色时间徽标；组内不可拖（时间就是序）
③ 可推组      今天该动手（裕度算出的提醒**锚点**落在今天）或今天到期的可推任务：
              按调度优先级排序（裕度薄的在前，优先级作乘数）；可拖插队
              ——**无排序档下**：成员一个不变（仍按锚点准入），只是组内顺序 = 手动序
④ 例行组      周期任务当天实例：排在可推组之后；不占工时、默认不响（设了响的到点走提醒）
⑤ 被挑散件    定期挑/手动挑的那一件：附在本页最后，无提醒、仅可见
```

- **切档不改变这一页有哪些条目**（v0.9，决议 38；v0.12，决议 43）：标准/完整/无排序
  三档下分组、编号、③ 可推组的**成员完全一致**——"锚点"是调度计算，"出不出声"是门槛，
  "谁排前面"是顺序；三者互不相干。所以**切档不会让清单里的条目增减**，变的只有
  会不会弹通知（标准↔完整）与第 3 组的先后（无排序）。
- **编号跨 ②③④ 组连续**（1、2、3…）；逾期组与被挑散件（⑤）不编号（⑤ 弱化呈现，决议 25）。
  无排序档下编号照旧连续，只是那一组的**编号 = 手动顺序**。
- **上下拖拽 = 手动插队，只对可推组生效**：手动顺序是**持久意图**（记在任务上）——
  被拖到前面的任务压在可推组最上面，**保持到它完成**；其余可推任务仍按调度排序。
  多件插队件之间**后插的在上**（栈式），插队件之间可再拖调整相对顺序。
  （**无排序档下**拖拽不再是"插队"而是"定序"：整组按你拖的结果排，算法不再插手。）
- **无排序档（v0.12，决议 43）**：设置页『提醒与排序』切到**无排序**，算法就不再决定
  今日清单的先后：
  - ③ 可推组的**成员不变**——仍是"锚点落在今天 / 今天到期"的那几件。
    无排序是**今天这几件不排序**，不是把池子里所有有截止的任务都搬进今天；
  - 顺序完全按**手动序**；没排过序的任务按**创建先后**排在后面（新建的从末尾开始，
    拖一下就有序了）；
  - **③ 组内可随意拖**：拖动即整段重编号、**重启保留**，拖完算法不会再把你排回去；
  - **四处不跟着变**（沿用上面的组号）：**① 逾期组**仍置顶（那是状态，不是排序）；
    **② 固定时点组**仍按时刻升序、组内不可拖（时刻本身就是序）；**④ 例行组**仍按当天
    发生时刻升序（实例每天新生，没有手动序）；**⑤ 被挑散件**仍在最后。
    **任务池也不变**（它本来就按整理序排，见 §6.3）；
  - **只关了排序**：裕度、提醒节奏（多久响一次）、逾期与"做不到"的提示、出不出声
    全部照旧——该响的照样响，只是**先后由你定**；
  - 切回**标准/完整**时手动序**原样保留、只是不生效**，不会丢、也不用重新拖一遍。
- **点条目 = 详情卡**（决议 44）：列表行只放标题 + 备注第一行 + 状态徽标，点一下展开
  这张卡——备注**全文**、全部属性（类型 / 截止或时间 / 工时 / 重要度 / 创建 / 完成 / 标签）
  与调度派生量（时间裕度 / 下一次该看它 / 会不会响 / 提醒间隔），底部一排动作按钮
  **与长按菜单同源**（同一份条目表，不另写一套）。例行实例的详情给的是它背后的
  **规则摘要 + 发生日**（实例是临时的，决议 23）。**分工：点击看、长按做**——
  详情卡本身只读，改数据只有显式点按钮这一条路，不会"点一下就进编辑态"；
  五个组与池子两段都走这一份卡，动作按组上下文给（同上）。
- **长按条目弹菜单**：完成 / 推迟（档位见 §7.2）/ 编辑 / 删除（软删除，见 §12 决议 15）；
  『编辑』复用创建对话框，**编辑态 = 属性展开表单**（显式控件直改类型/日期/工时/备注，
  改完调度自动重锚）；**新建态 = §5.1 的常驻档位按钮**——两处都是显式控件，创建流程里
  已无手势（见 §12 决议 17 与 42）。
- **菜单按组上下文相关**（决议 23/25）：
  ② 固定时点组的『推迟』= snooze 本次提醒（事件时刻不变，走 D8 档位）；
  ④ 例行实例 = **完成**（今日完成，次日再生）/ **跳过今天**（不完成，今日不再显示）/
  **编辑规则**（跳设置页定位到该规则，不提供"编辑实例"——实例是临时的）/
  **删除规则**（需确认，从 routines.md 移除），**无『推迟』**（实例默认不响，改节奏去编辑规则）；
  ⑤ 被挑散件 = 完成 / **放回池子** / 编辑（展开表单，可顺手转正）/ 删除，
  **无『推迟』**（无日期可推，"放回池子"承担"今天不想做"的语义）。
- **完成后**：人类文档里那一行**原地**把 `- [ ]` 改成 `- [x]` 并补 `完成 <日期,时间>`
  （内核属性文档同步落 `status: completed` 与 `completed_at`），**这一行与其余内容
  原样保留**（Obsidian 里可翻历史），各清单立即消失；疑问笔记文件与此无关，**零写入**。

## 7. 提醒系统

### 7.0 调度模式三档（v0.9 决议 38 + v0.12 决议 43；**默认标准**）

**三档是一组三选一**（设置页『提醒与排序』节），按"算法替人做主的程度"从强到弱排：

| | **完整** | **标准（默认）** | **无排序** |
|---|---|---|---|
| 算法排先后（谁先做） | 是 | 是 | **否**——今日可推组由人拖（`manual_order`） |
| 自动提醒 | 凡算法判定该响的都响 | **不出声**（默认安静） | 与标准一致：不出声 |
| 单个任务 | 不用开（本来就全响） | 可手动开提醒（编辑表单『提醒我』，落 metadata `remind`） | 同标准 |
| 到点类提醒（不可推到点 / 设了响的周期实例） | 照原方案响 | 默认不响，开了才响 | 同标准 |
| 今日清单有哪几件（③ 可推组的成员） | 锚点落在今天 / 今天到期 | 同左 | **同左**（不因为是"无排序"就多塞任务进来） |
| 任务池的顺序 | 整理序（`pool_order`） | 同左 | 同左 |

一句话记：**完整 = 排 + 响；标准 = 排 + 不响；无排序 = 不排 + 不响**。
三档互不重叠，也不存在"组合"——切一档就够了，不会出现"排但不响且不按锚点"这种第四态。

- **无排序是标准的再弱化版**：它把标准档里"算法排先后"这一层也去掉，其余全部照抄标准
  ——含默认不出声、含今日清单的成员口径。想让它出声，仍然去编辑表单给单件开『提醒我』。

- **为什么默认标准**：提醒是打扰。默认"只排队、不出声"，需要被推着走的事再单独开——
  一次设置或一次点击的代价，换默认安静（代价记在 architecture.md §12）。
- **门槛与送达策略是两件事，串联生效**：门槛决定"**要不要**出声"（这一件
  `reminds = false`、结果里的下一站 `nextReminderAt = null` 就是不出声），通知时间段决定
  "**什么时候**允许出声"（段外顺延，§7.1）。所以标准模式下连"顺延"都不会发生——
  根本没有那一站。（**锚点照算**：提醒锚点是调度计算，今日清单准入用它，不受门槛影响。）
- **切换立即生效**：顺序与下一站闹钟都重算（提醒是计算结果，无迁移、无历史改写）。

### 7.1 算法与默认策略（拍板：时间裕度优先 + AI 调参）

有截止日的可推任务，一律换算成"工作分钟"（跳过夜间/午休/周末）：

```text
available = workMinutesBetween(now, deadline)      # 距截止的真实可用工时
remaining = 工作强度 × 剩余工作量                    # 剩余工时（分钟）
slack     = available − remaining                   # 裕度，唯一的压力表
risk      = slack ≤ 0 ? 1 : exp(−(slack/τ)^γ)      # 【非线性】误期风险 ∈ (0,1]
priority  = risk × importance                       # 调度优先级 = 排序键（优先级缺省 3）
interval  = clamp(0.5 × slack, 30min, 480min)       # 提醒节奏（锚点用；出不出声看门槛）
nextReminderAt = addWorkMinutes(now, interval)      # 提醒锚点，自动落在工作窗内
默认：τ = 480（1 个工作日）、γ = 1
```

- **裕度优先**：裕度越薄风险越高、越排在前面；**优先级（1–5，缺省 3）是乘数**——
  让重要的事整体前移，但盖不过已经贴住截止的事（risk 接近 1 时，乘数再小也靠前）。
- **为什么非线性**：线性要让裕度"到哪算 0"凭空定一个量纲，还会算出负风险；
  指数族只要一个尺度 τ，且恒在 (0,1]——**裕度还宽时催得少，裕度一薄就陡然变急**；
  γ>1 = 裕度充足时压得更低（更平）、薄了迅速冲到 1（更陡）。
- **`priority` 这个名字只属于算法内部**：人定的是**优先级**（内核属性文档的
  `priority` 键 = `Task.importance`，缺省 3），算出来的是**调度优先级**（不落盘、不进人类文档）；
  界面照旧展示裕度这类派生量，但不显示这个排序分——**顺序本身就是表达**。
- **全局通知时间段（多段式）**：可推任务的提醒只落在时间段内，时间段外静默
  （这是**门槛之后**的一道，§7.0）。设置里支持**多段编辑**
  （如 9:00–12:00、14:00–18:00、19:00–21:00，方便抠掉午睡/饭点）；默认一段 **9:00–21:00**；
- **AI 动态调整 = L2 软控制**：AI 只允许在 Scheduler `params` 声明范围内微调
  （α、min/max、风险尺度 τ 与陡度 γ），一切变更走 origin=ai 的领域事件，**可审计、可拒绝**——
  回滚不承诺（架构合同 §6：逆命令机制未设计，落地前 UI 只提供"拒绝"，决议 28）；
  没配 key / AI 挂掉 → 默认策略照常。
- **不可推**：只到点响一次（拍板），不提前、不进调度；**标准模式下要先给这一件开提醒**
  才会响（§7.0）。【已落地 v1.5：
  `TaskService.nextPointReminder()` + ReminderDispatcher 双源单闹钟；
  `point_fired` 保证只响一次，改期重新生效；错过超过 30 分钟不再补响（决议 32）】
- **散件 / 可推无截止**：永不提醒（三档都一样）。
- **周期任务**：响不响单独设置（**标准模式下"规则设了响"就等价于给这个实例手动开了提醒**）；
  **不占工时**（不进裕度容量计算）；
  当天实例**跨日生成**（不存在"应用没开还会有零点任务"这回事）；
  完成即消，次日再生。【已落地 v1.5：实例在启动/跨日/回前台时**幂等**生成
  （没有"每天零点"的后台闹钟——应用下一次活着的时候补齐），落成任务文件】

### 7.2 提醒呈现与推迟（拍板）

> **前提（v0.9）**：本节讲的是"响了之后长什么样"。**标准模式下大多数任务走不到这里**
> ——要响，先给那一件开提醒，或把模式切成完整（§7.0）。

- 到点弹**系统通知**，通知上直接给快捷按钮：**『完成』『推迟 1 小时』**；
- 点通知**正文** → 展开**侧边栏**并定位到该任务。**定位边界**：目标在今日清单 → 定位高亮；
  已滚进任务池 → 跳池子定位高亮；已完成 → toast"该任务已完成"；已删除 → toast"已删除，可在回收找回"。
- **推迟档位**：通知快捷固定 1 小时；长按菜单『推迟』给档位：**30 分钟 / 1 小时 / 3 小时 /
  明早 9 点 / 自选时间**。推算结果落在静默/休息段 → **顺延到下一时段开头**（不强制响，
  夜间静默是硬规则；**不可推的到点闹钟不受静默限制**）；跨休息段的推迟按 architecture.md **D8**
  给显式选项"到下个工作窗"（≤120 分钟按自然时间）。**绝对档位（明早 9 点 / 自选）原样响**
  ——静默段顺延只作用于相对档位推算出的时刻（决议 26）。
- **可选闹钟模式**（**只对时点性提醒生效**：不可推的到点提醒 + 设了响的周期任务；
  可推任务的 Slack 例行软提醒永远普通通知）：开启后升级为**全屏提醒界面 + 持续响铃**，
  必须手动点『完成 / 推迟 / 知道了』才停；走系统闹钟渠道，媒体静音压不住
  （实现上对应 full-screen intent，需锁屏显示/上层显示权限，走 PermissionPort）。
  【已落地 v1.5：原生渠道 `gtd_alarm`（IMPORTANCE_HIGH + 闹钟音 + 震动）+
  `setFullScreenIntent`；权限缺失时退化为普通通知（决议 31）。
  应用被杀时由系统闹钟的接收器照"交付草案"弹出通知，按钮点击回传应用；
  应用当时没开则在下次启动补做（决议 33）】

## 11. 边界与异常

- **权限被拒**：悬浮窗被拒 → App 内抽屉形态兜底（**三页全功能复用**：同一套 panels，
  App 内左侧滑呼出，无悬浮把手）；悬浮面板的引擎/窗口起不来 → 回退为"把手打开应用面板"
  （功能不减，只是会跳进应用）；通知被拒 → 提醒只在侧边栏内高亮；
  精确闹钟被拒 → 提醒可能迟到（如实提示用户）。
- **后台被杀 / Doze**：提醒依赖 AlarmPort 系统闹钟唤醒（architecture.md 附录 A），不靠 Timer。
- **闹钟模式权限**：全屏提醒需要锁屏显示/上层显示权限；被拒则退化为普通通知 + 响铃。
- **无 AI 配置**：默认策略照常，设置页显示"未接入"。
- **误触防护**：完成走长按菜单（天然防误触）；**翻页不再靠"重手势"**（v0.15）——
  横滑与列表的纵向滚动方向正交，浏览清单不会翻页，翻页也不会误滚列表；
  通知上的"完成"按钮点击后给撤销 toast。**新建确认已改为纯点按（决议 42），不再承担
  防误触职责**：误建的代价很低（直接进散件段，长按就能改能删）。
- **隐私过头状态**下不渲染任何任务数据（不只是视觉隐藏，不进 widget 树）。
- **详情卡是打开那一刻的快照**（v0.13）：它不订阅控制器的后续刷新（后台重锚、别的
  引擎改了任务，卡上的派生量不会自己变）。动作一律"先收卡再执行"（执行完这条任务
  往往已经从清单消失），所以不会留下一张指向旧数据的卡；要看最新的，关掉再点一次。
- **默认模式下"什么都不响"**（v0.9）：这是**标准模式的正常表现，不是故障**。要响有两条路——
  ①给那一件开『提醒我』（编辑表单里），②把设置里的调度模式切成**完整**。
  设置页的三选一旁写明这一点，避免被当成通知权限没给。
- **无排序模式下今日清单不会变长**（v0.12）：可推组成员与标准/完整完全一致
  （仍按"锚点落在今天 / 今天到期"准入），变的只有组内顺序。条目无故变多是 bug
  不是特性；不想看到的拖到下面，要回到"算法排先后"就切回**标准**或**完整**。
- **存储层的异常**（v0.7）：
  - 人类文档里缺 `创建` 的复选框行 → **不改动**、进 `warnings`（它在 Obsidian 里仍是
    普通待办，但内核不接管、不进任何清单——与 architecture.md 附录 B.1"只进 warnings"是同一件事）；
  - 两行内容完全相同 → 无法区分内核属主，只告警不猜（改掉任务名或创建时间即可分开）；
  - 人在 Obsidian 里删掉了某一行 → 内核属性文件**保留并提示**，不静默删数据；
  - 人在 Obsidian 里改了任务名 → 优先按指纹、其次按名字、最后按位置配对（附录 B.3）；
    位置配对只在"两边剩余数量恰好相等"时启用，数量不等宁可新接管也不猜。

## 14. 范围声明（有意不做 / 边界澄清，防将来被当遗漏）

- **性能/尺寸规格**（面板宽度、把手大小、动画时长等）：实现期以手感调参定，不写死数字；
- **多设备同步**：v1 单机——任务目录即数据（Obsidian 共享已是事实上的"同步"）；
- **备份恢复**：交给任务目录本身（文件即备份），App 不另做；`legacy-tasks/`
  （迁移存档）与 `.gtd/.trash/`（回收站）都**只增不自动清理**；
- **Obsidian 插件 / vault 接管**：不做。与 Obsidian 的连接形式就只有"多一个手机侧边栏
  入口读同一批文件"（决议 37）；
- **人类文档的任务行里写内核字段**：不做。id/工作强度/优先级/时间裕度/剩余工作量
  只进 `.gtd/`，人类文档保持干净（决议 36）；
- **提醒的"自动升级"**：不做（v0.9）。标准模式下**不会**因为"快到期了"就自动开始提醒
  ——要响只能给那一件开提醒，或把模式切成完整。这是"默认安静"的代价，记在架构合同 §12；
- **用户自选调度算法**：不做（`slack.v1` 留在算法注册表里做对照，但设置页没有切换入口；
  要换得动组装点）。**调度模式三档不是算法选择**：换算法是换"怎么算 risk/priority"，
  而这三者改的是"算完之后用不用它"，两者别混为一谈；所以 v0.12 没有往注册表里加
  第三个不带数学的假算法，`Scheduler.schedule` 也不收任何排序口径；
- **无排序档下的"智能整理"**：不做。按截止/优先级/习惯自动重排、或提示"要不要按算法
  排一遍"，都与该档"顺序就是人的决定"直接冲突；要做也只能做成**一次性**的显式动作
  （点一下才排，且排完即转为手动序）；
- **给固定时点组与例行组排手动序**：不做。前者时刻就是序、后者实例每天新生没有可持久的
  序号（决议 43 的"四处不跟着变"）；
- **详情卡的"整卡可编辑"**：不做（决议 44）。详情卡只读，改数据走显式动作（底部按钮
  或长按菜单）；同理**详情里不做改期**（改期的主场景在日历 §6.4）、**不显示排序分**
  （`risk` / `priority` 是排序键，顺序本身就是表达）。要改字段去『编辑』；
- **数据埋点/使用统计**：无（`log.md` 是本地操作流水，不上报）；
- **新平台 shell**（iOS 等）：架构支持，需求不在本阶段；
- **桌面/Windows 端**：沿用现有 shell，不在本文档范围。
