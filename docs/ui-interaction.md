## 0. 一句话定位与设计原则

**日常一切操作发生在悬浮侧边栏里，App 主体几乎不开。**

0. **数据归属（地基）**：人写的归人、内核算的归内核，**物理分成两个文档**
   （人类文档 `tasks.md` + 内核属性文档 `.gtd/<id>.md`，见 §4.3）。
   下面的原则都建立在这条之上——侧边栏怎么摆、手势怎么滑，都不改变"谁写谁负责"。
1. **唯一入口哲学**：侧边栏承载添加、查看、完成、推迟、改期、日历、任务池、查看已完成的全部日常操作；
   打开 App 只剩设置页（暂定）。
2. **忙时零摩擦**：忙的时候点「+」、默认三无直接确认入池，属性整理全部推迟到闲时（三无的工作强度默认'长期'——不估工时、不设优先级，§4.2）。
3. **隐私防瞟**：人多的场合**不打开面板**——把手拖出头再拐个弯，就地记一条（§6.8），
   清单一次都不露；面板一旦打开，内容就在明处（v1.24 撤掉了『隐私』按钮，§6.5）。
4. **提醒自律，且默认不打扰**（见 §7.0）：默认
   **标准模式**只排列不提醒——看得到先后，听不到声音；需要被推着走的事
   **逐个手动开提醒**。切到**完整模式**才是"算法判定该响的都响"；
   **无排序**再弱化一层——连先后也交给人拖。三档都保留：夜间静默（通知时间段）、
   散件永不出声。

## 1. 名词表（本文件的专用词）

| 词                   | 定义                                                                                                                                                                             |
| -------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **侧边栏**           | App 自建的悬浮侧边条：贴屏小把手，任意界面（含其他 App 上方）拖出展开成面板                                                                                                      |
| **可推**             | 软任务：靠投入时间完成的事（写论文、收拾房间）；可有可无截止日                                                                                                                   |
| **不可推**           | 固定时点任务：到点必须发生的事（会议、约定、车票）；有确切日期时间，不需估工时                                                                                                   |
| **三无**             | 无结束日期、不需要提醒、可被推迟的任务——即完全无约束的散件；**工作强度默认'长期'**（见下面两行）                                                                          |
| **散件**             | 三无任务（默认'长期'）：标准/完整档在任务池横线后面，等闲时整理或被定期挑走；**无排序档常驻今日页最底**（§6.1 ⑥）                                                                |
| **长期（工作强度）** | 工作强度的一个**特殊值**：不是分钟数，是"这事长期存在、眼下估不出来"的标记；三无任务的缺省值                                                                            |
| **长期任务**         | 工作强度 = 长期的任务：**没有**工作强度数值、优先级、时间裕度（剩余工作量同理），内核属性文档里**只有一个任务 id**（§4.3）                                              |
| **任务池**           | 侧边栏『任务池』页：所有未完成任务的总览，横线分"未来计划段"与"散件段"（无排序档只剩计划段，§6.3）                                                                                   |
| **已完成**           | 侧边栏『已完成』页：已完成任务的总览，按完成日期分今天/昨天/更早三组；动作只有『恢复未完成』与删除（§6.7）                                                                            |
| **今日清单**         | 侧边栏『今日清单』页：挂起组（最顶）+ 逾期置顶 + 固定时点组 + 可推组 + 例行组（周期实例）+ 被挑散件 + 散件段（仅无排序档），分组连续编号；"当前"即"今日"                                              |
| **灵感**             | 侧边栏『灵感』页：从指定 Markdown 文件提取显示的段落，**可就地编辑**（只写正文段，frontmatter 不动，§6.2）                                                                            |
| **周期任务**         | 循环任务（每天/每周X），在设置页创建维护，到点自动出现，响不响单独设                                                                                                             |
| **定期挑**           | 定时（默认每天）从散件段随机挑一件附到今日清单尾部，不响提醒，仅可见；无排序档照旧（被挑中的那件从页底散件段移出，不重复显示）                                     |
| **今日会响**         | **会真的响**的今日条目：提醒锚点落在今天且**过了提醒门槛**的可推任务 + 今天到点且开了提醒的不可推任务（提醒口径；分组构成见 §6.1，门槛见 §7.0）                                  |
| **裕度（slack）**    | 距截止的真实可用工时 − 剩余工时，唯一压力表（见 architecture.md）                                                                                                                |
| **人类文档**         | `tasks.md`：**所有任务**都记在这一个文档里，`# 标题` 分类，一条任务一行（见 §4.3）。这里的**「分类」= `# 标题` 小节**，与任务类型（fixed/flex，记在内核属性的 `type`）不是一回事 |
| **内核属性文档**     | `.gtd/<任务id>.md`：内核算出来的属性（任务id/工作强度/优先级/时间裕度/剩余工作量）；人也能看能改（见 §4.3）                                                                      |
| **行指纹（digest）** | 人类文档里那一行的指纹，存在内核属性文档里；两条文档靠它对号（人不写、也不该改）                                                                                                 |
| **调度模式**         | **标准**（默认）/ **完整** / **无排序** 三档选一个，见 §7.0。三档是**一条逐级弱化的谱系**：算法替人做主的程度依次递减                                                  |
| **标准模式**         | 默认档。算法照常算先后（谁先做），但**不出声**；只有手动开了提醒的任务会响                                                                                                       |
| **完整模式**         | 算法判定该响的都响（顺序与标准完全一致）                                                                                                                                         |
| **无排序模式**       | **标准的再弱化版**：不再按算法排先后，今日清单**可推组**的顺序全靠手动拖（其余组的排法不变，见 §6.1）；**今天该看哪几件仍由算法挑**（锚点落在今天 / 今天到期），只额外把全部三无散件附在页底（⑥）——有截止的任务一件不多；被挑中的那件仍单列 ⑤ |
| **调度优先级**       | 算法排顺序用的分 = `risk × 优先级`（人看不到具体数字，只看顺序）                                                                                                                 |
| **手动序**           | 无排序档下人拖出来的顺序（`manual_order`，记在任务上、重启保留）；切到标准/完整后**保留但不生效**                                                                                |
| **风险（risk）**     | 由时间裕度算出的"误期风险"，∈(0,1]，裕度越小越接近 1；**非线性**（§7.1）                                                                                                         |
| **详情卡**           | 点条目展开的那张**只读**卡（§6.1）：备注全文 + 全部属性 + 调度派生量；改数据仍要走显式动作（底部按钮与长按菜单同源）                                                    |
| **挂起进行**         | 长期任务的"正在做"标记（`in_progress`）：点了『挂起进行』这件事就进今日页最顶的挂起组；多件可挂、组内可拖；保持到完成或主动取消，**不按天过期**                |
| **挂起组**           | 今日页最顶的那一组（⓿，逾期组之上，§6.1）：全部挂起进行中的任务，**无编号**；三档调度模式下都在最顶、都能拖                                                                  |
| **主线** | 侧边栏顶栏第二行那一条：当前正在推进的一件大事（写论文、装修……）。**同时只有一条**在跑，完成后归档；主线住在 `tasks/主线.md`，与任务池是两层——行为链上的步骤**不是任务**，不进调度、不占工时（§6.9） |
| **行为链** | 主线里的一串步骤，排成一条链：勾了就完成（记完成时刻，文字加横线），链上第一个没勾的是"下一步"。链上步骤与 `tasks.md` 无关（§6.9） |
| **圈（记录）** | 主线『记录』页（日历）上**手动拖选连续日期**圈出来的一段，圈里写文字——这就是主线 log 的本体；某天几点勾了哪一步是另一层（自动流水），点开那天看（§6.9） |

## 4. 任务模型（UI 视角）

### 4.1 类型二分

每条任务二选一：

|        | 不可推（固定时点）                                       | 可推（软任务）                                                                             |
| ------ | -------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| 例子   | 会议、约定、车票                                         | 写论文、回邮件                                                                             |
| 必填   | 日期时间（创建时选『定点』，经『自选…』弹日期+时间弹窗） | 截止日可选                                                                                 |
| 估工时 | 不需要                                                   | 需要（进调度）；**无截止的三无除外**——默认'长期'，不估工时                        |
| 提醒   | **只到点响一次**（**完整模式**，或该任务手动开了提醒时） | 有截止日→按裕度排序并按裕度调频（§7）；**标准模式下手动开了提醒才响**；无截止日→**不提醒** |
| 归属   | 今日清单（到点当天）、任务池计划段                       | 有截止：今日清单+任务池计划段；无截止：任务池散件段                                        |

### 4.2 字段（对现有 domain 的扩展需求）

沿用现有 Task（id/title/description/deadline/estimatedWork/remainingWork/importance/status/
snoozedUntil/metadata/created），需要扩展（详见 §10）：

- **类型**：fixed / flex（可推）。三无 = flex 且无截止。
- **截止日可空**：现在 deadline 是必填，散件没有截止——这是最大的领域变更。
- **工作强度的特殊值'长期'**：三无任务（可推 + 无截止 + 不提醒）创建时**默认长期**——'长期'不是分钟数，标了它就是**不估工时、不设优先级、不算裕度**，内核属性文档里只有一个任务 id（§4.3）。**长期不是新类型**（类型仍是 fixed/flex，§4.1）；有截止的可推任务仍必须给数字工时（缺省 30 分钟，进 slack 数学，§7.1）；'转正'= 补截止 + 把'长期'换成具体工时（§6.3）。
- **标签 `tags`**（正式字段）：人类文档行尾的 `##标签`，见 §4.3。
- **完成时刻 `completedAt`**（正式字段）：人类文档的 `完成 <日期,时间>`，
  与打勾同步落一次；`status=completed` 与它任一成立即视为完成。
- **提醒开关 `remind`**（走 metadata 缓冲带）：标准模式下给**单个任务**
  开提醒——开了它，这一件就按完整模式的规则出声。它**不改变顺序**，只改"出不出声"
  （§7.0）；完整模式下这个开关没有意义（本来就全响）。
- 散件与"被定期挑中"的状态、周期任务规则，见 §6.3 与 §10。

### 4.3 存储形态：双文档（正典见 architecture.md 附录 B）

**人写人看的归一个文档，内核算的归另一个文档。** 任务数据不是一个文件，是两个：

```text
tasks/
├── tasks.md           ← 人类文档：Obsidian 里看/改/共享的就是它
└── .gtd/<任务id>.md    ← 内核属性文档：应用自己写
```

**人类文档**（一个文档、`# 标题` 分类、一条任务一行）：

```markdown
# 工作

- [ ] 任务名 创建 2026-10-11,07:00 结束 2026-10-12,18:00 这是备注。 ##这是标签1 ##这是标签2
- [x] 交房租 创建 2026-10-01,09:00 完成 2026-10-01,09:30 ##生活
```

人写的六个属性：**任务名、创建日期、结束日期、完成日期、备注、标签**。
**更多的标签 = 更多的属性**：多打一个 `##标签` 就多一个维度，内核不解释它的语义
（唯一用法：新任务按第一个标签落到同名 `# 小节`）。

**内核属性文档**（应用根据已有属性算出来或补上的那部分）：

```markdown
---
id: task-001
digest: 7683b0bb       # 行指纹：把这一条和人类文档里那一行对上号
work_intensity: 120    # 工作强度（完成它需要的工时，工作分钟）
remaining_load: 0.75   # 剩余工作量（**分数**，乘以工作强度才是分钟）
priority: 3            # 优先级 1–5
time_slack: 210        # 时间裕度（工作分钟）
status: active
---
```

**长期任务**：三无的缺省态——这份文档**只剩 `id` 一行**：工作强度、优先级、时间裕度、剩余工作量全部没有（'长期'不单独落一行，**没有 `work_intensity` 就是长期**），完成态只认人类文档的 `[x]` / `完成 <时刻>`。

**分工与承诺**（写死，这是本次改造的全部要点）：

|                      | 人类文档 `tasks.md`                                | 内核属性文档 `.gtd/<id>.md`                            |
| -------------------- | -------------------------------------------------- | ------------------------------------------------------ |
| 谁写                 | 人（也由应用代笔**自己那一行**）                   | 应用                                                   |
| 应用改什么           | 只改它自己写的那一行：插入新任务、打勾、补完成时刻 | 全部字段随任务对象改写                                 |
| 应用绝不做什么       | **不重排行、不动别人的行、不动标题/空行/正文**     | 不动人的东西（这文件本来就只有内核字段）               |
| 人在 Obsidian 里能做 | 改名/改日期/改备注/加删行/换分类/加标签            | 也能改（字段级保真：注释、未知字段、内核备注原样保留） |
| 冲突时谁赢           | 人类那边赢（任务名/创建/结束/完成/备注/标签）      | 内核那边赢（工作强度/优先级/时间裕度/剩余工作量）      |

- **人只改人类文档也能用**：应用发现指纹变了就按上面的归属合并；
  新增的行会被内核接管并分配任务 id（**首次同步会提示一次**）；
  删掉的行不会连带删掉内核属性（文件即备份，删不删由人决定，只提示）；
- **人类文档里不出现任何内核字段**：id、工作强度、优先级、时间裕度、剩余工作量
  一个都不写进去——这是"共享/查看的文档要干净"这条要求的落地；
- **形态选择**：所有任务记在一个 `tasks.md` 里用标题分类
  （不是一任务一文件）；`log` 数据（领域事件流）**单独一个文档**，
  见 architecture.md §3.3。

> 与 Obsidian 相连的形式不变（§6.2）：**形式上只是单纯在 Obsidian 外
> 增加一个手机侧边栏的快捷入口**——不做 Obsidian 插件、不接管 vault、不代改笔记，
> 差异只在"多一个入口读同一批文件"。

## 5. 创建流程

### 5.1 完整对话框（侧边栏内弹出）

```text
┌──────────────────────────────┐
│  新建待办                     │
│  回车 = 跳到备注 · 直接点确认 = 三无   │  ← 对话框常驻提示文案
│  标题…            ← 首焦点    │
│  备注…（选填）                │
│                              │
│  类型 [三无 ✓] [有截止] [定点] │  ← 常驻按钮，默认『三无』
│                              │
│      [ ✱ 确认 ]              │  ← 纯点按，没有任何手势
└──────────────────────────────┘
```

1. 标题输入框首焦点；**回车 = 跳到备注**（对话框上有提示文案说明这一操作）。
2. 备注选填，可留空。
3. **类型档位常驻在对话框里**（不再藏在手势里），三个互斥按钮，**默认『三无』**：
   - **三无** = 可推 + 无截止 + 不提醒 → 入池散件段；**工作强度默认'长期'**（不估工时、不设优先级）；
   - **有截止** = 可推 + 有截止日 → 下方升起日期档位；
   - **定点** = 不可推（固定时点）→ 下方升起日期档位。
4. **日期档位**（选了类型才升起，没选就是三无）：
   - 『有截止』→ **【今天】【明天】【自选…】**：今天/明天取该日 **18:00**
     （当日工作窗末尾的常用截止点），要精确到分走『自选…』；
   - 『定点』→ 只给 **【自选…】** 一个：定点必须有确切时刻，"今天/明天"这种含糊档位没有意义；
   - 『自选…』= 弹日期 + 时间弹窗，选完**回到对话框**，所选日期显示在按钮上；
   - 点回『三无』→ **清掉已选日期、档位收起**（可逆，不留残留）。
5. **确认键是纯点按**（长按与滑动全部移除）：
   - 停在『三无』（默认态）→ 点确认**直接创建三无任务入池散件段**，中间不弹任何东西；
   - 选了『有截止』/『定点』但还没点日期档位 → 点确认**自动弹日期+时间弹窗**，选完即创建；
   - 已选日期 → 点确认按所选类型与日期创建（可推有截止 / 定点）。
6. **提醒开关不进新建对话框**（明确不做）：默认三无本来就不响；要响在创建后走『编辑』
   开『提醒我』（§7.0）。新建只问"是什么、什么时候"，不额外问"要不要吵你"。
7. **语音输入**：任何输入框都可以用输入法的语音键说话出字，App 不额外做语音功能。

> **为什么砍掉手势**：长按不松再滑档位这套动作**没有视觉 affordance**——不长按就永远
> 看不到档位在哪、也无从知道它能二分；而且它和系统返回手势、面板翻页手势抢同一块触摸区
> （边缘手势冲突已经为此吃过一次亏，见 §6.0）。档位摆成常驻按钮之后，"默认三无、点确认就走"这条最
> 短路反而比原来更快——它现在就是忙时最短的一条路（§5.2 的快捷堆三无已删）。

## 6. 悬浮侧边栏

### 6.0 把手与面板

- 贴屏把手 = **一段贴在边缘的半透明白条**（6dp 宽、72dp 高、白色 35% 不透明）：
  默认就是"看不见的存在"；竖向拖动可停靠左右边缘；**展开只认拖动**——朝屏内拖着
  走即拉开面板（跟手，见下条）；点按**什么都不做**（v1.21 修订，理由与代价见
  本节末那条）；
- **能起手的区域比白条大得多**（白条缩细后的补偿）：把手窗口本身是一块
  **宽 12dp（默认，设置项可调：细 8 / 标准 12 / 宽 20）× 高 200dp**的透明热区，
  白条贴在热区靠屏幕边缘那一侧、竖直居中——横竖都不必精确摁到白条上。200dp 是系统
  "每边最多兑现 200dp 返回手势排除"的配额上限，正好用满（再多系统不认），
  **竖向不开放调节**（缩了只是自损竖拖起手的容错）。代价写死在此：系统级热区是
  overlay 窗口，**它盖住的触摸归把手**，底下 App 的那一条收不到——这层做不到
  "点按透过、拖动照旧"（Android 按**手势**挑窗口：一次 DOWN…UP 要么整个归把手、
  要么整个归底下的 App，没有"识别成点击就退还"这回事），能调的只有面积，所以
  默认宽度从 28dp 收到 12dp 并交成设置项（§9 第 10 条；两处把手共用同一个值）。
  应用内那条压的是**我们自己的**设置页留白，且**点按不再被把手消费**（只有拖动
  回调的探测器不进命中链），实际不挡任何操作；
- **拖动用热区，长按只认白条**：竖拖移位、横拖拉开都可以在热区任意位置起手；
  长按（换边）的靶是**白条外扩 10dp**（26×92dp）——热区放大是为了好抓，
  不是为了"在别的 App 边缘随手一摁就弹出面板"；点按没有靶（它现在不触发任何事）；
- **把手位置可上锁**（新增）：设置页『固定把手位置』打开后把手**不再跟着竖向拖动**
  上下移动，钉在当前高度；长按换左右边仍然可用，横拖拉开不受影响（点按本就不是
  入口）。
  锁存 `settings.json` 的 `handle_locked` 并同步给原生服务（把手位置本身存在原生
  prefs 里）；**系统级与应用内两个把手一起锁**。要挪动就先解锁。
- **拖把手"拉开"侧边栏**（修订：由"横甩一下全开"改为跟手拖动）：朝屏幕中心拖动
  把手进入拉开态——**把手跟着手指横移**，侧边栏跟着手指**滑出**（露出多少跟手多少，
  遮罩随进度渐显）；松手时拖过约 72dp（或快速甩过 24dp）即补满到全展开，没拖够则
  滑回屏外、把手归位，等同没拖过。**点按不展开**。拉开只作用于**系统级悬浮把手**
  （应用外，跟手有中间态）；应用内壳的面板锚在把手上、没有"跟手滑出"的中间态，
  但判**同一套阈值**：朝屏内累计拖过 72dp 或快甩 ≥500 逻辑 px/s 才展开，慢慢蹭
  不算。拖动中的位置**不落盘**——把手仍是侧边栏唯一的持久锚点。拖到上限之后的
  第二档（拐离水平 = 快记）见 §6.8。
- **面板本体是系统级悬浮面板**：拖出后在**当前 App 上方就地展开**，
  不是把用户带进应用；面板与应用内壳**共用同一份 panels**（`ui/panels/side_panel.dart`）；
- **面板宽高都可拖**（由"仅宽度可拖"修订；**可固定，见下条**）：内侧边缘竖条把手
  横拖改宽、底边横条把手竖拖改高，都实时改、松手落盘（`settings.json` 的
  `panel_width` / `panel_height`；两个引擎共用同一份设置，悬浮窗与 App 内面板
  自动一致）；宽度夹在 [240, 屏宽−24]、高度夹在 [320, 可用高度]，没拖过 = 默认
  `min(0.80 × 屏宽, 360)` 宽 × `0.85 × 可用高度` 高——拖回去即「重置」，
  不另设重置入口；
- **面板尺寸可固定**（新增）：设置页『固定侧边栏大小』打开时把**此刻生效**的宽高
  冻成具体数字写进 `panel_width` / `panel_height`（之后换屏宽、横竖屏都不再按
  默认公式自适应），并**撤掉两条改尺寸的把手**——底边那条直接不渲染，内侧竖条
  就地换成**收起把手**：朝停靠侧横拖，面板整体跟手往屏外走（遮罩同步淡出），
  松手时**拖过面板宽的一半即缩回**，没过则回弹到原位。
  判定只看距离、不看速度——与"拉开"侧（72dp 或快甩）**刻意不对称**：推回去是
  "看完了"的确认动作，宁可慢一点，不能甩一下就把面板关了；跟手走完半程本身
  已经是明确意图。关掉开关只解锁，冻住的数值留着，还能接着拖。收起走的是
  点遮罩同一条路（悬浮窗侧由它去调原生 `collapse`），
  两个宿主口径一致；
- **面板位置以把手为锚**（修订：系统级悬浮窗也已打通，原先"仅应用内壳"）：面板
  垂直居中于把手——把手的中心即面板的垂直锚点，拖把手定了位、改高度时围绕把手
  伸缩（顶/底触边时夹紧）；悬浮窗侧的原生把手位置随 `state` 广播送来
  （`handle_center_y`，逻辑像素），字段缺失（老版本原生 / 桌面）= 贴顶展开；
- **四页结构，左右横滑翻页**：页面区横向拖动即翻页，与列表的纵向滚动是
  两个方向、互不抢手；圆点同时也是**跳转靶**——点哪个跳哪页（页序指示即可点的按钮）。
- **翻页从面板内部起手**：贴着屏幕最边缘那一小条是系统返回手势的地盘，
  从那儿横拖可能先被判成返回 / 收起面板；往面板里挪一点起手就是翻页。
- **不做纵向翻页**：竖滑手势和"浏览清单"抢的是同一个纵向手势区，代价就是翻不动。
- 页序（**全文唯一定义处**）：**灵感 → 今日清单 → 任务池 → 已完成**——今日清单
  退到第二页（v1.24）：默认落点已经可配（下条），"打开就是今日"不再是唯一正确姿势。
  文档与代码里的页面引用一律只认**页名**，不写"第 N 页"——页序改一次就要全库改数字的写法，
  上一轮已经吃过一次亏；
- **展开后默认落在哪一页**（设置项，§9 第 12 条）：拖动把手展开时停在设置里选的那一页，
  默认**今日清单**；**跟手拖出的那几帧就落在这一页**（起手页跟着设置走，不是松手补满后才跳过去）；点通知定位时按定位目标翻（今日件 / 池子件 / 已完成件），**定位优先**于这个
  默认值。落 `settings.json` 的 `default_page`，存的是页的稳定 id（`today` / `notes` / `pool` /
  `completed`）——与页序无关，将来再调顺序，旧设置仍指向同一页；
- 把手与面板互斥显示：展开时把手让位、收起后把手回来；应用自身在前台时两者都收起
  （此时走应用内把手 + 应用内面板）；
- **面板头两行**（v1.30 修订，原为"只有页名与一个图标"）：
  - 第一行：页名（左）+ 右上角『设置』（应用内壳不显示这个按钮——App 主体就是设置页）；
  - 第二行：**当前主线名**——小链条图标 + 名字 + 进度（`3/7`），**整行可点**，点开主线的
    覆盖页（§6.9）；没有主线时显示灰字『＋ 新建主线』。名字超长按省略号截断（窄面板
    240dp 上也有大半行），点开覆盖页看全名；
  - 为什么另起一行、不挤在页名右边：两个名字抢一行，240dp 上必有一个被截成三四个字。
    页名是"我在哪一页"（圆点兜底），主线名是"我在干什么"（没有替代品），后者值得这 20dp；
  - 『隐私』与『关闭』两个图标按钮撤掉（v1.24）：隐私那套改由快记承担（§6.5 / §6.8），
    关面板靠点遮罩、系统返回键，以及尺寸固定后那条收起把手——三条路都不需要一颗常驻
    图标，而窄面板上每少一颗图标，页名就多留一截；
- 进应用的唯一入口：面板头『设置』与实例菜单『编辑规则』。
- **点按不再是入口**（v1.21 修订，两处把手都删）：拖出侧边栏只剩**拖动**一条路
  （系统级 = 跟手拉过 72dp 或快甩；应用内 = 同阈值一次判定）。理由：贴边那一竖条
  是拇指的常驻落点，"点一下就弹面板"既误触，又让底下那一竖条变成"点了也不知道
  点给谁"的死区。**代价登记在此**：点按原先还是"ROM 不认手势排除区"时的兜底
  入口（决议 41），删掉后这类 ROM 上只剩拖动，若拖动也被判成返回则把手打不开——
  退路是 App 内的『侧边栏』按钮与抽屉。长按换边**保留**：500ms 的停顿不算误触，
  且它是换停靠边的唯一入口；
- **右下角『侧边栏』FAB 撤掉**（v1.31 修订）：~~设置页右下角那颗「▏▎ 侧边栏」按钮~~——
  它与把手拖出、抽屉打的是同一个动作，三条路留两条就够；而它是唯一一颗压在设置页
  **内容区**上的常驻按钮（每张卡片右侧都得少一块地方）。**上一段登记的"边角 ROM
  退路"现在只剩抽屉**（AppBar 菜单 → 抽屉本体，保留不动）：那条路在页面内，不占
  内容区。将来若还想加入口，加进抽屉里，别在右下角再摆一颗；

### 6.1 今日清单页

**分组连续编号**：

```text
⓿ 挂起组      挂起进行中的长期任务：无编号、置于本页最顶（逾期组之上）；
              组内可上下拖动调序；完成或『取消挂起』后消失，不按天过期
① 逾期组      过截止未完成：无编号、橙红徽标置顶，完成/改期前不消失
② 固定时点组  今天到点的不可推任务：按时间点升序，橙色时间徽标；组内不可拖（时间就是序）
③ 可推组      今天该动手（裕度算出的提醒**锚点**落在今天）或今天到期的可推任务：
              按调度优先级排序（裕度薄的在前，优先级作乘数）；可拖插队
              ——**无排序档下**：成员一个不变（仍按锚点准入），只是组内顺序 = 手动序
④ 例行组      周期任务当天实例：排在可推组之后；不占工时、默认不响（设了响的到点走提醒）
⑤ 被挑散件    定期挑/手动挑的那一件：无提醒、仅可见（标准/完整档在本页最后；
              **无排序档在 ⑥ 之上**，被挑中的那件从 ⑥ 移出，两处不重复）
⑥ 散件段      全部三无散件，**仅无排序档**：附在 ⑤ 之后、本页最底；不编号、弱化呈现；
              可拖，但只改整理序（`pool_order`，与池子散件段同一个动作）
```

- **标准 ↔ 完整：这一页一个条目都不变**：分组、编号、③ 可推组的**成员完全一致**——
  "锚点"是调度计算，"出不出声"是门槛，"谁排前面"是顺序；三者互不相干。变的只有
  会不会弹通知。**无排序档是唯一的例外**：③ 成员照样不变、顺序改手动，另外页底多出
  一段 ⑥ 散件段（任务池的散件段整体搬到这里），⑤ 仍在这段之上。
- **编号跨 ②③④ 组连续**（1、2、3…）；挂起组（⓿）、逾期组、被挑散件（⑤）与散件段（⑥）
  不编号（后两者弱化呈现）。无排序档下编号照旧连续，只是那一组的**编号 = 手动顺序**。
- **挂起进行**：长期任务（三无、默认'长期'）有一个专属动作
  **『挂起进行』**（长按菜单与详情卡底部按钮都有，和别的动作同一份条目表）——
  点了它这件事就**顶到今日页最顶**的**挂起组**（⓿，在逾期组之上、无编号），
  表示"现在正在做它"：
  - **只有长期任务能挂**：有截止的事归调度管（§7.1），池子菜单里这个动作只对长期任务
    出现；'转正'后已挂的**仍占着挂起位**，直到完成或『取消挂起』；
  - **可以同时挂多件**，组内**上下拖动调序**（和可推组同一个拖把手）——挂起时刻只是
    排序的载体，拖动即整段重写、重启保留；
  - **保持到完成或主动取消**，**不按天过期**（与插队同一性质：持久意图记在任务上，
    metadata `in_progress`）；完成后自动消失（完成命令顺手清掉这个标记）；
  - 挂起中的任务**从任务池两段隐藏**（和被挑散件同一规则：今日页顶置组是它唯一的
    显示位置），『取消挂起』后回池子原处；
  - **三档调度模式下挂起组都在最顶、都能拖**——它是持久意图不是算法排序，无排序档
    也不把它并进手动序（与逾期组同列"四处不跟着变"的地位）。
- **上下拖拽 = 手动插队，只对可推组生效**：手动顺序是**持久意图**（记在任务上）——
  被拖到前面的任务压在可推组最上面，**保持到它完成**；其余可推任务仍按调度排序。
  多件插队件之间**后插的在上**（栈式），插队件之间可再拖调整相对顺序。
  （**无排序档下**拖拽不再是"插队"而是"定序"：整组按你拖的结果排，算法不再插手。）
- **无排序档**：设置页『提醒与排序』切到**无排序**，算法就不再决定
  今日清单的先后：
  - ③ 可推组的**成员不变**——仍是"锚点落在今天 / 今天到期"的那几件。
    无排序是**今天这几件不排序**，不是把池子里所有有截止的任务都搬进今天；
  - 顺序完全按**手动序**；没排过序的任务按**创建先后**排在后面（新建的从末尾开始，
    拖一下就有序了）；
  - **③ 组内可随意拖**：拖动即整段重编号、**重启保留**，拖完算法不会再把你排回去；
  - **四处不跟着变**（沿用上面的组号）：**① 逾期组**仍置顶（那是状态，不是排序）；
    **② 固定时点组**仍按时刻升序、组内不可拖（时刻本身就是序）；**④ 例行组**仍按当天
    发生时刻升序（实例每天新生，没有手动序）；**⑤ 被挑散件**仍在页底、压在 ⑥ 之上。
    任务池的**计划段**也不变（仍按整理序，见 §6.3）——变的只有散件段，见下一条；
  - **页底多一段 ⑥ 散件段**：池子里的三无散件全部列在这里，池子那边不再显示散件段
    （这些件的位置从池子搬到了今日页，不会两处重复；被挑中的那件仍在 ⑤，从 ⑥ 移出）。
    这一段**不编号**，拖动只改**整理序**（写 `pool_order`，与池子散件段同一个动作）——
    不碰 ③ 的手动序（`manual_order`），两套序号各管各的；
  - **只关了排序**：裕度、提醒节奏（多久响一次）、逾期与"做不到"的提示、出不出声
    全部照旧——该响的照样响，只是**先后由你定**；
  - 切回**标准/完整**时手动序**原样保留、只是不生效**，不会丢、也不用重新拖一遍；
    散件段回到任务池，今日页底那一段随之消失。
- **点条目 = 详情卡**：列表行只放标题 + 备注第一行 + 状态徽标，点一下展开
  这张卡——备注**全文**、全部属性（类型 / 截止或时间 / 工时 / 优先级 / 创建 / 完成 / 标签；
  **长期任务**的工时显示'长期'、无优先级——它本来就没有这两项）
  与调度派生量（时间裕度 / 下一次该看它 / 会不会响 / 提醒间隔），底部一排动作按钮
  **与长按菜单同源**（同一份条目表，不另写一套）。例行实例的详情给的是它背后的
  **规则摘要 + 发生日**（实例是临时的）。**分工：点击看、长按做**——
  详情卡本身只读，改数据只有显式点按钮这一条路，不会"点一下就进编辑态"；
  七个组与池子两段都走这一份卡，动作按组上下文给（同上）。
- **长按条目弹菜单**：完成 / 推迟（档位见 §7.2）/ 编辑 / 删除（软删除，见下文『完成后』与 §10#11）；
  『编辑』复用创建对话框，**编辑态 = 属性展开表单**（显式控件直改类型/日期/工时/备注，
  改完调度自动重锚）；**新建态 = §5.1 的常驻档位按钮**——两处都是显式控件，创建流程里
  已无手势（§5.1）。
- **菜单按组上下文相关**：
  ⓿ 挂起组 = 完成 / **取消挂起** / 编辑 / 删除，**无『推迟』**（长期任务没有截止，无可推）；
  ② 固定时点组的『推迟』= snooze 本次提醒（事件时刻不变，走 D8 档位）；
  ④ 例行实例 = **完成**（今日完成，次日再生）/ **跳过今天**（不完成，今日不再显示）/
  **编辑规则**（跳设置页定位到该规则，不提供"编辑实例"——实例是临时的）/
  **删除规则**（需确认，从 routines.md 移除），**无『推迟』**（实例默认不响，改节奏去编辑规则）；
  ⑤ 被挑散件 = 完成 / **放回池子** / 编辑（展开表单，可顺手转正）/ 删除，
  **无『推迟』**（无日期可推，"放回池子"承担"今天不想做"的语义）。
- **完成后**：人类文档里那一行**原地**把 `- [ ]` 改成 `- [x]` 并补 `完成 <日期,时间>`
  （内核属性文档同步落 `status: completed` 与 `completed_at`；**长期任务没有内核属性可同步**——它的内核文档只有 id，完成只落在人类文档那一行），**这一行与其余内容
  原样保留**（Obsidian 里可翻历史），各清单立即消失——可在『已完成』页找回并恢复
  （§6.7）；灵感文件与此无关，**不动**（它在自己的页里改，§6.2）。
  **删除** = 内核属性文件移入 `.gtd/.trash/` + 那一行用 `%%…%%` 注释掉（可捞回，见 §4.3）。
- 每页右下角都有两个按钮：**添加待办**（「+」，进 §5.1 对话框）与**日历**（「日历」，§6.4）。

### 6.2 灵感页

- 数据源：用户在 Obsidian 维护的一篇 Markdown（文件名随意，路径设置里可配，§9 第 5 条）；
  App 与 Obsidian **读写同一份文件**——连接形式仍然只是"多一个入口"，
  不做插件、不接管 vault。
- **提取显示规则**（已确认，v1.29 未改）：
  - 显示 **frontmatter 闭合 `---` 之后、到下一个 `---` 之间**的那段正文（不是 YAML 本身）；
  - 行内出现 `[[` 的**整行屏蔽不显示**（过滤 wiki 链接行）；
  - 正文里没有第二个 `---` → 取到**文件末尾**；
  - 空状态：文件未配置/找不到 → "未找到灵感，去设置选择文件"；整段被 `[[` 过滤光 → "这一段没有可显示的内容"。
- **编辑（v1.29 新口径）**：App **可就地改正文段**，frontmatter 一个字符都不动。
  - 入口：页头的铅笔图标（页名就叫"灵感"，不再带"（只读）"后缀）；点了进**编辑态**——
    正文换成占满页面的多行输入框，页头按钮换成『保存』『取消』，其余不变；
  - **编辑态显示正文段完整原文**：只读态被 `[[` 屏蔽的行在这里可见可改。
    这是有意的——让"看不见的行"在保存时被悄悄抹掉，比多显示几行糟糕得多；
  - **保存 = 用编辑内容替换正文段**：frontmatter、正文段前后的全部内容（含分隔用的
    `---` 与其后段落）逐行原样保留；文件原有的换行风格（CRLF/LF）与"是否以换行结尾"
    也照旧，不因为保存把整个文件重排一遍；
  - 编辑靠空行分段，不解析 Markdown；保存后回到只读态并按新内容重新过滤显示；
  - **可编辑的前提**：路径已配置且文件存在。未配置/找不到只给空态提示，不给编辑
    （App 不替人创建文件）；frontmatter 未闭合（只有开头的 `---` 没有闭合）属于结构
    坏掉的文件，同样不给编辑——那时"正文段"的边界本身是不确定的；
  - 局限（登记在此，不另做）：写盘是"读—改—写"，若 Obsidian 此刻也在改同一个文件，
    以 App 这次保存为准（Obsidian 自己的历史还在）；App 不做锁、不做合并。

### 6.3 任务池页

- **点条目 = 详情卡**：与今日清单同一张卡（§6.1），动作给的是池子这一套
  （挑到今日 / 完成 / 编辑 / 删除）；计划段与散件段同款。
- **条目操作（长按菜单，散件段与计划段同款）**：**挑到今日**（不转正，附今日尾部，
  当日手动挑标记生效，自动挑让位；**无排序档下这个动作在今日页 ⑥ 的菜单里**，
  池子那边没有散件段了）/ **转正**（走 §5.1 对话框补属性，进调度）/
  完成 / 编辑 / 删除（软删除）。**长期任务（三无散件）还多一个
  『挂起进行』**：顶到今日页最顶的挂起组，保持到完成或主动取消；
  挂起中的件在池子两段都不再出现（它的显示位置只在今日页顶置组）。
- **上下拖拽**：仅为整理位置方便看（无调度含义）；**顺序持久化**——显示序记在任务
  metadata，重启保留；新建任务进对应组末尾。
- **任务池不受调度模式影响**，**唯一例外是散件段**：无排序档下那些件已经整段列在
  今日页底部（§6.1 ⑥），池子这边不再显示——它们的动作（挑到今日 / 挂起 / 编辑 / 删除）
  跟着条目走，在 ⑥ 的菜单里。
  池子其余部分在三档下都按**整理序**——手动整理过的在前（`pool_order`），
  其余计划段按截止升序、散件段按创建时间，周期条目按发生日期升序插入对应位置。
  这里的拖动与今日 ③ 是两套序号（`pool_order` vs `manual_order`），互不干扰。
- **空状态**："池干水清"；无排序档下若计划段也空、只有搬去今日页的散件，
  显示"散件都在今日清单底部"。
- **一条横线分两段**：
  - **横线前（计划段）**：明天、后天……未来要做的任务（有截止的可推 + 未来的不可推）；
    **周期任务按下一次发生日期升序插入对应位置**（设置里提供"是否显示"开关）；
  - **横线后（散件段）**：全部三无散件；**无排序档没有这一段**（整段在今日页底部）。
- **散件转正**两条路：
  1. **闲时手动**：长按散件选『转正』→ 走 §5.1 对话框补属性（分类/截止/工时，即把'长期'换成具体工时）→ 进调度；
  2. **定期挑**（自动）：间隔可设置，**默认一天**；**随机**挑一件附到今日清单尾部，不响提醒只可见。
     细则：每天**独立随机**；昨天没做完的件**回池子重新参与随机**（不优先续挑）；
     你**手动挑过**的日子，当日自动挑就让位——今日尾部**最多一件散件**。
     无排序档照旧挑：挑中的那件从页底 ⑥ 移到 ⑤（不重复），没挑中的仍在 ⑥。

### 6.4 日历弹窗

- 入口 = 面板右下角的小按钮（原『～』堆三无的位置，v1.22 起），四个页面都在；
  点开弹出**月历**，有任务的日子打点。
- 点某天 → **当天列表从弹窗底部下滑展开**（同一弹窗内联动，**不再叠一层弹窗**）。
- 当天列表里可直接**改某任务日期**（点条目即改期），改完调度自动重锚（事件驱动，
  符合防 Zeno 规则）。**这里是详情卡的例外**：日历不属于侧边栏这四页，点条目仍是改期，
  不弹详情卡。
- **改期的适用范围**：可推/不可推任务可改；**例行实例只读**（在其发生日打点，
  点开提供『编辑规则』跳转）；散件与被挑散件无日期，不进日历。
- **与主线『记录』页不是同一个日历**：这里是**全局任务日历**（看哪天到期、就地改期）；
  主线覆盖页里那个日历画的是**主线的行为链流水与圈**（§6.9），两处互不相干——任务日期
  不画进主线记录页，主线的圈也不进这个弹窗。

### 6.6 空状态与首次引导

- **首次拖出侧边栏**：一次性四步气泡引导——拖出展开 / 左右横滑翻页 /
  右下角两个钮（「+」新建、「日历」看月历）/ 拖到顶再拐个弯 = 快记（§6.8，文案注明

  设置里可重看；
- 今日清单空："今天清单是空的"，附快捷按钮『从池子随机挑一件』（等价手动挑）；
- 任务池空："池干水清"；灵感空态见 §6.2；已完成空："还没有完成的事"。

### 6.7 已完成页

- **定位**：已完成任务的总览（任务池右边一页）。完成即从今日清单与任务池消失，
  但那一行原样留在人类文档里（§6.1『完成后』）——这一页就是它在 App 里的落脚处，
  不用去 Obsidian 翻。**与调度模式三档无关**：存档不参与排序，三档下都是同一份列表。
- **分组**：按完成日期分三组——**今天 / 昨天 / 更早**，组内按完成时刻**倒序**
  （最新完成的在上）。人在 Obsidian 里手打了勾、没写完成时刻的（`completedAt` 为空），
  归入『更早』组末尾、按创建时间倒序——完成日期属人写的那半边（§4.3），内核不猜。
- **条目**：与任务池同款的任务行，弱化呈现、无编号、**不可拖**（历史没有顺序意图）；
  点条目 = 同一张只读详情卡（§6.1），『完成 <时刻>』属性行照常显示，例行实例照常给规则摘要。
- **动作（长按菜单与详情卡底部按钮同源，就两个）**：**恢复未完成** / 删除（软删除，带撤销 toast）。
  - **恢复未完成** = 撤销这一次完成：人类文档那行回 `- [ ]` 并去掉『完成 <时刻>』，
    任务回到未完成状态（有截止的回今日清单/任务池、三无的回散件段；剩余工作量回满，
    长期任务没有工时可回）。这是**误触完成的兜底**——完成是全 App 唯一原本没有撤销入口的
    操作（删除都有 undo toast）。
  - **例行实例不给恢复**：恢复一个往日实例，它会从所有清单里消失（实例是临时的，
    明天的实例才是真的）——要续上节奏去设置页『编辑规则』。
- **空状态**："还没有完成的事"。

### 6.8 拖出头：快记（v1.23）

**一条手势的第二档**：把手朝屏内横拖到 **0.45 × 屏宽**（原先的横移上限，现在是
**分岔点**）之后才判方向——

- 继续**近似水平**（竖向偏移不足 24dp，或不足"过线之后横向还在推进的量"的
  0.8 倍）→ 解除上限，把手一路横移到**面板宽**为止、面板全开，仍是"要面板"那条路；
- 明显**拐离水平**（竖向偏移 ≥ 24dp 且大于上述横向推进量的 0.8 倍）→ 进**快记态**。
  横向顶死之后（0.45 或面板宽）推进量归零，拐 24dp 即触发。

0.45 之前的正常拉开段不参与方向判定（那里只有"拖多深"一个问题）。拐弯一旦判定成立
就在本次手势里锁死，不随手指抖动回摆；但**进快记后把位移退回 0.45 × 屏宽以内即取消**，
方块缩回白条、面板恢复跟手，所以拖错了有退路。

**快记态**：把手窗口就地变形为 **52dp 圆角方块**（白底、细描边、中心一个加号），
中心落在**指尖上方 28dp**（否则被手指盖住），**二维跟手指移动**，进入时轻振一次。
方块不带任何任务文字——旁边人看到的就是一块空白小方块。窗口本身留 120dp 的透明
余量（方块居中），保证指尖始终落在窗口内、不因缩窗而中断拖动。

**面板同时退场**：进快记态时面板**不摘窗口**，只把展开进度在 160ms 内淡出到 0；
回拖取消时原地恢复跟手，省掉"摘了再挂"的闪烁。真正摘窗口推迟到松手之后。

**松手 → 屏幕中央的输入条**：原生把松手坐标交给 Dart，Dart 在同一坐标画同尺寸方块接管
（原生窗口当场隐藏），方块沿缓出曲线滑到**屏幕正中**（约 200ms）、再横向展开成一条胶囊
输入条（宽 `min(360, 屏宽 − 48)`，总时长 360ms），动画放完才挂输入框、请求焦点弹键盘。
**没有遮罩**，底下的 App 照常可见但不可点（点外部即收起）——这正是公共场合的用法：
清单一次都不露。

**输入与提交**：回车提交 = **三无任务**入池散件段（与创建对话框的确认同一条命令：无截止、
不提醒、工作强度默认'长期'），右侧闪一个静默对勾后**留着继续记**；点输入条外部、
按返回 = 丢弃草稿收起；空文本提交什么都不做。**不做**日期 / 优先级语法解析——
快记只管记下来，整理留给闲时。

**只在系统级悬浮把手**：应用内壳的把手没有跟手中间态（一次判定就展开），也没有
"公共场合防瞟"的场景，不做；桌面同理。

**可发现性**：进首次引导第 4 步（§6.6）。这仍是"拖到那一步才知道"的手势，只有走过
一次的人会再用；不接受这个代价的唯一替代是再加一个常驻按钮，那正是 §5.2 撤掉过的
东西。

**降级**：第二个引擎起不来时不进快记态，手势保持原样（拖够就展开面板）。输入条住
面板窗口，个别 ROM 上 overlay 窗口不弹 IME 时它仍可点聚焦，不另做原生输入框兜底。

### 6.9 主线（顶栏名字 → 覆盖页，v1.30）

**一句话**：顶栏第二行永远显示"现在在推的那一件大事"；点开是一块盖住整块面板的页面——
第一页是行为链，向左横滑是记录（日历），顶栏那个名字是唯一入口。

- **同时只有一条主线**在跑。完成后归档（`tasks/主线.md` 里状态改"已完成"），顶栏第二行
  回到『＋ 新建主线』——不存在"切到另一条在跑的"这种操作，也没有并行几条的列表；
- **覆盖页盖住整块面板**（含面板头与页序圆点），自带标题行：
  `[返回] 主线名 … [1/2] [✎] [完成主线]`。退出两条路：左上『返回』与系统返回键
  （返回键先收编辑态，再退覆盖页）。退出即回原来那四页，**原来的页位置不变**；
- **两页**：第 1 页**行为链**、第 2 页**记录**（日历）。翻页有两条路：
  1. **点页头那颗 `1/2`**（点一下切到另一页）；
  2. **记录页的下半区向右滑**（当天详情 / 空提示那半边）就回行为链——**横滑按区域
     分工**：日历格子里是"按住拖选日期圈一段"，下面那半边没有日历可圈，就让给翻页。
     第 1 页仍可向左横滑去记录页。
  横滑/翻页只发生在覆盖页内部，不动面板本身的页序；
- **行为链的画法**：纵向一条链——节点 + 连线，从上往下读：
  - 完成的步骤：节点**实心**、文字加**横线**（删除线）、连线转实色；
  - 未完成的步骤：节点空心、连线虚线；
  - **第一个没勾的**是"下一步"：节点加一圈强调色描边；
  - 点**节点** = 勾选 / 取消勾选（记/清完成时刻）；点**文字** = 打开这一步的编辑（改名 /
    写备注 / 看完成时刻）——勾选是高频动作，所以给它最小的靶；改名是低频，放在文字上；
  - 全部勾完 → 标题行出现『完成主线』。**不自动归档**：勾完只是"可归档"，要显式点一下；
- **记录 = 日历上手动圈的段**（不是按天写流水）：
  - 月历一屏（周一开头，今天淡圈），每天格子里只放日期数字；**有内容的日子**（勾过步骤
    或圈覆盖）在数字下留一个小点；
  - **按住某天拖到另一天** → 拖过的连续日期高亮成一条 → 松手弹输入框写文字 → 这一段被
    **一个圆角圈**框住，文字就写在圈里（窄了省略，点圈看全文/改文字/删除）。一次只圈
    **连续**日期；跨周会自动按周分段画（像多日日程条），同一段里不必每天都有内容；
  - **点某一天**：日历下方列这一天的两样东西——① 当天勾掉的步骤（时刻 + 步骤名 +
    写在步骤上的备注，自动流水）② 覆盖这一天的圈。**圈是人写的那一半，流水是勾选自动
    记的那一半，互不替代**；
  - 圈可以重叠（同一天两个圈），日历上按行叠放，最多显示三条，多出的折成 `+N`；
- **编辑**（标题行 ✎）：同一页切成编辑态——主线名变输入框；每个步骤一行输入框，右侧
  删除按钮、长按拖动把手（组内可拖，改的是行为链顺序）；末尾『＋ 添加一步』；底部
  『保存』『取消』。保存一次落盘（改名 + 整条链一次写），取消原样退回。**圈不进编辑态**：
  圈的文字在"点圈"的对话框里改，删除也在那里；
- **归档与查看**：归档只改状态与归档时刻，不删任何数据。归档后主线只读——第 1 页底部
  永远有一行『已完成的主线 · N 条』，点开是归档列表（标题 + 完成日期 + 完成时几件/共几件），
  选一条进入**只读**查看（标题行换成『已归档』徽标 + 『返回当前』），行为链、圈、完成时刻
  都还在；
- **存储**：`tasks/主线.md`，一个文件装全部主线（附录 B.6）。应用维护整份文件；Obsidian
  可读可改，读进来的改动生效，保存时正文按模型重写（局限登记在 B.6）；
- **与任务的关系**：行为链步骤是主线自己的条目，**不绑任务、不进任务池与今日清单、不占
  工时、不参与调度、不响提醒**。想让某一步也进调度，就另建一条任务——这是有意的边界，
  不另做双向同步（写在 §13）。

### 6.10 桌面（Windows）布局：同一套面板，换个摆法（v1.32）

**一句话**：桌面窗口一直开着，"展开 / 收起面板"这件事本身不存在——侧边栏改成
**左侧常驻一栏**，右边一整栏是设置页主体。四页、页序圆点、面板头第二行的主线、
覆盖页、右下角双钮与 §6.0–§6.9 完全一致，因为它们用的就是同一个 `SidePanel`。

- **两栏**：左栏 = 侧边栏本体（宽 300–420dp；窗口窄时按 32% 缩，下限 240dp 与手机
  面板同档），右栏 = 设置页（§9 全部内容）。左栏垫 8dp 留白浮起来，与右栏之间一条
  细分隔线——两栏各是一块面，不像手机那样整屏压着内容。
- **桌面上没有的东西**（不是漏做，是移动端那套"进出"机制在常驻窗口里没有对应物）：
  贴屏把手、遮罩、滑入 / 滑出动画、尺寸固定后的跟手收起、抽屉兜底、面板头的
  『设置』图标（设置页就在右边）、首次拖出引导、返回键那两步收。
- **翻页**：页序圆点可点（与手机一致），触控板横扫也能翻；**鼠标按住横拖不翻页**
  ——滚动视图在桌面上不接鼠标拖动，这是 Flutter 的默认，局限登记在
  architecture.md §12。
- **主线**：点面板头第二行进覆盖页，覆盖页盖住**左栏**（不是整个窗口），右栏的
  设置页照常可见；退出走覆盖页左上『返回』，桌面没有系统返回键这一步。
- **提醒**：到点弹应用内对话框（`ReminderListener`，与手机前台兜底同一个组件）。
  桌面没有系统通知 / 全屏闹钟渠道，应用不在前台就看不到——局限见 architecture.md
  §12「提醒链路的跨天自续」。
- **窄窗口（< 720dp）**：退回单栏——只摆面板，设置页用标题栏那颗『设置』按钮
  push 成独立页面（桌面壳唯一保留的"独立设置页"形态）。
- **窗口级 chrome** 只有标题栏一行：应用名 + 一颗『重新调度』。新建待办与日历仍在
  面板右下角双钮上（§6.1），标题栏不重复摆。

## 7. 提醒系统

### 7.0 调度模式三档（**默认标准**）

**三档是一组三选一**（设置页『提醒与排序』节），按"算法替人做主的程度"从强到弱排：

|                                             | **完整**                | **标准（默认）**                                         | **无排序**                                 |
| ------------------------------------------- | ----------------------- | -------------------------------------------------------- | ------------------------------------------ |
| 算法排先后（谁先做）                        | 是                      | 是                                                       | **否**——今日可推组由人拖（`manual_order`） |
| 自动提醒                                    | 凡算法判定该响的都响    | **不出声**（默认安静）                                   | 与标准一致：不出声                         |
| 单个任务                                    | 不用开（本来就全响）    | 可手动开提醒（编辑表单『提醒我』，落 metadata `remind`） | 同标准                                     |
| 到点类提醒（不可推到点 / 设了响的周期实例） | 照原方案响              | 默认不响，开了才响                                       | 同标准                                     |
| 今日清单有哪几件                            | 锚点落在今天 / 今天到期 | 同左                                                     | **有截止的同左**；另加页底 ⑥ 散件段（全部三无，仅这一档） |
| 任务池的顺序                                | 整理序（`pool_order`）  | 同左                                                     | 同左；**散件段不显示**（那些件在今日页 ⑥）                 |

一句话记：**完整 = 排 + 响；标准 = 排 + 不响；无排序 = 不排 + 不响**。
三档互不重叠，也不存在"组合"——切一档就够了，不会出现"排但不响且不按锚点"这种第四态。

- **无排序是标准的再弱化版**：它把标准档里"算法排先后"这一层也去掉，其余全部照抄标准
  ——含默认不出声、含"有截止的任务仍按锚点准入"。唯一的加法是页底 ⑥ 散件段：
  标准/完整档看散件要切到任务池，无排序档把那段直接铺在今日页最底下（§6.1）。
  想让它出声，仍然去编辑表单给单件开『提醒我』。

- **为什么默认标准**：提醒是打扰。默认"只排队、不出声"，需要被推着走的事再单独开——
  一次设置或一次点击的代价，换默认安静（代价记在 architecture.md §12）。

- **门槛与送达策略是两件事，串联生效**：门槛决定"**要不要**出声"（这一件
  `reminds = false`、结果里的下一站 `nextReminderAt = null` 就是不出声），通知时间段决定
  "**什么时候**允许出声"（段外顺延，§7.1）。所以标准模式下连"顺延"都不会发生——
  根本没有那一站。（**锚点照算**：提醒锚点是调度计算，今日清单准入用它，不受门槛影响。）

- **切换立即生效**：顺序与下一站闹钟都重算（提醒是计算结果，无迁移、无历史改写）。

### 7.1 算法与默认策略（时间裕度优先 + AI 调参）

有截止日的可推任务，一律换算成"工作分钟"（跳过夜间/午休/周末）：

```text
available = workMinutesBetween(now, deadline)      # 距截止的真实可用工时
remaining = 工作强度 × 剩余工作量                    # 剩余工时（分钟）
slack     = available − remaining                   # 裕度，唯一的压力表
risk      = slack ≤ 0 ? 1 : exp(−(slack/τ)^γ)      # 【非线性】误期风险 ∈ (0,1]
priority  = risk × importance                       # 调度优先级 = 排序键（优先级缺省 3）
interval  = clamp(0.5 × slack, 30min, 480min)       # 提醒节奏（锚点用；出不出声看门槛）
          = 480min × (1 + log₂(0.5 × slack / 480min))  # 裕度超过一个工作日之后按对数放缓
nextReminderAt = 沿用上次锚点（任务自身没变时）否则 addWorkMinutes(now, interval)
默认：τ = 480（1 个工作日）、γ = 1
```

- **排序四档**：不可行 → 普通（调度优先级降序）→ 逾期 → 已推迟。不可行是
  "已经注定误期"，单独一档等用户裁决（改截止 / 砍范围 / 加班）；
- **裕度优先**：裕度越薄风险越高、越排在前面；**优先级（1–5，缺省 3）是乘数**，
  让重要的事整体前移。乘数最多 5 倍，裕度差出一个 τ（480 分钟）以上它就盖不动了。
- **为什么非线性**：线性要让裕度"到哪算 0"凭空定一个量纲，还会算出负风险；
  指数族只要一个尺度 τ，且恒在 (0,1]——**裕度还宽时催得少，裕度一薄就陡然变急**；
  γ>1 = 裕度充足时压得更低（更平）、薄了迅速冲到 1（更陡）。
- **`priority` 这个名字只属于算法内部**：人定的是**优先级**（内核属性文档的
  `priority` 键 = `Task.importance`，缺省 3），算出来的是**调度优先级**（不落盘、不进人类文档）；
  界面照旧展示裕度这类派生量，但不显示这个排序分——**顺序本身就是表达**。
- **全局通知时间段（多段式）**：可推任务的提醒只落在时间段内，时间段外静默
  （这是**门槛之后**的一道，§7.0）。设置里支持**多段编辑**
  （如 9:00–12:00、14:00–18:00、19:00–21:00，方便抠掉午睡/饭点）；默认一段 **9:00–21:00**；
- **AI 动态调整 = L2 软控制**：AI 只允许在 Scheduler `params` 声明范围内微调
  （α、最小间隔、间隔拐点、风险尺度 τ 与陡度 γ），一切变更走 origin=ai 的领域事件，**可审计、可拒绝**——
  回滚不承诺（架构合同 §6：逆命令机制未设计，落地前 UI 只提供"拒绝"）；
  没配 key / AI 挂掉 → 默认策略照常。
- **不可推**：只到点响一次，不提前、不进调度；**标准模式下要先给这一件开提醒**
  才会响（§7.0）。（实现：`TaskService.nextPointReminder()` + ReminderDispatcher
  双源单闹钟；`point_fired` 保证只响一次，改期重新生效；错过超过 30 分钟不再补响。）
- **散件 / 可推无截止**：永不提醒（三档都一样）。
- **三无的默认工作强度 = '长期'**：'长期'不是分钟数，是"长期存在、估不出来"的标记——标长期的任务不估工时、不设优先级，也不进上面的公式（它们本来就没有截止；内核属性文档里只有一个任务 id）。
- **周期任务**：响不响单独设置（**标准模式下"规则设了响"就等价于给这个实例手动开了提醒**）；
  **不占工时**（不进裕度容量计算）；
  当天实例**跨日生成**（不存在"应用没开还会有零点任务"这回事）；
  完成即消，次日再生。（实现：实例在启动/跨日/回前台时**幂等**生成
  ——没有"每天零点"的后台闹钟，应用下一次活着的时候补齐，落成任务文件。）

### 7.2 提醒呈现与推迟

> **前提**：本节讲的是"响了之后长什么样"。**标准模式下大多数任务走不到这里**
> ——要响，先给那一件开提醒，或把模式切成完整（§7.0）。

- 到点弹**系统通知**，通知上直接给快捷按钮：**『完成』『推迟 1 小时』**；
- 点通知**正文** → 展开**侧边栏**并定位到该任务。**定位边界**：目标在今日清单 → 定位高亮；
  已滚进任务池 → 跳池子定位高亮；已完成 → 跳『已完成』页定位高亮（§6.7）；已删除 → toast"已删除，可在回收找回"。
- **推迟档位**：通知快捷固定 1 小时；长按菜单『推迟』给档位：**30 分钟 / 1 小时 / 3 小时 /
  明早 9 点 / 自选时间**。推算结果落在静默/休息段 → **顺延到下一时段开头**（不强制响，
  夜间静默是硬规则；**不可推的到点闹钟不受静默限制**）；跨休息段的推迟按 architecture.md **D8**
  给显式选项"到下个工作窗"（≤120 分钟按自然时间）。**绝对档位（明早 9 点 / 自选）原样响**
  ——静默段顺延只作用于相对档位推算出的时刻。
- **可选闹钟模式**（**只对时点性提醒生效**：不可推的到点提醒 + 设了响的周期任务；
  可推任务的 Slack 例行软提醒永远普通通知）：开启后升级为**全屏提醒界面 + 持续响铃**，
  必须手动点『完成 / 推迟 / 知道了』才停；走系统闹钟渠道，媒体静音压不住
  （实现上对应 full-screen intent，需锁屏显示/上层显示权限，走 PermissionPort）。
  （实现：原生渠道 `gtd_alarm`（IMPORTANCE_HIGH + 闹钟音 + 震动）+
  `setFullScreenIntent`；权限缺失时退化为普通通知。
  应用被杀时由系统闹钟的接收器照"交付草案"弹出通知，按钮点击回传应用；
  应用当时没开则在下次启动补做。）

## 8. 视觉规范

- **橙色系**：橙做**强调色 + 中性底**——底色纸白/深灰双模式；
  橙只给关键元素：编号、确认键、"今日会响"徽标、裕度告急、逾期标记等。
- 主题可在设置里切换：明暗三选一 + 4 套强调色预设（见 §9 第 7 条）。
- 侧边栏窄幅、低密度舒适行高；编号大而醒目（橙色），标题为主文案，备注弱化。
- **明暗三选一**：**跟随系统（默认）/ 浅色 / 深黑**，落 `settings.json` 的
  `theme_mode`；两个引擎（应用内壳 + 系统级悬浮面板）读同一份设置，切换
  立即生效、不迁移任何任务数据。深色底 = **暖深褐黑**（`#1E1B18` 底 /
  `#2A2622` 卡）而不是纯黑——配橙种子保住"纸"的暖底基因。
- **状态语义色不随强调色预设变化**（逾期橙红、时间徽标橙是状态不是装饰）；
  暗色模式下**逾期橙红取提亮变体**（浅底约 4:1 → 暗底约 5.5:1），时间徽标橙
  暗底已达标不动。"不随预设变"与"随明暗提亮"是两件事：前者防装饰性漂移，
  后者保可读性。

  为限；降级结果由申请失败时的 toast 说，不预写在每一行下面。**设计文档的

## 9. 设置页清单（暂定 App 唯一页面）

【**除第 3 条的 AI L2 外**全部已落地；桌面端与安卓用**同一份设置页**——安卓里它是
App 主体，桌面上它是侧边栏右边那一栏（§6.10）】

**只对某种壳有意义的项**（v1.33）：同一份设置页里有一组项只属于"贴屏悬浮壳"——
权限引导（悬浮窗 / 精确闹钟 / 电池白名单 / 锁屏 / 文件访问）、系统级贴屏把手、
把手位置上锁、把手热区宽度、固定侧边栏大小（含跟手收起）、重看首次拖出引导、
闹钟模式（全屏渠道）。判据是"**这套壳有没有那个东西**"，不是"什么系统"：由组装点
注入一张 `ShellCapabilities` 能力表（`lib/application/shell_capabilities.dart`），
设置页只读表、**不问平台**（arch §5.1 的口诀）。桌面上这几项**整行不渲染**——
不是灰掉：灰掉会让人以为"再找找就找到了"，而桌面上它根本不存在。于是桌面的
『侧边栏』区只剩"展开后默认页面"，副标题也跟着改成"重新打开窗口时落在这一页"。
下面各条里标〔悬浮壳〕的即此列。

1. 〔悬浮壳〕首次引导 + 权限申请（悬浮窗/通知/精确闹钟/电池白名单/文件访问）——逐项申请、
   逐项显示当前状态，被拒时页面内 toast 说明降级；任务目录另支持手输路径兜底；
2. 周期任务管理（增删改、频率、响不响、启用开关）——读写任务目录下独立的 `routines.md`，
   Obsidian 可直接看改；下方另有『周期任务在任务池显示』开关（第 6 条）；
3. 提醒：通知时间段（**多段式**编辑，默认 9:00–21:00）、〔悬浮壳〕闹钟模式开关、AI 接入与参数范围
   （L2 展示与拒绝；**本页唯一未落地项**）；**提醒/排序的模式切换见第 9 条**；
4. 定期挑：开关、间隔（默认 1 天）；
5. **灵感**文件路径（**系统选择器挑文件 + 手输路径兜底**，与任务目录同款弹层；
   App 就地编辑这篇 Markdown 的正文段，§6.2）；
6. 周期任务在任务池的显示开关；
7. 主题：**明暗三选一**（跟随系统（默认）/ 浅色 / 深黑）+ 4 套强调色预设
   （橙（默认）/ 墨蓝 / 苔绿 / 梅紫；只换强调色种子）。明暗落
   `settings.json` 的 `theme_mode`、预设落 `theme_preset`；逾期橙红等
   状态语义色不随预设变（暗色下的提亮变体见 §8）；
8. 附加：〔悬浮壳〕系统级贴屏把手开关（需悬浮窗权限，被拒自动退化为 App 内抽屉）、
   〔悬浮壳〕重看首次引导、回收站清空。
9. **调度模式三档**：**完整 / 标准（默认）/ 无排序**一组三选一，
   三行一行说明用途（见 §7.0 那张表）；模式落 `settings.json` 的 `schedule_mode`
   （仍读得懂旧的 `reminder_mode`），切换立即生效、不迁移任何数据。
   ~~无排序那一档的按钮旁写明："今天该看哪几件仍由算法挑，只有先后由你拖"——
   免得被理解成"所有任务都堆到今天"。~~
   **修订（v1.19）**：界面上三档各只留半句（"排先后，该响的都响" /
   "排先后，默认不响" / "顺序全靠手动拖"）——细化解释不挤窄屏，切一下就
   体会得到；   "今天该看哪几件仍由算法挑"那层澄清留在 §7.0 的三档表里，
   不属于界面文案。
10. 〔悬浮壳〕**把手热区宽度三档**：**细 8 / 标准（默认）12 / 宽 20**（单位 dp）一组三选一，
    落 `settings.json` 的 `handle_hot_width`，两处把手（系统级悬浮 + 应用内）
    共用同一个值、改完立即生效；原生侧另在 prefs 里存一份镜像（服务可能比 Dart
    先起来）。选的就是"好抓"与"不挡路"的折中点——热区盖住的触摸归把手（§6.0），
    越宽越好抓、底下那一竖条越挡路，系统返回手势被抢走的边也越宽。**竖向高度不开
    这个口子**：200dp 是系统手势排除的配额上限，调小只是自损竖拖起手的容错。
    `settings.json` 本就**不参与同步**（范围见 architecture.md §4.4），所以它是
    纯本机手感项，换设备不跟着走。
11. 〔悬浮壳〕**固定侧边栏大小**：打开时**冻结此刻生效**的宽高——开关本身落
    `settings.json` 的 `panel_size_locked`，数值仍写 `panel_width` /
    `panel_height`；两条改尺寸的把手撤掉，内侧竖条就地换成跟手收起把手
    （朝停靠侧拖过面板宽的一半即缩回，见 §6.0）。关掉只解锁、数值保留。
    与第 8 条的『固定把手位置』是两件事：一个锁把手的**竖向位置**，一个锁
    **面板的宽高**。固定后误触改尺寸这件事就没有了——把手那两条边原本是面板上
    唯一会改布局的地方。
12. **展开后默认页面**：一组四选一——**今日清单（默认）/ 灵感 / 任务池 / 已完成**，
    落 `settings.json` 的 `default_page`（存页的稳定 id，与页序无关）。拖动把手展开即落
    这一页；点通知定位时按定位目标走，不被它盖掉（§6.0）。桌面上没有"展开"这一步，
    它是**重新打开窗口时**左栏的起始页（副标题随之改口，见本节开头）。标签最长四个字，窄面板
    下用可换行的 chip 而不是四等分按钮——240dp 上四等分会把"已完成"挤成省略号。
13. **工作时间**：**哪几天算工作日**（一~日多选）+ **那几天的工作窗**（多段式，
    如 09:00–12:00、13:30–18:00），落 `settings.json` 的 `work_days` / `work_windows`。
    它是 §7.1 那个 `available` 的分母——**改完立即重算，已定下的提醒锚点全部作废**
    （产能变了，旧锚点没有意义）。默认周一至周五、两段（09:00–12:00、13:30–18:00）。
    入口只有设置页这一项（v1.32 撤掉桌面标题栏那颗『工作时间规则』按钮：桌面的设置页
    就摆在侧边栏右边，标题栏不必再放一份），打开编辑面板；
    应用内今日清单不再有只读版。**节假日/调休未做**（`WorkTimeRule.holidays` 留位未接线）。

## 11. 边界与异常

- **权限被拒**：悬浮窗被拒 → App 内抽屉形态兜底（**四页全功能复用**：同一套 panels，
  App 内左侧滑呼出，无悬浮把手）；悬浮面板的引擎/窗口起不来 → 回退为"把手打开应用面板"
  （功能不减，只是会跳进应用）；通知被拒 → 提醒只在侧边栏内高亮；
  精确闹钟被拒 → 提醒可能迟到（如实提示用户）。
- **后台被杀 / Doze**：提醒依赖 AlarmPort 系统闹钟唤醒（architecture.md 附录 B），不靠 Timer。
- **闹钟模式权限**：全屏提醒需要锁屏显示/上层显示权限；被拒则退化为普通通知 + 响铃。
- **无 AI 配置**：默认策略照常，设置页显示"未接入"。
- **误触防护**：完成走长按菜单（天然防误触）；**翻页不靠"重手势"**——
  横滑与列表的纵向滚动方向正交，浏览清单不会翻页，翻页也不会误滚列表；
  通知上的"完成"按钮点击后提示完成，误触可去『已完成』页『恢复未完成』（§6.7）。
  **新建确认是纯点按，不承担
  防误触职责**：误建的代价很低（直接进散件段，长按就能改能删）。
- **详情卡是打开那一刻的快照**：它不订阅控制器的后续刷新（后台重锚、别的
  引擎改了任务，卡上的派生量不会自己变）。动作一律"先收卡再执行"（执行完这条任务
  往往已经从清单消失），所以不会留下一张指向旧数据的卡；要看最新的，关掉再点一次。
- **默认模式下"什么都不响"**：这是**标准模式的正常表现，不是故障**。要响有两条路——
  ①给那一件开『提醒我』（编辑表单里），②把设置里的调度模式切成**完整**。
  设置页的三选一旁写明这一点，避免被当成通知权限没给。
- **无排序模式下页底会多一段散件**：有截止的条目与标准/完整完全一致
  （仍按"锚点落在今天 / 今天到期"准入），变的只有组内顺序；页底那段 ⑥ 是这一档的
  设计（全部三无散件，池子那边不再显示，§6.1 / §6.3）。**有截止的任务无故变多是 bug
  不是特性**；不想看到的拖到下面，要回到"算法排先后"就切回**标准**或**完整**。
- **存储层的异常**：
  - 人类文档里缺 `创建` 的复选框行 → **不改动**、进 `warnings`（它在 Obsidian 里仍是
    普通待办，但内核不接管、不进任何清单——与 architecture.md 附录 B.1"只进 warnings"是同一件事）；
  - 两行内容完全相同 → 无法区分内核属主，只告警不猜（改掉任务名或创建时间即可分开）；
  - 人在 Obsidian 里删掉了某一行 → 内核属性文件**保留并提示**，不静默删数据；
  - 人在 Obsidian 里改了任务名 → 优先按指纹、其次按名字、最后按位置配对（附录 B.3）；
    位置配对只在"两边剩余数量恰好相等"时启用，数量不等宁可新接管也不猜。

## 13. 范围声明（有意不做 / 边界澄清，防将来被当遗漏）

- **性能/尺寸规格**（把手大小、动画时长等）：实现期以手感调参定，不写死数字；**侧边栏宽高是例外**——范围与默认值见 §6.0（用户能拖，数字本身就是给用户看的调参入口）；
- **多设备同步**：v1 单机——任务目录即数据（Obsidian 共享已是事实上的"同步"）；
- **备份恢复**：交给任务目录本身（文件即备份），App 不另做；`legacy-tasks/`
  （迁移存档）与 `.gtd/.trash/`（回收站）都**只增不自动清理**；
- **Obsidian 插件 / vault 接管**：不做。与 Obsidian 的连接形式就只有"多一个手机侧边栏
  入口读写同一批文件"（灵感篇的正文段可就地改，§6.2）；
- **人类文档的任务行里写内核字段**：不做。id/工作强度/优先级/时间裕度/剩余工作量
  只进 `.gtd/`，人类文档保持干净；
- **提醒的"自动升级"**：不做。标准模式下**不会**因为"快到期了"就自动开始提醒
  ——要响只能给那一件开提醒，或把模式切成完整。这是"默认安静"的代价，记在架构合同 §12；
- **用户自选调度算法**：不做（`slack.v1` 留在算法注册表里做对照，但设置页没有切换入口；
  要换得动组装点）。**调度模式三档不是算法选择**：换算法是换"怎么算 risk/priority"，
  而这三者改的是"算完之后用不用它"，两者别混为一谈；也没有往注册表里加
  第三个不带数学的假算法，`Scheduler.schedule` 也不收任何排序口径；
- **无排序档下的"智能整理"**：不做。按截止/优先级/习惯自动重排、或提示"要不要按算法
  排一遍"，都与该档"顺序就是人的决定"直接冲突；要做也只能做成**一次性**的显式动作
  （点一下才排，且排完即转为手动序）；
- **给固定时点组与例行组排手动序**：不做。前者时刻就是序、后者实例每天新生没有可持久的
  序号（"四处不跟着变"）；
- **详情卡的"整卡可编辑"**：不做。详情卡只读，改数据走显式动作（底部按钮
  或长按菜单）；同理**详情里不做改期**（改期的主场景在日历 §6.4）、**不显示排序分**
  （`risk` / `priority` 是排序键，顺序本身就是表达）。要改字段去『编辑』；
- **已完成页不做统计、不设条数上限**：只按天列条目，不做"本周完成 N 件"一类的汇总
  （要流水有 `log.md`）；也不做分页与"仅看最近 30 天"的开关——按天分组 +
  `ListView.builder` 足够，真到几千条再说。
- **数据埋点/使用统计**：无（`log.md` 是本地操作流水，不上报）；
- **新平台 shell**（iOS 等）：架构支持，需求不在本阶段；
- **桌面/Windows 端不做移动端的"进出"机制**：把手、遮罩、抽屉、跟手收起都不在桌面做
  （§6.10）——桌面窗口常驻，那套东西没有对应物。但**页面与能力**（四页 / 主线 / 设置 /
  提醒弹窗 / 同步）与安卓是同一份，不另做简化版。托盘图标、全局快捷键、开机自启属
  Windows 原生能力，当前不在范围。
- **面板头的『关闭』与『隐私』按钮**：不做（v1.24 撤掉）。关面板有点遮罩、返回键、尺寸固定
  后的收起把手三条路；防瞟走快记（§6.8）。面板头只留右上角『设置』——窄面板上多一颗图标，
  页名就少一截。
- **主线不做提醒、不与任务双向联动、不自动归档**：行为链步骤不参与调度（要参与就另建任务，
  两边不互相同步）；完成主线必须是显式动作（全部勾完 → 点『完成主线』），勾完不会自己归档；
  归档只有"看"没有"恢复为当前"——要重做就新建一条（同时只有一条在跑）。主线也不做统计
  图表与"连续 N 天"成就一类的汇总，日历上能看到的就是全部。
