# UI 与交互需求文档（安卓侧边栏版）

> 定位：这是**客户端层的需求**。architecture.md 的分层契约不变：侧边栏、悬浮把手、系统通知
> 全部是"平台呈现"，用户能做的一切动作仍然只能通过 TaskService 的命令进入核心。
> UI 里只出现接口名，不出现平台名——本文件描述"要什么"，"从哪个文件调"永远归适配器。

## 0. 一句话定位与设计原则

**日常一切操作发生在悬浮侧边栏里，App 主体几乎不开。**

0. **数据归属（地基）**：人写的归人、内核算的归内核，**物理分成两个文档**
   （人类文档 `tasks.md` + 内核属性文档 `.gtd/<id>.md`，见 §4.3）。
   下面的原则都建立在这条之上——侧边栏怎么摆、手势怎么滑，都不改变"谁写谁负责"。
1. **唯一入口哲学**：侧边栏承载添加、查看、完成、推迟、改期、日历、任务池、查看已完成的全部日常操作；
   打开 App 只剩设置页（暂定）。
2. **忙时零摩擦**：忙的时候点「+」，在月历上点今天那格、再敲标题就完事——日期一屏可选任意一天，其余属性整理全部推迟到闲时（§5.1）；问多少由档位决定，无排序档只问标题和日期（外加一颗响铃开关）。要"先记下来、之后再想"的走『不排期』，工作强度默认'长期'——不估工时、不设优先级（§4.2）。
3. **隐私防瞟**：人多的场合**不打开面板**——把手拖出头再拐个弯，就地记一条（[快记](panels/quick-note.md)），
   清单一次都不露；面板一旦打开，内容就在明处（面板头只留右上角『设置』）。
4. **提醒一律发出，吵不吵由自己定**（见 §7.0）：开关是**调度模式**，共两档，默认**无排序**
   ——软件不排先后、不问工时与重要度，只在每件截止前 30 分钟和截止那一刻各提醒一次，页底还
   多出一段散件。想让它按时间裕度排先后就切**标准**（多问工时）；重要度另有一个开关，默认不问。
   两档都一样：有时间的任务一定提醒（通知栏 + 横幅），响不响铃看每件任务的『响铃』；
   夜间静默（通知时间段）与"散件永不出声"照旧。

## 1. 名词表（本文件的专用词）

| 词                   | 定义                                                                                                                                                                             |
| -------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **侧边栏**           | App 自建的悬浮侧边条：贴屏小把手，任意界面（含其他 App 上方）拖出展开成面板                                                                                                      |
| **截止型**           | 要在某个时刻前完成的事（写论文、收拾房间）；截止日可空，空即散件                                                                                                                   |
| **开始型**           | 某个时刻开始的事（会议、约定、车票）；有确切时刻，不需估工时                                                                                                     |
| **三无**             | 无结束日期、不需要提醒、可被推迟的任务——即完全无约束的散件；**工作强度默认'长期'**（见下面两行）                                                                          |
| **散件**             | 三无任务（默认'长期'）：标准档在任务池横线后面，等闲时整理或被定期挑走；**无排序档常驻今日页最底**（[今日清单页](panels/today.md) ⑥）                                            |
| **长期（工作强度）** | 工作强度的一个**特殊值**：不是分钟数，是"这事长期存在、眼下估不出来"的标记；三无任务的缺省值                                                                            |
| **长期任务**         | 工作强度 = 长期的任务：**没有**工作强度数值、优先级、时间裕度（剩余工作量同理），内核属性文档里**只有一个任务 id**（§4.3）                                              |
| **任务池**           | 侧边栏『任务池』页：所有未完成任务的总览，横线分"未来计划段"与"散件段"（无排序档只剩计划段，[任务池页](panels/pool.md)）                                                                                   |
| **已完成**           | 侧边栏『已完成』页：已完成任务的总览，按完成日期分今天/昨天/更早三组；动作只有『恢复未完成』与删除（[已完成页](panels/completed.md)）                                                                            |
| **今日清单**         | 侧边栏『今日清单』页：挂起组（最顶）+ 逾期置顶 + 开始型组 + 截止型组 + 例行组（周期实例）+ 被挑散件 + 散件段（仅无排序档），分组连续编号；"当前"即"今日"                                              |
| **灵感**             | 侧边栏『灵感』页：从指定 Markdown 文件提取显示的段落，**可就地编辑**（只写正文段，frontmatter 不动，[灵感页](panels/notes.md)）                                                                            |
| **周期任务**         | 循环任务（每天/每周X），在设置页创建维护，到点自动出现，响不响单独设                                                                                                             |
| **定期挑**           | 定时（默认每天）从散件段随机挑一件附到今日清单尾部，不响提醒，仅可见；**无排序档不跑**（散件本来就全在页底，没有"挑上来"的去处）                                     |
| **今日会响**         | **今天会响**的今日条目：提醒锚点落在今天的截止型任务 + 今天到点的开始型任务；**无排序档**换成"两站时点提醒落在今天的"（提醒口径，分组构成见 [今日清单页](panels/today.md)，口径见 §7.0） |
| **裕度（slack）**    | 距截止的真实可用工时 − 剩余工时，唯一压力表（见 architecture.md）                                                                                                                |
| **人类文档**         | `tasks.md`：**所有任务**都记在这一个文档里，`# 标题` 分类，一条任务一行（见 §4.3）。这里的**「分类」= `# 标题` 小节**，与任务类型（截止型/开始型，记在内核属性的 `type`）不是一回事 |
| **内核属性文档**     | `.gtd/<任务id>.md`：内核算出来的属性（任务id/工作强度/优先级/时间裕度/剩余工作量）；人也能看能改（见 §4.3）                                                                      |
| **行指纹（digest）** | 人类文档里那一行的指纹，存在内核属性文档里；两条文档靠它对号（人不写、也不该改）                                                                                                 |
| **调度模式**         | **无排序**（默认）/ **标准** 两档选一个，见 §7.0。两档是**一条信息深度的谱系**：上一档多问工时、多换一种能力                                                                     |
| **标准模式**         | 问工时。算法按时间裕度算先后（谁先做），提醒按裕度节奏响；要不要再问重要度由设置里的开关决定                                                                                     |
| **问重要度**         | 标准档里的一个开关（默认关）：打开后新建多问一项 1–5 的重要度，并把它当排序乘数；关掉时整个维度不参与——表单不问、排序不乘，已存的值原样留着                                      |
| **无排序模式**       | 只问标题和日期：不跑调度算法、不问工时与重要度，今日清单**截止型组**只收"今天到期"的、顺序全靠手动拖，每件在截止前 30 分钟响一次；另把全部三无散件附在页底（⑥）。其余组的排法不变，见 [今日清单页](panels/today.md) |
| **调度优先级**       | 算法排顺序用的分 = `risk × 优先级`（人看不到具体数字，只看顺序）                                                                                                                 |
| **手动序**           | 无排序档下人拖出来的顺序（`manual_order`，记在任务上、重启保留）；切到标准后**保留但不生效**                                                                                     |
| **风险（risk）**     | 由时间裕度算出的"误期风险"，∈(0,1]，裕度越小越接近 1；**非线性**（§7.1）                                                                                                         |
| **详情卡**           | 点条目展开的那张**只读**卡（[今日清单页](panels/today.md)）：标题 + 一行时间 + 备注全文，**没有按钮**；改数据一律走长按菜单                                                        |
| **挂起进行**         | 长期任务的"正在做"标记（`in_progress`）：点了『挂起进行』这件事就进今日页最顶的挂起组；多件可挂、组内可拖；保持到完成或主动取消，**不按天过期**                |
| **挂起组**           | 今日页最顶的那一组（⓿，逾期组之上，[今日清单页](panels/today.md)）：全部挂起进行中的任务，**无编号**；两档调度模式下都在最顶、都能拖                                             |
| **主线** | 侧边栏顶栏第二行那一条：当前正在推进的一件大事（写论文、装修……）。**同时只有一条**在跑，完成后归档；主线住在 `tasks/主线.md`，与任务池是两层——行为链上的步骤**不是任务**，不进调度、不占工时（[主线覆盖页](panels/mainline.md)） |
| **行为链** | 主线里的一串步骤，排成一条链：勾了就完成（记完成时刻，文字加横线），链上第一个没勾的是"下一步"。链上步骤与 `tasks.md` 无关（[主线覆盖页](panels/mainline.md)） |
| **圈（记录）** | 主线『记录』页（日历）上**手动拖选连续日期**圈出来的一段，圈里写文字——这就是主线 log 的本体；某天几点勾了哪一步是另一层（自动流水），点开那天看（[主线覆盖页](panels/mainline.md)） |

## 2. 平台与权限前置（安卓）

- 平台：安卓 App，Flutter（现有工程已有 domain/application/repository/scheduler，本阶段补安卓 shell）。
- 需要的系统能力（全部走插座，契约见 [sockets/delivery.md](sockets/delivery.md)）：
  - **悬浮窗权限**（SYSTEM_ALERT_WINDOW）：侧边栏把手与面板；
  - **通知权限**：到点提醒；
  - **精确闹钟权限 + 电池白名单**：准点响铃（安卓 12+ 需单独授权）；
  - **语音输入不自研**：直接用输入法自带的语音键（讯飞/搜狗/Gboard 等），
    通知输入框和侧边栏输入框天然接住识别文本，零额外开发。
- 首次引导：App 设置页负责逐项申请权限并解释用途；权限被拒时对应功能优雅降级（见 §10）。

## 4. 任务模型（UI 视角）

### 4.1 类型二分

每条任务二选一：

|        | 开始型（某时发生）                                       | 截止型（某时前完成）                                                                       |
| ------ | -------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| 例子   | 会议、约定、车票                                         | 写论文、回邮件                                                                             |
| 必填   | 日期时间（创建时在第 2 页切到『开始型』，时刻经『自选…』挑） | 截止日可选（空 = 散件）                                                                 |
| 估工时 | 不需要                                                   | 需要（进调度）；**无截止的三无除外**——默认'长期'，不估工时                        |
| 提醒   | **到点响一次**（默认开；关掉只是不出声——提醒照发）       | 有截止日→按裕度排序并按裕度调频（§7），**最后一次不晚于截止**；无截止日→**不提醒**         |
| 归属   | 今日清单（到点当天）、任务池计划段                       | 有截止：今日清单+任务池计划段；无截止：任务池散件段                                        |

### 4.2 字段

Task 的字段（正典见 [formats/sidecar.md](formats/sidecar.md)，这里只说 UI 认哪些）：
id / title / description / deadline / estimatedWork / remainingWork / importance /
status / snoozedUntil / metadata / created。下面几条值得单独说：

- **类型**：截止型（`flex`）/ 开始型（`fixed`）。三无 = 截止型且无截止。
- **截止日可空**：散件没有截止。
- **工作强度的特殊值'长期'**：三无任务（截止型 + 无截止 + 不提醒）创建时**默认长期**——'长期'不是分钟数，标了它就是**不估工时、不设优先级、不算裕度**，内核属性文档里只有一个任务 id（§4.3）。**长期不是新类型**（类型仍是 fixed/flex，§4.1）；有截止的这类任务仍必须给数字工时（缺省 30 分钟，进 slack 数学，§7.1）；'转正'= 补截止 + 把'长期'换成具体工时（[任务池页](panels/pool.md)）。
- **标签 `tags`**（正式字段）：人类文档行尾的 `##标签`，见 §4.3。
- **完成时刻 `completedAt`**（正式字段）：人类文档的 `完成 <日期,时间>`，
  与打勾同步落一次；`status=completed` 与它任一成立即视为完成。
- **响铃开关 `remind`**（走 metadata 缓冲带）：提醒照发，它只决定这条提醒**响不响**——
  开 = 有声渠道（声音 + 震动），关 = 静音渠道（横幅与通知栏照旧，只是不出声）。**新建时
  默认打开**。它**不改变顺序**、不改变提醒时刻（§7.0）。缺键 = 静音（旧版本只在人主动开
  提醒时才写 `true`）。散件不写这个键。
- 散件与"被定期挑中"的状态、周期任务规则，见 [任务池页](panels/pool.md)。

### 4.3 存储形态：双文档（正典见 [formats/](formats/README.md)）

**人写的归一个文档，内核算的归另一个文档**：`tasks.md` 一行一条任务（人看人改，
应用只代笔自己那一行）；`.gtd/<任务id>.md` 装内核算出来的属性；两条靠行指纹配对。
长期任务的内核文档只剩 `id` 一行——'长期'不单独落一行，**没有 `work_intensity` 就是长期**。

字段、行语法、配对与归属规则的正典在 [formats/](formats/README.md)，本节不复述。

**分工与承诺**（写死）：

|                      | 人类文档 `tasks.md`                                | 内核属性文档 `.gtd/<id>.md`                            |
| -------------------- | -------------------------------------------------- | ------------------------------------------------------ |
| 谁写                 | 人（也由应用代笔**自己那一行**）                   | 应用                                                   |
| 应用改什么           | 只改它自己写的那一行：插入新任务、打勾、补完成时刻 | 全部字段随任务对象改写                                 |
| 应用绝不做什么       | **不重排行、不动别人的行、不动标题/空行/正文**     | 不动人的东西（这文件本来就只有内核字段）               |
| 人在 Obsidian 里能做 | 改名/改日期/改备注/加删行/换分类/加标签            | 也能改（字段级保真：注释、未知字段、内核备注原样保留） |
| 冲突时谁赢           | 人类那边赢（任务名/创建/结束/完成/备注/标签）      | 内核那边赢（工作强度/优先级/时间裕度/剩余工作量）      |

- **人只改人类文档也能用**：应用发现指纹变了就按上面的归属合并；
  新增的行会被内核接管并分配任务 id（**首次同步会提示一次**）；
  删掉的行不会连带删掉内核属性（文件即备份，删不删由人决定，只提示）；
- **人类文档里不出现任何内核字段**：id、工作强度、优先级、时间裕度、剩余工作量
  一个都不写进去——这是"共享/查看的文档要干净"这条要求的落地；
- **形态选择**：所有任务记在一个 `tasks.md` 里用标题分类
  （不是一任务一文件）；`log` 数据（领域事件流）**单独一个文档**，
  见 [架构文档](architecture.md) §3.3。

> 与 Obsidian 相连的形式不变（[灵感页](panels/notes.md)）：**形式上只是单纯在 Obsidian 外
> 增加一个手机侧边栏的快捷入口**——不做 Obsidian 插件、不接管 vault、不代改笔记，
> 差异只在"多一个入口读同一批文件"。

## 5. 创建流程

### 5.1 先问什么时候（侧边栏内弹出）

```text
第 1 页 · 什么时候？                第 2 页 · 填内容（标题已获焦）
┌────────────────────────┐       ┌──────────────────────────────┐
│ 什么时候？      [不排期] │       │  标题…                        │
│  ◀  2026 年 10 月  ▶   │       │  备注…（选填）                │
│  一 二 三 四 五 六 日    │       │  📅 截止 10-28 18:00 [改日期] │
│           1  2  3  4  5 │ ────▶ │  类型 [截止型 ✓] [开始型]     │
│  6  7  8  9 10 11 12    │       │  工作强度 [长期] [按时长 ✓]   │
│  …（固定六行，横滑换月） │       │  响铃    ○                    │
│  点某天，接着填内容       │       │      [ ✱ 创建 ]               │
└────────────────────────┘       └──────────────────────────────┘
```

1. **第一步是日期，按月历点**：点某天即落定、原地翻到第 2 页。左右横滑换月，两侧箭头
   一次一格（与[日历弹窗](panels/calendar.md)共用同一个组件）。这里**不打点**——新建时
   只关心选哪天，那天已经排了什么与这件事无关。
2. **时刻按类型取默认**：截止型落该日 **18:00**（工作窗末尾，"今天做完"的安全上界）；
   开始型落该日 **12:00**（午前收尾、午后动手的常用起点）。第 2 页切类型时，**没手动改过
   的时刻**跟着换整点。
3. **时刻可点改**：第 2 页日期行里那颗时刻点开弹时间选择器；改过之后即钉住，再切类型不再
   覆盖它。右侧『改日期』退回月历，那天保持选中，已填的标题与备注不丢。
4. **『不排期』在标题行右侧**，不占月历里的一格 = 截止型 + 无截止 → 入池散件段，工作强度
   '长期'（不估工时、不设优先级，§4.2）。
5. **两页住同一个 sheet**：切页不叠一层弹窗，第 2 页的标题自动获焦。
6. **第 2 页与『编辑』同一套字段**（[今日清单页](panels/today.md)）：
   - 截止型 = 要在某时前做完；开始型 = 某时开始，切过去时若还没有日期，就地补一小时后；
   - **散件不显示『响铃』**——它们永不出声（§7.0）；
   - 标题为空时『创建』不可用。
7. **回车**：标题框回车跳备注，备注框回车 = 创建。
8. **没有预选的日期**：月历上今天只是淡色高亮，不进第 2 页就没有"默认今天"这回事。最短
   的一条路是"点 + → 点今天那格 → 敲标题 → 创建"，落一件截止 18:00 的任务。
9. **语音输入**：任何输入框都可以用输入法的语音键说话出字，App 不额外做语音功能。
10. **问多少由档位决定**（§7.0，上图是标准档打开了『问重要度』的形态）：无排序档第 2 页
    只有标题、备注、日期行和『响铃』——工时与重要度不出现，缺省值按 30 分钟 / 3 落盘；
    标准档多问工时，重要度再看那个开关。『响铃』不在裁剪之列：它管声音，不管发不发。
    **编辑表单不按档裁**（工时在无排序档照样能改），只跟『问重要度』走：开关关着时，
    编辑表单里也没有重要度这一行。

> **为什么日期在第一步**：默认『三无』等于默认"不排期"，而绝大多数任务有日期——建一件
> 普通任务反倒要多点两次（类型 + 日期），只有少数派零成本，默认值站错了队。反过来之后
> 三无并没有变难：它还在第 1 页，只是要点一下。当时也想过干脆去掉『不排期』，但那会让
> 桌面壳失去建三无的入口——快记只在系统级悬浮把手上（[快记](panels/quick-note.md)）。
> 取舍与代价见 [决策卡片](decisions/2026-10-24-create-date-first.md)，第 1 页为什么是月历见
> [另一张卡片](decisions/2026-10-28-create-month-calendar.md)。

## 7. 提醒系统

### 7.0 调度模式两档（**默认无排序**）

**两档是一组二选一**（设置页『提醒与排序』节），按**信息深度**排——上一档多问工时：

|                  | **无排序（默认）**                                                          | **标准**                                 |
| ---------------- | --------------------------------------------------------------------------- | ---------------------------------------- |
| 新建时问什么     | 标题 + 日期                                                                 | 再加**工时**（长期 / 按时长）            |
| 跑不跑调度算法   | **不跑**                                                                    | 跑                                       |
| 今日截止型组成员 | **今天到期**（逾期的在 ① 组）                                               | 锚点落在今天 / 今天到期                  |
| 今日截止型组顺序 | 手动序（`manual_order`）                                                    | 调度优先级（裕度风险 × 重要度乘数）      |
| 提醒             | 截止型与开始型同一套：`T − manual_lead_minutes`（默认 30）与 `T` **各一次** | 截止型按裕度节奏**多次**，开始型到点一次 |
| 逐件『响铃』开关 | 有（新建默认开）                                                            | 有（新建默认开）                         |
| 页面额外内容     | 页底 ⑥ 散件段                                                               | —                                        |
| 放弃的能力       | 不可行预警、按裕度提前介入、工时对账                                        | —                                        |

一句话记：**无排序只管日子；标准再加上时间压力。**

**重要度是标准档里的一个开关**（『问重要度』，默认关，落 `settings.json` 的
`ask_importance`）：打开后新建多问一项 1–5（缺省 3），并把它当排序乘数
（`priority = risk × importance`）；关掉时**整个维度不参与**——新建不问、编辑表单里也没有
这一行、乘数按 1 算。已存的值原样留在内核属性文档里，打开开关即恢复，切档不迁移。

- **界面按档裁剪，数据不留空白**（[决定](decisions/2026-10-28-mode-as-information-depth.md)）：
  无排序档不问的项按缺省值落盘——工时 30 分钟、重要度 3、`remind` 开（响铃）。切到标准档
  立刻能参与排序，不用补数据。**编辑表单不按档裁**（工时在无排序档照样能改，它也是把一件
  升成有估值的唯一入口），只跟『问重要度』这个开关走：开关关着时，编辑表单里也没有那一行
  ——关掉的是整个维度，不是一个控件的可见性。
- **无排序档的提醒是两站时点提醒**：截止型与开始型同一套——`T − manual_lead_minutes`
  与 `T` 各一次（`T` = 截止型的截止、开始型的开始）。按墙钟算、**不受通知时间段约束**
  （提前那一站若早于任务创建就整站不排，不补响）；错过靠长按『推迟』，**推迟之后 `T`
  不再单独响**——推迟那一刻就是这件任务的下一次、也是最后一次。它不依赖裕度，所以这一档
  不问工时也不会少响。
- **重要度只进排序**：它不改变提醒节奏，也不改变今日页收哪几件（那是锚点的事）。
- **发不发与响不响是两件事**：有没有提醒看任务有没有时间（有就一定发），响不响看这一件
  的『响铃』（挑 `ring` / `silent` 渠道）；通知时间段决定"**什么时候**允许出声"（段外
  顺延，§7.1）。无排序档不走时间段顺延——它的两站按墙钟原样响。
- **为什么默认无排序**：新装先让人只填最少的东西，排序与估工时是升级项，切一下就有。
  代价（默认档恰好把"有截止的怎么安排"这个特色关掉了）记在
  [架构文档](architecture.md) §11。
- **切换立即生效**：顺序与下一站闹钟都重算（提醒是计算结果，无迁移、无历史改写）。

### 7.1 算法与默认策略（时间裕度优先 + AI 调参）

**标准档**里，截止型任务一律换算成"工作分钟"（跳过夜间/午休/周末）再比。
`available` / `slack` / `risk` / `priority` / 提醒间隔的公式与默认参数**只有一份**，在
[架构文档](architecture.md) §3.1；本节只说这些量在界面上怎么用、由谁调，以及哪些任务
根本不在那套公式里。**无排序档整档不在公式里**——它只有一条提前量，见本节
『无排序档的提前量』。

- **排序四档**：不可行 → 普通（调度优先级降序）→ 逾期 → 已推迟。不可行是
  "已经注定误期"，单独一档等用户裁决（改截止 / 砍范围 / 加班）；
- **裕度优先**：裕度越薄风险越高、越排在前面；**优先级（1–5，缺省 3）是乘数**，
  让重要的事整体前移。乘数最多 5 倍，裕度差出一个 τ（480 分钟）以上它就盖不动了；
  『问重要度』关掉时乘数取 1，这一层整个不参与。
- **为什么非线性**：线性要让裕度"到哪算 0"凭空定一个量纲，还会算出负风险；
  指数族只要一个尺度 τ，且恒在 (0,1]——**裕度还宽时催得少，裕度一薄就陡然变急**；
  γ>1 = 裕度充足时压得更低（更平）、薄了迅速冲到 1（更陡）。τ 与 γ 的取值见
  [架构文档](architecture.md) §3.1。
- **`priority` 这个名字只属于算法内部**：人定的是**优先级**（内核属性文档的
  `priority` 键 = `Task.importance`，缺省 3），算出来的是**调度优先级**（不落盘、不进人类文档）；
  界面照旧展示裕度这类派生量，但不显示这个排序分——**顺序本身就是表达**。
- **提醒时刻不晚于截止**：锚点按裕度算完还要夹到截止。算出来晚于截止——截止前来不及
  准备、工时超过剩余可用时间、锚点跨到了非工作日——就取截止那一刻，保证"设了时间"至少
  响一次，而不是排到一个已经逾期的时刻。
- **无排序档的提前量**：`manual_lead_minutes`（默认 30 分钟，设置页在两档下面那一行）。
  只有无排序档用它——每件任务在 `T − 提前量` 与 `T` 各响一次（截止型取截止、开始型取
  开始），按墙钟算、**不受通知时间段约束**。标准档的节奏仍由上面的间隔公式
  决定，与这个值无关。
- **全局通知时间段（多段式）**：截止型任务的提醒只落在时间段内，时间段外静默
  （这是**门槛之后**的一道，§7.0）。设置里支持**多段编辑**
  （如 9:00–12:00、14:00–18:00、19:00–21:00，方便抠掉午睡/饭点）；默认一段 **9:00–21:00**；
- **AI 动态调整 = L2 软控制**：AI 只允许在 Scheduler `params` 声明范围内微调
  （α、最小间隔、间隔拐点、风险尺度 τ 与陡度 γ），一切变更走 origin=ai 的领域事件，**可审计、可拒绝**——
  回滚不承诺（[架构文档](architecture.md) §6：逆命令机制未设计，落地前 UI 只提供"拒绝"）；
  没配 key / AI 挂掉 → 默认策略照常。
- **开始型**：标准档到点响一次，不提前、不进调度；**无排序档多出提前那一站**
  （见上条）。（实现：`TaskService.nextPointReminder()` + ReminderDispatcher
  三源单闹钟；`point_fired` 记"已响到哪一站"，改期重新生效；错过超过 30 分钟不再补响。）
- **散件（截止型且无截止）**：永不提醒（两档都一样）。
- **三无的默认工作强度 = '长期'**：'长期'不是分钟数，是"长期存在、估不出来"的标记——标长期的任务不估工时、不设优先级，也不进 [架构文档](architecture.md) §3.1 那套公式（它们本来就没有截止；内核属性文档里只有一个任务 id）。
- **周期任务**：响不响单独设置（**标准模式下"规则设了响"就等价于给这个实例手动开了提醒**）；
  **不占工时**（不进裕度容量计算）；
  当天实例**跨日生成**（不存在"应用没开还会有零点任务"这回事）；
  完成即消，次日再生。（实现：实例在启动/跨日/回前台时**幂等**生成
  ——没有"每天零点"的后台闹钟，应用下一次活着的时候补齐，落成任务文件。）

### 7.2 提醒呈现与推迟

> **前提**：本节讲的是"响了之后长什么样"。有时间的任务都会走到这里（两档一样）；
> 『响铃』只决定这条提醒有没有声音，形态不随它变。

- 到点弹**通知栏消息 + 横幅**（高优先级渠道，横幅从屏幕顶部滑出），通知上直接给快捷
  按钮：**『完成』『推迟 1 小时』**；开着『响铃』的那件同时出声 + 震动，关掉的只有横幅
  和通知栏；
- 点通知**正文** → 展开**侧边栏**并定位到该任务。**定位边界**：目标在今日清单 → 定位高亮；
  已滚进任务池 → 跳池子定位高亮；已完成 → 跳『已完成』页定位高亮（[已完成页](panels/completed.md)）；已删除 → toast"已删除，可在回收找回"。
- **推迟档位**：通知快捷固定 1 小时；长按菜单『推迟』给档位：**30 分钟 / 1 小时 / 3 小时 /
  明早 9 点 / 自选时间**。推算结果落在静默/休息段 → **顺延到下一时段开头**（不强制响，
  夜间静默是硬规则；**开始型的到点提醒不受静默限制**）；跨休息段的推迟按 architecture.md **D8**
  给显式选项"到下个工作窗"（≤120 分钟按自然时间）。**绝对档位（明早 9 点 / 自选）原样响**
  ——静默段顺延只作用于相对档位推算出的时刻。
- **可选闹钟模式**（**只对开始型生效**：开始型的到点提醒 + 设了响的周期任务；
  其余提醒一律走通知栏）：开启后这一条**升级为全屏提醒界面 + 持续响铃**，覆盖掉它本来
  那条通知栏投递，必须手动点『完成 / 推迟 / 知道了』才停；走系统闹钟渠道，媒体静音压不住
  （实现上对应 full-screen intent，需锁屏显示/上层显示权限，走 PermissionPort）。
  （实现：原生渠道 `gtd_alarm`（IMPORTANCE_HIGH + 闹钟音 + 震动）+
  `setFullScreenIntent`；权限缺失时退化为通知栏 + 横幅。
  应用被杀时由系统闹钟的接收器照"交付草案"弹出通知，按钮点击回传应用；
  应用当时没开则在下次启动补做。）
- **编排条目只有一句话**：没有『完成』『推迟』按钮，也不进闹钟模式；点正文落编排页的今天
  （[今日编排](panels/plan.md)『到点提醒』）。能推迟的是任务，编排只排不做。

## 8. 视觉规范

- **橙色系**：橙做**强调色 + 中性底**——底色纸白/深灰双模式；
  橙只给关键元素：编号、确认键、"今日会响"徽标、裕度告急、逾期标记等。
- 主题可在设置里切换：明暗三选一 + 4 套强调色预设（见 §9 第 7 条）。
- 侧边栏窄幅、低密度舒适行高；编号大而醒目（橙色），标题为主文案，备注弱化。
- **明暗三选一**：**跟随系统（默认）/ 浅色 / 深黑**，落 `settings.json` 的
  `theme_mode`；两个引擎（主引擎 + 系统级悬浮面板）读同一份设置，切换
  立即生效、不迁移任何任务数据。深色底 = **暖深褐黑**（`#1E1B18` 底 /
  `#2A2622` 卡）而不是纯黑——配橙种子保住"纸"的暖底基因。
- **状态语义色不随强调色预设变化**（逾期橙红是状态不是装饰）；暗色模式下**逾期橙红取
  提亮变体**（浅底约 4.4:1 → 暗底约 5.5:1）。"不随预设变"与"随明暗提亮"是两件事：前者
  防装饰性漂移，后者保可读性。
- **列表行右端的时间签 / 日期签是例外：它随预设走**。两颗色直接取日历那套点色板
  （开始型与例行 = 开始色，截止型 = 截止色），职责是"分类型"不是"报状态"——同一件事在
  日历格子和清单行上是同一个颜色，人才认得出。逾期件是唯一压过类型的情形：整条签
  转逾期橙红。签的字体比正文小一档、数字用等宽字形，各行时间才竖着对得齐。
- **日历的点另有一套色板**（[日历弹窗](panels/calendar.md)）：开始 / 截止 / 完成三色。每套预设
  配一对有色——开始沿用该主题的色相，截止取相隔约 150° 的那一侧、避开逾期橙红那一段；完成
  是全主题共用的一颗暖灰。三色按对底对比分三档（白卡 4.5 / 6.2 / 3.6，深卡 4.6 / 5.8 /
  3.6，深底上变亮才是变重），灰度截图与色弱视角下仍分层。这套色板只服务日历格子：强调色
  种子照旧只管按钮、编号、选中高亮——按钮要托白字，点要的是 4dp 下可辨，两者需求不同。
- **界面文案的边界**：每条只写"这条设置/这个按钮是干什么的"，一句
  为限；降级结果由申请失败时的 toast 说，不预写在每一行下面。**设计文档的
  内部引用不出现在界面上**——「决议 N」「§x」「[formats/](formats/README.md)」「routines.md」
  「.gtd/.trash/」这类只属于 docs；旧文案里的这些引用已全部清掉。
- **动效口径**：遮罩与面板同步渐显渐隐；自绘对话框统一走
  `showScaledDialog`（从 0.94 倍缩放淡入）；空态与浮出块（面板右下角的
  「日历」+「+」双钮）用 `FadeIn` 淡入 + 轻微上移；页名切换淡入、页序圆点切换时颜色渐变。
  时长都在 200–260ms、缓出曲线，**不做回弹**。
- **面板头翻页圆点单独一行**：居中四个圆点是面板的"我在第几页"标识，7dp
  圆形（只留切换时的颜色渐变）。省下那 30dp 内容高度不划算。
- **抽屉与面板同底、页名条左对齐内容**：抽屉吃 M3 默认底色
  （`surfaceContainerLow`，被种子色染过一层）会跟纸白的内容区有色差——
  **状态栏那条与页名条看得出来**（真机截图可见）。抽屉底色取 `scaffoldBackgroundColor`，
  与面板本体（`Material(color: theme.scaffoldBackgroundColor)`）同一个值；页名条
  `TabAlignment.start` + 标签内边距 18dp，**左缘与页内容留白对齐**——默认的
  52dp 起始偏移是给 AppBar 左侧头像留位的，抽屉里没有头像，留着就是一截空当。
- **设置页分区卡片化**：八个区改为"橙色小标题 + 一张 Card"的分区
  卡片，区的边界看得见；周期任务区内的规则行不再套 Card（卡中卡），高亮
  改用浅色底。面板头图标按钮收到 34 dp 见方（默认 40 在 240 dp 宽的面板上
  会把页名挤没）。App 壳 AppBar 不摆与抽屉重复的"打开侧边栏"图标，抽屉本体与
  AppBar 菜单保留（见 [把手与面板](panels/handle.md)）。

## 9. 设置页清单（暂定 App 唯一页面）

【**除第 3 条的 AI L2 外**全部已落地；桌面端与安卓用**同一份设置页**——安卓里它是
App 主体，桌面上它是侧边栏右边那一栏（[桌面布局](panels/desktop.md)）】

**只对某种壳有意义的项**：同一份设置页里有一组项只属于"贴屏悬浮壳"——
权限引导（悬浮窗 / 精确闹钟 / 电池白名单 / 锁屏 / 文件访问）、
把手位置上锁、把手热区宽度、固定侧边栏大小（含跟手收起）、重看首次拖出引导、
闹钟模式（全屏渠道，**只对开始型生效**，覆盖那一条的通知栏投递）、关于（版本号 / 反馈方式，第 14 条）。判据是"**这套壳有没有那个东西**"，不是"什么系统"：由组装点
注入一张 `ShellCapabilities` 能力表（`lib/application/shell_capabilities.dart`），
设置页只读表、**不问平台**（[架构文档](architecture.md) §5.1 的口诀）。桌面上这几项**整行不渲染**——
不是灰掉：灰掉会让人以为"再找找就找到了"，而桌面上它根本不存在。于是桌面的
『侧边栏』区只剩"展开后默认页面"，副标题也跟着改成"重新打开窗口时落在这一页"。
下面各条里标〔悬浮壳〕的即此列。**系统级贴屏把手不在这张表里**：它恒开、没有开关
（见 [把手与面板](panels/handle.md)），所以不需要"哪种壳有没有它"这一层判断。

1. 〔悬浮壳〕首次引导 + 权限申请（悬浮窗/通知/精确闹钟/电池白名单/文件访问）——逐项申请、
   逐项显示当前状态，被拒时页面内 toast 说明降级；任务目录另支持手输路径兜底；
2. 周期任务管理（增删改、频率、响不响、启用开关）——读写任务目录下独立的 `routines.md`，
   Obsidian 可直接看改；下方另有『周期任务在任务池显示』开关（第 6 条）；
3. 提醒：通知时间段（**多段式**编辑，默认 9:00–21:00）、〔悬浮壳〕闹钟模式开关（只把开始型升级成全屏，覆盖那一条的通知栏投递）；**提醒/排序的模式切换见第 9 条**；
4. 定期挑：开关、间隔（默认 1 天）；
5. **灵感**文件路径（**系统选择器挑文件 + 手输路径兜底**，与任务目录同款弹层；
   App 就地编辑这篇 Markdown 的正文段，[灵感页](panels/notes.md)）；
6. 周期任务在任务池的显示开关；
7. 主题：**明暗三选一**（跟随系统（默认）/ 浅色 / 深黑）+ 4 套强调色预设
   （橙 / 墨蓝 / 苔绿 / 梅紫；只换强调色种子，选中只靠底色，不画勾、标签也不带"默认"）。明暗落
   `settings.json` 的 `theme_mode`、预设落 `theme_preset`；逾期橙红等
   状态语义色不随预设变（暗色下的提亮变体见 §8）；
8. 附加：〔悬浮壳〕重看首次引导、回收站清空。
9. **调度模式两档**：**标准 / 无排序（新装默认）**一组二选一，各一行说明用途
   （见 §7.0 那张表）；模式落 `settings.json` 的 `schedule_mode`（仍读得懂旧的
   `reminder_mode`；旧文件里的 `full` 落到标准，并把『问重要度』打开——那正是它当初要的），
   切换立即生效、不迁移任何数据。
   界面上两档各只留半句："排先后，提醒按裕度节奏" / "不排，截止前与截止各提醒一次"。
   细化解释不挤窄屏，切一下就体会得到；各档问什么、今日页收哪几件那层澄清留在 §7.0 的表里，
   不属于界面文案。
   紧跟一行**『问重要度』开关**：只在标准档出现，默认关。打开后新建多问一项 1–5 并把它
   当排序乘数；关掉时整个维度不参与（编辑表单里也没有那一行）。落 `settings.json` 的
   `ask_importance`，改完立即重排。
   再紧跟一行**无排序档的提前量**：`manual_lead_minutes`（默认 30，范围 5–1440），
   只在无排序档生效（截止型与开始型都在 `T − 提前量` 与 `T` 各提醒一次），改完立即重算下一次闹钟。
   最后一格是 **AI 编排的入口位**：不可点，只写用途（记住你的习惯、自动估工时、语音改清单）。
   位置留着，形状不承诺——它不是在排序算法里再加一档，做什么见[路线图](roadmap.md)。
10. 〔悬浮壳〕**把手热区宽度三档**：**细 8 / 标准（默认）12 / 宽 20**（单位 dp）一组三选一，
    落 `settings.json` 的 `handle_hot_width`，改完立即生效；原生侧另在 prefs 里存一份镜像（服务可能比 Dart
    先起来）。选的就是"好抓"与"不挡路"的折中点——热区盖住的触摸归把手（[把手与面板](panels/handle.md)），
    越宽越好抓、底下那一竖条越挡路，系统返回手势被抢走的边也越宽。**竖向高度不开
    这个口子**：200dp 是系统手势排除的配额上限，调小只是自损竖拖起手的容错。
    `settings.json` 本就**不参与同步**（范围见 [sockets/sync.md](sockets/sync.md)），所以它是
    纯本机手感项，换设备不跟着走。
11. 〔悬浮壳〕**固定侧边栏大小**（**默认打开**，新装即 240 × 425 固定）：打开时**冻结此刻生效**的宽高——开关本身落
    `settings.json` 的 `panel_size_locked`，数值仍写 `panel_width` /
    `panel_height`；两条改尺寸的把手撤掉，内侧竖条就地换成跟手收起把手
    （朝停靠侧拖过面板宽的一半即缩回，见 [把手与面板](panels/handle.md)）。**想自己调尺寸就得先关掉这个
    开关，拖完再打开把新尺寸冻住**；关掉只解锁、数值保留。
    与第 8 条的『固定把手位置』是两件事：一个锁把手的**竖向位置**，一个锁
    **面板的宽高**。固定后误触改尺寸这件事就没有了——把手那两条边原本是面板上
    唯一会改布局的地方。
12. **展开后默认页面**：一组四选一——**今日清单（默认）/ 灵感 / 任务池 / 已完成**，
    落 `settings.json` 的 `default_page`（存页的稳定 id，与页序无关）。拖动把手展开即落
    这一页（默认页是今日清单且今天排过编排时，每次展开先亮编排覆盖页，见 [今日编排](panels/plan.md)）；点通知定位时按定位目标走，不被它盖掉（[把手与面板](panels/handle.md)）。桌面上没有"展开"这一步，
    它是**重新打开窗口时**左栏的起始页（副标题随之改口，见本节开头）。标签最长四个字，窄面板
    下用可换行的 chip 而不是四等分按钮——240dp 上四等分会把"已完成"挤成省略号。
13. **工作时间**：**哪几天算工作日**（一~日多选）+ **那几天的工作窗**（多段式，
    如 09:00–12:00、13:30–18:00），落 `settings.json` 的 `work_days` / `work_windows`。
    它是 §7.1 那个 `available` 的分母——**改完立即重算，已定下的提醒锚点全部作废**
    （产能变了，旧锚点没有意义）。默认周一至周五、两段（09:00–12:00、13:30–18:00）。
    入口只有设置页这一项，打开编辑面板（桌面的设置页就摆在侧边栏右边，标题栏不必
    再放一份）；
    应用内今日清单不再有只读版。**节假日/调休未做**（`WorkTimeRule.holidays` 留位未接线）。
14. **关于**：设置页最底部一张卡，三行——**版本号**（形如 `1.2.0 (4)`：主版本 + 构建号）、
    **反馈方式**（QQ 号）、**GitHub**（`github.com/lumen-one/gtd_todo`）。后两行点整行即
    复制到剪贴板并 toast 一句结果，**行尾不写『点一下复制』**——给一长串地址缀四个字，
    窄栏里只会折成第二行；也不为一行字引 `url_launcher`。版本号取自**安装包自己的元数据**
    （安卓 `versionName` / `versionCode`），源码里不写死：升级只改 `pubspec.yaml` 的
    `version:`，界面自己跟上。读它走**自建原生通道**（`gtd/native` 的 `appVersion`），
    不引第三方插件——`package_info_plus` 那类插件的安卓 Gradle 脚本会自己 apply Kotlin
    Gradle Plugin，而 AGP 9 起 Kotlin 内置、Flutter 往后要禁掉这条路。拼成
    `主版本 (构建号)` 的规则在 `AppController.loadAppVersion`，原生只回两截事实。
    桌面上这张卡暂不摆——那一栏要整块重做
    （[路线图](roadmap.md)），裁它的仍是同一张能力表，所以桌面设置页里连"关于"这个分区标题
    都不出现，也不去问平台读版本。

## 10. 边界与异常

- **权限被拒**：悬浮窗被拒 → App 内抽屉形态兜底（**四页全功能复用**：同一套 panels，
  App 内左侧滑呼出，无悬浮把手）；悬浮面板的引擎/窗口起不来 → 回退为"把手打开应用面板"
  （功能不减，只是会跳进应用）；通知被拒 → 提醒只在侧边栏内高亮；
  精确闹钟被拒 → 提醒可能迟到（如实提示用户）。
- **后台被杀 / Doze**：提醒依赖 AlarmPort 系统闹钟唤醒（见 [sockets/delivery.md](sockets/delivery.md)），不靠 Timer。
- **闹钟模式权限**：全屏提醒需要锁屏显示/上层显示权限；被拒则退化为通知栏 + 横幅。
- **无 AI 配置**：默认策略照常，设置页显示"未接入"。
- **误触防护**：完成走长按菜单（天然防误触）；**翻页不靠"重手势"**——
  横滑与列表的纵向滚动方向正交，浏览清单不会翻页，翻页也不会误滚列表；
  纵向唯一的越界是**今日页到顶之后再下拉**（[今日编排](panels/plan.md)）：列表没到顶时
  它不存在，而且要拉过一截（72dp 或快甩）才算数，浏览中不会误触；
  通知上的"完成"按钮点击后提示完成，误触可去『已完成』页『恢复未完成』（[已完成页](panels/completed.md)）。
  **批量动作不走这条防线**：它靠自己两步（长按 → 菜单『多选』→ 勾选 → 按动作）；删除仍是软删除 + 撤销 toast，一次删多件时恢复整批；批量完成不进回收站，反悔去『已完成』页逐条恢复。
  **新建确认是纯点按，不承担
  防误触职责**：误建的代价很低（直接进散件段，长按就能改能删）。
- **详情卡是打开那一刻的快照**：它不订阅控制器的后续刷新（后台重锚、别的引擎改了
  任务，卡上的时间不会自己变）。卡里没有动作，所以不存在"执行完留下一张指向旧数据的
  卡"这回事；要看最新的，关掉再点一次。
- **"提醒来了但没声音"是响铃没开**：旧版本带过来的任务身上没有 `remind` 标记，升级后
  照发提醒但走静音渠道——打开那一件的『响铃』即可。两档行为一致，没有"哪一档才响"这回事。
- **无排序模式下页底会多一段散件**：页底 ⑥ 是这一档的设计（全部三无散件，池子那边
  不再显示，[今日清单页](panels/today.md) / [任务池页](panels/pool.md)）。但**有截止的
  条目会比标准档少**：这一档只收"今天到期"的，标准还会把"裕度薄、今天该动手"
  的远期任务捞进今天。想看到那些就切**标准**。
- **存储层的异常**：
  - 人类文档里缺 `创建` 的复选框行 → **不改动**、进 `warnings`（它在 Obsidian 里仍是
    普通待办，但内核不接管、不进任何清单——与 architecture.md [人类文档](formats/tasks-md.md)"只进 warnings"是同一件事）；
  - 两行内容完全相同 → 无法区分内核属主，只告警不猜（改掉任务名或创建时间即可分开）；
  - 人在 Obsidian 里删掉了某一行 → 内核属性文件**保留并提示**，不静默删数据；
  - 人在 Obsidian 里改了任务名 → 优先按指纹、其次按名字、最后按位置配对（[配对规则](formats/matching.md)）；
    位置配对只在"两边剩余数量恰好相等"时启用，数量不等宁可新接管也不猜。

## 11. 范围声明（有意不做 / 边界澄清，防将来被当遗漏）

- **性能/尺寸规格**（把手大小、动画时长等）：实现期以手感调参定，不写死数字；**侧边栏宽高是例外**——范围与默认值见 [把手与面板](panels/handle.md)（用户能拖，数字本身就是给用户看的调参入口）；
- **多设备同步**：只做**同一局域网内**（[局域网同步](sockets/sync.md)）——不经云端、
  不跨网络、无账号；换网络或异地靠任务目录本身（Obsidian 共享是事实上的同步）；
- **备份恢复**：交给任务目录本身（文件即备份），App 不另做；`legacy-tasks/`
  （迁移存档）与 `.gtd/.trash/`（回收站）都**只增不自动清理**；
- **Obsidian 插件 / vault 接管**：不做。与 Obsidian 的连接形式就只有"多一个手机侧边栏
  入口读写同一批文件"（灵感篇的正文段可就地改，[灵感页](panels/notes.md)）；
- **人类文档的任务行里写内核字段**：不做。id/工作强度/优先级/时间裕度/剩余工作量
  只进 `.gtd/`，人类文档保持干净；
- **提醒的"自动升级"**：不做。标准模式下**不会**因为"快到期了"就自动开始提醒
  ——新建任务默认开着『响铃』，关掉的那些只能自己再打开。代价记在
  [架构文档](architecture.md) §11；
- **用户自选调度算法**：不做（`slack.v1` 留在算法注册表里做对照，但设置页没有切换入口；
  要换得动组装点）。**调度模式不是算法选择**：换算法是换"怎么算 risk/priority"，
  两档换的是"问多少、排不排"；也没有往注册表里加不带数学的假算法，
  `Scheduler.schedule` 只收算法参数（工时日历、锚点表、要不要乘重要度），**不认
  `ScheduleMode`**——无排序档压根不调用它；
- **无排序档下的"智能整理"**：不做。按截止/优先级/习惯自动重排、或提示"要不要按算法
  排一遍"，都与该档"顺序就是人的决定"直接冲突；要做也只能做成**一次性**的显式动作
  （点一下才排，且排完即转为手动序）；
- **给开始型组与例行组排手动序**：不做。前者时刻就是序、后者实例每天新生没有可持久的
  序号（"四处不跟着变"）；
- **详情卡的"整卡可编辑"**：不做。详情卡只读、也没有动作按钮，改数据一律走长按菜单；
  同理**详情里不做改期**（改期的主场景在日历 [日历弹窗](panels/calendar.md)）、**不显示排序分**
  （`risk` / `priority` 是排序键，顺序本身就是表达）。要改字段去长按『编辑』；
- **已完成页不做统计、不设条数上限**：只按天列条目，不做"本周完成 N 件"一类的汇总
  （要流水有 `log.md`）；也不做分页与"仅看最近 30 天"的开关——按天分组 +
  `ListView.builder` 足够，真到几千条再说。
- **数据埋点/使用统计**：无（`log.md` 是本地操作流水，不上报）；
- **新平台 shell**（iOS 等）：架构支持，需求不在本阶段；
- **桌面/Windows 端不做移动端的"进出"机制**：把手、遮罩、抽屉、跟手收起都不在桌面做
  （[桌面布局](panels/desktop.md)）——桌面窗口常驻，那套东西没有对应物。但**页面与能力**（四页 / 主线 / 设置 /
  提醒弹窗 / 同步）与安卓是同一份，不另做简化版。托盘图标、全局快捷键、开机自启属
  Windows 原生能力，当前不在范围。
- **面板头的『关闭』与『隐私』按钮**：不做。关面板有点遮罩、返回键、尺寸固定
  后的收起把手三条路；防瞟走快记（[快记](panels/quick-note.md)）。面板头只留右上角『设置』——窄面板上多一颗图标，
  页名就少一截。面板已经开着、旁边忽然来人时没有"一键清屏"，只能先收起面板再决定
  要不要记：不为这个低频场面常驻一颗按钮。
- **把面板拖拽过头不进入隐私态**：拖过头这一档落在快记（[快记](panels/quick-note.md)），
  不是把面板换成一片空白——快记一进入就有可见的方块跟着手指、回拖即取消。
- **支线里不建任务**：支线的候选只从今日清单与任务池里挑，没有标题输入框——建任务的地方
  在别的页（[支线](panels/branch.md)）。代价是池子空、清单也空时只能建出一条空支线。
- **主线不做提醒、不与任务双向联动、不自动归档**：行为链步骤不参与调度（要参与就另建任务，
  两边不互相同步）；完成主线必须是显式动作（全部勾完 → 点『完成主线』），勾完不会自己归档；
  归档只有"看"没有"恢复为当前"——要重做就新建一条（同时只有一条在跑）。主线也不做统计
  图表与"连续 N 天"成就一类的汇总，日历上能看到的就是全部。
