# 文档管理课：从分诊到门禁

> 教学大纲。对象是 deepseek-harness 的文档体系，落点是本项目（gtd_todo）能抄什么。
> 每节一句"讲什么"+ 一句"产出"，勾选表示已讲完。

## 怎么用这份大纲

按讲推进，不跳读：每一讲都依赖上一讲的一个概念（尤其第五、六讲必须连着看）。标 `选学` 的可以不看，不影响后面。标 `针对本项目` 的是把外部体系裁到你这个仓的落点。

如果只有精力学三节，学这三节：`2.3 分诊六去向`、`5.4 备选为什么强制`、`8.1 预算三选一`。

## 第一讲　先认病，再学药

不先讲规矩，先讲这套规矩在防什么。不认病，规矩就只是别人的洁癖。

- [ ] **1.1 三种腐烂**　重复（一句话住三个地方）、失忆（没人记得为什么不那样做）、腐烂（状态标注三个月变假话）。　产出：能用这三种名字给你现有两份文档体检。
- [ ] **1.2 为什么"写清楚点"从来不管用**　规范靠自觉的半衰期约三个月；对照它把每条规则都落成脚本这件事。　产出：理解为什么后面有一半篇幅在讲脚本，而不是讲文笔。
- [ ] **1.3 这套体系的四个总纲**　一份事实一个家 / 决策走路径编码 / 只写现状 / 规则必须有门禁。　产出：一张能贴在墙上的四句话。

## 第二讲　一条事实的家在哪

- [ ] **2.1 判据：主题 + 树位置 = scope**　为什么"文档类型"不决定写多深；上层只讲目的与责任、细节链接到后代。　产出：会判断"这条内容该写多细"。
- [ ] **2.2 十二层的职责与禁区**　逐层过一遍那张表，重点讲每层"不该写什么"——禁区比职责更能定住人。　产出：一张自己项目版的层表。
- [ ] **2.3 分诊六去向**　六个家的判别口诀；为什么先问"这条事实是什么"而不是"我要写个文档"。　产出：日常分诊不犹豫。
- [ ] **2.4 三个真边界案例**　①既像决策又像步骤 ②既像 bug 记录又像架构决定 ③既像包契约又像参考页。　产出：知道模糊时按什么优先级裁决。
- [ ] **2.5 一条事实住在两个家怎么办**　保留一个 + 其余改成链接；"重复规则"为什么是 slop 清单第一条。　产出：会做收编而不是复制。

## 第三讲　各层的内部形态（五个必学，四个跳过）

- [ ] **3.1 根 AGENTS.md：常驻军规**　一条 1–3 行、必须有理由链接、2080 词上限、什么不该进来（故事、完整示例、情景流程）。　产出：能写一条合格的军规。
- [ ] **3.2 architecture.md：有序地图**　讲组成、循环、接缝、扩展点；明确不写类型、不写单包细节、不写决策理由、不标实现状态。　产出：能判断架构文档该不该收某段内容。
- [ ] **3.3 包 README：契约**　Summary 100 词、用法→折叠实现→局限的顺序、Model Experience 与 Known Limitations 固定收尾。　产出：一个 README 骨架。
- [ ] **3.4 cookbook 与 postmortem**　前者是带验证的编号步骤，后者是唯一允许写故事的层；两者的边界（同一件事两种写法对照）。　产出：会选"写步骤"还是"写故事"。
- [ ] **3.5 选学：subsystems / defensive-patterns / 生成型参考 / 网站投影**　为什么这四层在你这个规模上可以先不建；生成型为什么必须禁手改。　产出：知道哪些先欠着。

## 第四讲　Agent Note 之一：路径即状态

- [ ] **4.1 路径三段式**　`{lifecycle}/{class}/日期-标题.md`；为什么用搬文件代替打标签；为什么刻意不建 INDEX.md。　产出：理解"元数据放在路径里"的取舍。
- [ ] **4.2 六个 class 怎么选**　feature / bug-fix / simplification / architecture / process / testing；architecture 与 process 的分界线（出货的源码 vs 围绕代码的工具）；为什么故意没有 refactor。　产出：能一次选对目录。
- [ ] **4.3 日期是首次提出日**　不是实现日、不是合并日；为什么这条小规则能省掉一整列元数据。　产出：命名不出错。
- [ ] **4.4 Status 行与目录交叉校验**　一条纪律如何变成可执行检查；`rejected` 为什么是唯一带内容的 status。　产出：看懂"规则→脚本"的翻译方式。

## 第五讲　Agent Note 之二：两套骨架逐节

- [ ] **5.1 Problem：不带方案也能读懂**　把"我想加一个 X"改写成"现在卡在哪、不解决会怎样"；三个真实改写前后对照。　产出：会写问题陈述。
- [ ] **5.2 Decision：现在时怎么落地**　把提案腔改成已出货现实（"将会""计划"全部改写）；为什么 implemented 里禁 `## Proposal`/`## Plan`/`## Acceptance criteria`。　产出：能改写一段规格腔。
- [ ] **5.3 Consequences：代价与收获必须成对**　只写好处的是宣传稿；"这条决定放弃了什么"才是六个月后的你需要的。　产出：会给自己的决定标价。
- [ ] **5.4 Alternatives considered：为什么强制**　"只记决定的记录会邀请别人重打一遍这场仗"；备选要记录不要发明；怎么写"输在哪"而不是"它不好"。　产出：会给每个备选写一句判词。
- [ ] **5.5 自定义节的边界**　可以有的（包拓扑、线格式、schema）；不该有的（迁移计划、验收清单、测试走查）。　产出：知道中间那段自由区怎么写不跑偏。
- [ ] **5.6 完整样例精读**　逐段拆一篇真的（冻结归档那篇），看四面怎么落成 120 行。　产出：心里有一个长度基准。

## 第六讲　Agent Note 之三：生命周期与消亡

- [ ] **6.1 proposed → implemented 的搬迁清单**　改 Status、Proposal 重写成 Decision、验收与风险折进 Consequences、补 Testing。　产出：会做状态迁移。
- [ ] **6.2 翻案：不许改决定**　决定变了只能新写一篇并互相链接；"就地改事实"和"改决定"的界线在哪。　产出：不会把历史改成正相反。
- [ ] **6.3 合并与删除**　完全被取代才可并入新篇并删除（须保留唯一理由、备选、后果、修复入链）；小 UI / 纯机械改动整组删。　产出：知道什么时候该让一张卡片消失。
- [ ] **6.4 归档冻结**　SHA-256 清单只增不改；为什么冻结后连断链都不修；`.rgignore` 把归档排出搜索的真实理由（陈旧事实会靠字面匹配压过现行文档）。　产出：理解"冻结"是省维护费，不是留纪念。
- [ ] **6.5 单人项目的裁剪**　它 1262 篇是 389 个包撑起来的；你只该有 5–8 篇，且不建归档层。　产出：一条明确的规模红线。

## 第七讲　写作纪律：八条，每条配一个反例

- [ ] **7.1 只写现状**　历史的四个合法去处（commit / PR / 决策卡片 / postmortem）；"这次改成了…"为什么必须删。　产出：会做"去历史化"改写。
- [ ] **7.2 一段一物理行**　好处（diff 精确到段、改一句不重排整段）；代价（一次 format-only 提交）。　产出：决定要不要在自己仓里改。
- [ ] **7.3 slop 清单六病**　重复规则 / 历史错层 / 状态标注 / 手抄目录 / 推理转录 / 段落墙 / 强调通胀——每病一个真例子。　产出：能审自己的文档。
- [ ] **7.4 术语纪律**　一个概念一个词；`contract` 只留给承诺与不变量，`boundary` 只给真实边界；别用隐喻代替具体名词。　产出：会做术语统一。
- [ ] **7.5 受控技术英语**　一句一个指令、明确施动者、不删 `must`/`never`/数字凑长度；20/25 词是提示不是门禁。　产出：长句拆法。
- [ ] **7.6 Dev Note：唯一的草稿区**　允许放没想清的方向，但必须标"非权威"，且结项时提升或删除。　产出：知道草稿该放哪。
- [ ] **7.7 事实核查 = 跑一遍**　文档里的命令、默认值、报错必须实测；跑不出来就删，不许类推。　产出：一份"待实测"清单习惯。

## 第八讲　让规矩活下来

- [ ] **8.1 字数预算三选一**　迁走 → 压缩 → 抬高上限（并辩护）；"上限是护栏不是削减目标"、5% 余量、为什么下限只能等有空间时降。　产出：一个不会失效的写短机制。
- [ ] **8.2 四道卡与快慢分档**　写作时 / commit / PR 21 项 / CI 43 项；钩子只能跑两秒，否则人就开始 `--no-verify`。　产出：知道该在哪里设卡。
- [ ] **8.3 选学：双语三件套与章节哈希**　`.md`+`.zh.md`+`.i18n.yaml`；按章节存哈希对、`--write` 是人工确认动作、物理行数相等。当机制范本看，别照搬。　产出：理解"配对确认"这个设计模式。
- [ ] **8.4 门禁要自测，且每条承诺配反例**　标准本身被测（参考示例必须仍合法）；"绿只说明确认过，不说明确认靠得住"。　产出：会给自己写的检查写反例。
- [ ] **8.5 单向派生**　生成物与网站投影：只在规范源编辑、永不改生成目录、移动要源+清单+入链原子改。　产出：知道派生内容的所有权归谁。

## 第九讲　落到 gtd_todo（针对本项目）

- [ ] **9.1 移植判断表**　抄 / 改 / 不抄三列，逐条过完这套体系；含"为什么双语与冻结归档在你这里价值为负"。　产出：一份决策记录（正好是第一张练习）。
- [ ] **9.2 第一张卡片实写**　拿"排序四档"完整走一遍：问题 → 决定 → 备选与为什么输 → 代价。　产出：`docs/decisions/` 里第一篇真文件。
- [ ] **9.3 `tool/check_docs.dart` 设计**　三条检查（字数上限 / 死链 / 段落内换行）+ 怎么定初始上限 + 怎么在 CI 之外单独跑。　产出：约 100 行的脚本骨架。
- [ ] **9.4 一周节奏**　第 1 天一张卡片、第 2 天脚本、第 3 天给两份正文体检；节奏比一次做完重要。　产出：可执行的排期。
